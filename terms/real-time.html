Term · OS Lab, Operating Systems, Software Eng

Real-time

  • Traditional (PCs, portals, network computers, thin clients); mobile (smartphones, tablets: GPS, accelerometer, gyroscope; augmented reality; Android, iOS); client–server (compute-server system and file-server system); peer-to-peer (P2P) — all nodes are peers; each can act as client or server; register with a centralised lookup service (Napster) or discovery protocol (Gnutella); cloud computing — computing, storage, even apps delivered as a service across a network: public, private, hybrid cloud; SaaS (software as a service), PaaS (platform as a service), IaaS (infrastructure as a service); real-time embedded systems (hard and soft real-time) — rigid time requirements on the operation of a processor or flow of data

From Operating Systems › Operating-System Operations

  • Microkernels — move as much from the kernel into user space; Mach (Carnegie Mellon); kernel provides minimal process and memory management and communication facility (message passing between client program and the services running in user space). Benefits: easier to extend (new services added to user space; no kernel modification), easier to port the OS to new architectures, more reliable (less code in kernel mode), more secure. Drawback: performance overhead of user space to kernel space communication (Windows NT 4.0 moved layers back into kernel space and speed improved; Windows XP closer to monolithic). Examples: QNX (real-time; Mach-style message passing), Darwin (macOS kernel — hybrid of Mach microkernel + BSD)

From Operating Systems › Operating-System Structure

  • Proportional share scheduling: allocate \(T\) shares among all applications; an application receiving \(N\) shares is assured \(N/T\) of total processor time; needs admission control (don't admit if not enough shares). POSIX real-time scheduling: SCHED_FIFO (FCFS with no time slicing among equal priority), SCHED_RR (like FIFO but time slicing among equal priority), pthread_attr_setschedpolicy()

From Operating Systems › Real-Time CPU Scheduling

  • Typical queues from highest priority: real-time processes → system processes → interactive processes → interactive editing processes → batch processes → student processes

From Operating Systems › Scheduling Algorithms

  • Windows: priority-based, preemptive scheduling; dispatcher is the scheduler; thread runs until preempted by a higher-priority thread, terminates, its time quantum ends, or it calls a blocking system call; 32-level priority scheme: variable class (1–15), real-time class (16–31), memory-management thread at priority 0; queue for each priority; idle thread when no ready thread. Priority classes: REALTIME, HIGH, ABOVE_NORMAL, NORMAL, BELOW_NORMAL, IDLE; relative priorities within classes. Priority boost on wait for I/O or after a wait
