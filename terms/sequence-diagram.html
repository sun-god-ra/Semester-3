Sequence diagram

  • Class diagram, sequence diagram, state diagram (UML) for object-oriented analysis (next sections and Unit III)

From Software Eng › UML Models That Supplement the Use Case

  • Difference: state diagram = behaviour of one class/system across states; sequence diagram = interaction between several objects over time

From Software Eng › State Representations

  • Interaction model: how the user interacts with the page. Components: use cases, sequence diagrams (user ↔ browser ↔ server), state diagrams (page states, e.g. logged-out, logged-in), and the user interface prototype (layout, navigation, forms).

From Software Engineering Unit III questions › question

A sequence diagram looks at the same behaviour from a different angle. It shows the objects as vertical lifelines and the messages between them as horizontal arrows in time order from top to bottom. It is a compact version of a use case. The difference to remember is that a state diagram describes one object's life across many events, and a sequence diagram describes one scenario across many objects.
