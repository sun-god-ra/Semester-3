Term · Java, Operating Systems, Software Eng

Debugging

  • Testing = process of executing a program with the intent of finding errors. A good test has a high probability of finding an as-yet-undiscovered error. Debugging = finding and fixing the cause after a test fails

From Software Eng › A Strategic Approach to Software Testing

  • Debugging process: test case → results → suspected causes → additional tests → identified cause → corrections → regression tests. Approaches: brute force, backtracking, cause elimination (binary partitioning), automated debugging (debugger, breakpoints, watches)

From Software Eng › Black-Box Testing

  • Operating-system debugging: failure analysis — log files with error info; core dump (capture of process memory) and crash dump (kernel memory) written to a file for analysis; performance tuning — trace listings, profiling (periodic sampling of the instruction pointer), top, strace, DTrace (Solaris, FreeBSD, macOS), BCC/eBPF (Linux). Kernighan's law: "Debugging is twice as hard as writing the code in the first place."

From Operating Systems › Operating-System Structure

  • Status information (date, time, free memory/disk, users, performance, logging, debugging info; registry in Windows)

From Operating Systems › System Services (System Programs)

  • Multicore programming: concurrency (progress of more than one task — on a single core, interleaved) vs parallelism (perform more than one task simultaneously — needs multiple cores). Programming challenges (Amdahl and others): identifying tasks (independent, divisible), balance (equal work/value), data splitting, data dependency (synchronise), testing and debugging
