Smoke testing

  • Smoke testing: daily build of the integrated product tested by a fixed set of tests (used in time-critical projects).

From Software Engineering Unit V questions › question

  • Smoke testing: an integration testing approach commonly used for time-critical projects: (1) software components translated into code merged into a build (all data files, libraries, reusable modules, engineered components); (2) a series of tests designed to expose "show-stopper" errors; (3) the build is integrated with other builds and the entire product is smoke tested daily. Benefits: integration risk minimised, quality improved, error diagnosis simplified, progress easy to assess. ("Does it smoke?")

From Software Eng › Test Strategies for Conventional Software

  1. Integration testing: tests the interfaces between modules as they are combined. Approaches: top-down, bottom-up, sandwich, big-bang; regression and smoke testing.
