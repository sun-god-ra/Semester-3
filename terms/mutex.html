Home › Terms A–Z › Mutex

Term · OS Lab, Operating Systems

Mutex

  • Uses: mutual exclusion (mutex initialised to 1: wait(mutex); CS; signal(mutex)); ordering / synchronisation — to execute statement S2 in P2 only after S1 in P1: share semaphore synch initialised to 0: P1: S1; signal(synch); P2: wait(synch); S2;

From Operating Systems › Semaphores

  • Order matters: wait(empty) before wait(mutex) — reversed order can deadlock (a producer with the mutex waits on empty while a consumer waits on mutex)

From Operating Systems › Classic Problems of Synchronisation

  • A mutex is the simpler tool: pthread_mutex_lock() / pthread_mutex_unlock() (see Unit III)

From OS Lab › Task 7 — Critical-section problem and Peterson's solution

  • OS designers build higher-level software tools because hardware solutions are complicated and inaccessible to application programmers. Mutex lock (mutual exclusion) — the simplest tool: protect a critical section by first acquire() a lock then release() the lock; a boolean variable available indicates whether the lock is available

From Operating Systems › Mutex Locks

  • Problem with semaphores: timing errors can occur if semaphores are used incorrectly — e.g. signal(mutex) … wait(mutex) (several processes in CS → violates mutual exclusion); wait(mutex) … wait(mutex) (deadlock); omitting wait(mutex) or signal(mutex) or both (mutual exclusion violated or permanent block). Hard to detect (occur only with particular sequences)
