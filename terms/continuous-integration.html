From Software Eng › Agile Tool Set

Agile claim. With good practices (iterative delivery, continuous integration, refactoring, test-driven development, simple design) the curve is flattened: the cost of a late change stays low, so there is no need to freeze everything up-front. (Kent Beck's argument for XP.) Pessimistic note: the flat curve is an aim, it only holds if automated tests and a clean design are really maintained.

From Software Engineering Unit I questions › question

Agile methods challenge the cost-of-change curve. In conventional development, a change costs far more when made late, because it affects documents, designs and code that were built on earlier decisions. Agile proponents say that with short iterations, constant testing, refactoring and continuous integration, the curve flattens and a late change costs only slightly more than an early one. This claim is debated, particularly for large architectural changes. An agile process is incremental, so a working increment is delivered in short cycles, and customer feedback on each increment guides the next one.
