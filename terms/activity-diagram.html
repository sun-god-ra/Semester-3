From Software Eng › Conducting Component-Level Design

The analysis model is the first technical representation of what the system must do. It has three purposes: to describe what the customer needs, to give a starting point for design, and to define requirements that can be checked once the software is built. It is built from four kinds of elements. Scenario-based elements (use cases, activity diagrams) show how users interact. Class-based elements show the objects and their relationships. Behavioural elements show how the system reacts to events. Flow-oriented elements show how information moves and is transformed. A rule of thumb is that the analysis model should describe the problem and not the solution, so it is kept at a high level of abstraction and does not contain design details.
