Term · OS Lab, Operating Systems

Starvation

  • Problem: starvation (indefinite blocking) — low-priority processes may never execute (rumour: when IBM 7094 at MIT shut down in 1973, a low-priority process submitted in 1967 had not yet run). Solution: aging — gradually increase the priority of processes that wait in the system for a long time

From Operating Systems › Scheduling Algorithms

  • Select the request with the minimum seek time from the current head position; SJF-like, may cause starvation (a far request may wait forever as nearer ones keep arriving); not optimal. Order: 53→65 (12) →67 (2) →37 (30) →14 (23) →98 (84) →122 (24) →124 (2) →183 (59) = 236 cylinders

From Operating Systems › Disk Scheduling

  • Deadlock and starvation with semaphores: deadlock — two or more processes waiting indefinitely for an event that can be caused only by one of the waiting processes (e.g., S and Q initialised to 1: P0: wait(S); wait(Q); … signal(S); signal(Q); P1: wait(Q); wait(S); … signal(Q); signal(S); → P0 holds S waits for Q, P1 holds Q waits for S). Starvation (indefinite blocking) — a process may never be removed from the semaphore queue (e.g., LIFO)

From Operating Systems › Semaphores

  • Hold and wait: guarantee that whenever a process requests a resource, it does not hold any other resources — protocol 1: require the process to request and be allocated all its resources before execution begins; protocol 2: allow a process to request resources only when it has none (release all before requesting more). Disadvantages: low resource utilisation (resources allocated but unused for a long time), starvation possible (a process needing several popular resources may wait forever)

From Operating Systems › Deadlock Prevention

  • Resource preemption — successively preempt some resources from processes and give them to other processes until the deadlock cycle is broken. Three issues: selecting a victim (minimise cost: number of resources held, time consumed); rollback (return to some safe state and restart the process from that state; simplest = total rollback, abort and restart; better = roll back only as far as necessary); starvation (the same process may always be picked as victim — include the number of rollbacks in the cost factor)
