Term · OS Lab, Operating Systems

FCFS

  • If the order is P2, P3, P1: waiting 0, 3, 6 → average = 3. Much better — convoy effect: short processes stuck behind a long CPU-bound process (low CPU and device utilisation). FCFS is not suitable for time-sharing (nonpreemptive)

From Operating Systems › Scheduling Algorithms

  • Resuming processes within a monitor: if several processes are suspended on condition x and x.signal() is executed — FCFS or conditional-wait x.wait(c) where c is a priority number, resumed in order of the smallest c. Example: ResourceAllocator monitor (R.acquire(t), R.release()), where t is the maximum time the process plans to use the resource

From Operating Systems › Monitors

  • Selection of a disk-scheduling algorithm: SSTF common, natural appeal; SCAN and C-SCAN perform better for systems that place a heavy load on the disk (less starvation, but starvation still possible with some variants); performance depends on the number and types of requests (file-allocation method and location of directories/index blocks influence it); the disk-scheduling algorithm should be a separate module of the OS (replaceable); default: SSTF or LOOK. Modern disks do their own scheduling using physical layout knowledge; OS also guarantees priorities (e.g., demand paging requests over application I/O, writes with order constraints); Linux has deadline, NOOP and CFQ schedulers — NOOP (FCFS with merging) is used for SSDs; NVM scheduling: FCFS with merging adjacent requests, since there is no seek time

From Operating Systems › Disk Scheduling

  • FCFS: serve in order of arrival (non-preemptive). SJF: pick the process with the shortest burst among those that have arrived; optimal average waiting time. SRTF: at each time unit run the process with the shortest remaining time (preemptive). Round Robin: each process gets a time quantum \(q\); then it goes to the back of the queue. See Unit II

From OS Lab › Task 4 — CPU scheduling: FCFS, SJF (non-preemptive and preemptive), Round Robin

  • FCFS: in arrival order; SSTF: nearest request first (may starve); SCAN (elevator): move to one end servicing requests, then reverse; C-SCAN: move in one direction only; at the end jump to the start without servicing (more uniform wait). LOOK / C-LOOK go only as far as the last request. Total head movement = sum of \(|{\rm next}-{\rm current}|\) (see Unit V)
