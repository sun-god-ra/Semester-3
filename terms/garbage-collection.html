Term · Java, Operating Systems

Garbage collection

  • General graph directory: allows cycles (when links are added to an ordinary tree). Problems: avoid traversing shared sections twice → algorithms to avoid infinite loops; deleting — reference count may not be zero even when it's no longer possible to refer to the directory or file (a self-referencing cycle) → garbage collection (traverse the whole file system, mark everything that can be accessed, then collect the unmarked — time-consuming). Easier: allow only links to files, not subdirectories, and ensure no cycles when a new link is added (cycle-detection algorithms — expensive)

From Operating Systems › Directory Structure

  • TRIM (SSDs, NVM): since NVM flash cannot overwrite and blocks need to be erased before writing, the file system informs the device that blocks are unused (TRIM) so the device can erase them ahead of time for faster writes (and garbage collection)

From Operating Systems › Free-Space Management

ii) Garbage collection. Java frees memory automatically: the garbage collector (GC) thread of the JVM finds objects that are no longer reachable (no reference points to them) and reclaims their memory. The programmer need not free memory, so memory leaks and dangling pointers are avoided.

From Object Oriented Programming Through Java Unit II questions › question

  • Nonvolatile memory (NVM) devices: solid-state disks (SSDs) — flash memory based; no moving parts → faster, more reliable, more expensive per MB, shorter lifespan (limited write cycles), lower power; can be bus-attached (NVMe — NVM express, PCIe) — much faster than SATA. NAND flash: read/write in pages, but cannot overwrite in place — must first erase (in blocks); flash translation layer (FTL); garbage collection; over-provisioning; wear leveling (spread erasures evenly); write amplification. Used as cache tier or main storage. Other: magnetic tape (large archival, very slow random access, cheap, backup, ~200 GB to many TB), optical disks

From Operating Systems › Overview of Mass-Storage Structure

The "buzzwords" are the features designers claimed for the language, and each one is a consequence of a design choice. It is simple and secure because pointers were removed, so a program can neither forge an address nor overwrite arbitrary memory. It is robust because types are checked strictly, exceptions force error handling, and garbage collection removes manual freeing. It is portable and architecture-neutral because programs are compiled to bytecode, and because the size of each type is fixed by the language and not by the machine: an int is 32 bits everywhere.
