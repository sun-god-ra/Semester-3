Term · OS Lab, Operating Systems

Round robin

  • The two-memory-access problem can be solved by the use of a special fast-lookup hardware cache: associative memory / translation look-aside buffer (TLB) — small (32–1024 entries), fast; each entry has two parts: a key (tag) and a value; the item being searched for is compared with all keys simultaneously; if found, the value is returned. TLB miss → page number looked up in the page table in memory; the entry is then added to the TLB (replacement policies: LRU, round robin, random); some entries can be wired down (kernel code). Some TLBs store address-space identifiers (ASIDs) in each entry — uniquely identify each process to provide address-space protection for that process and allow entries for several processes to coexist in the TLB (otherwise TLB must be flushed at every context switch)

  • Round Robin: each process gets a time quantum, then goes to the back of the queue; good response; quantum too large → FCFS, too small → context-switch overhead.

  • FCFS: serve in order of arrival (non-preemptive). SJF: pick the process with the shortest burst among those that have arrived; optimal average waiting time. SRTF: at each time unit run the process with the shortest remaining time (preemptive). Round Robin: each process gets a time quantum \(q\); then it goes to the back of the queue. See Unit II

From OS Lab › Task 4 — CPU scheduling: FCFS, SJF (non-preemptive and preemptive), Round Robin

Round robin gives every process a time quantum and moves it to the back of the queue when the quantum ends. With a very large quantum it behaves like FCFS and with a very small one it spends too much time in context switches. The usual rule is that 80% of CPU bursts should be shorter than the quantum. For the example with q=4, the waits are 6, 4, 7 and the average is 5.67.
