Term · OS Lab, Operating Systems

LRU

  • LRU-approximation algorithms (few systems give full LRU hardware support)
    • Reference bit: with each page associate a bit, initially 0; when the page is referenced, the bit is set to 1 by hardware; replace any page with reference bit = 0 (if one exists) — order of use unknown
    • Additional-reference-bits algorithm: keep an 8-bit byte for each page in a table in memory; at regular intervals (e.g. every 100 ms) a timer interrupt shifts the reference bit into the high-order bit of the byte (shifting the others right, discarding the low bit): the byte holds the history of page use for the last 8 periods; page with the lowest unsigned value is the LRU page (e.g. 11000100 used more recently than 01110111)
    • Second-chance (clock) algorithm: FIFO with a reference bit; if page to be replaced has reference bit = 0 → replace it; if reference bit = 1 → set the bit to 0, leave the page in memory (its arrival time is reset) and move to the next page (subject to the same rules). Implemented as a circular queue with a clock-hand pointer: if all bits are 1, it degenerates into FIFO
    • Enhanced second-chance algorithm: consider (reference bit, modify bit) as an ordered pair: (0,0) neither recently used nor modified — best to replace; (0,1) not recently used but modified — not quite as good (must be written out); (1,0) recently used but clean — probably used again soon; (1,1) recently used and modified — probably used again, and need to write out before replacement. Replace the first page encountered in the lowest nonempty class (may have to scan the circular queue several times) — used in old Macintosh virtual memory

From Operating Systems › Page Replacement

  • The two-memory-access problem can be solved by the use of a special fast-lookup hardware cache: associative memory / translation look-aside buffer (TLB) — small (32–1024 entries), fast; each entry has two parts: a key (tag) and a value; the item being searched for is compared with all keys simultaneously; if found, the value is returned. TLB miss → page number looked up in the page table in memory; the entry is then added to the TLB (replacement policies: LRU, round robin, random); some entries can be wired down (kernel code). Some TLBs store address-space identifiers (ASIDs) in each entry — uniquely identify each process to provide address-space protection for that process and allow entries for several processes to coexist in the TLB (otherwise TLB must be flushed at every context switch)

From Operating Systems › Paging

  • Efficiency and performance: efficiency depends on the disk-allocation and directory algorithms (e.g., UNIX inodes preallocated on a partition; cluster blocks; the type of data kept in a file's directory entry such as "last access time" updates → write for each read, so disable "access time" updates (noatime); fixed-size vs variable-size pointer structures; 32-bit vs 64-bit pointers — a trade-off between max file size and space). Performance — buffer cache (separate section of main memory for frequently used blocks), page cache (caches pages rather than disk blocks using virtual-memory techniques and addresses; memory-mapped I/O uses a page cache; routine I/O through the file system uses the buffer cache → double caching problem; a unified buffer cache uses the same page cache to cache both memory-mapped pages and ordinary file-system I/O to avoid double caching); synchronous writes (no buffering — e.g. metadata) vs asynchronous writes (stored in cache and return immediately — common); free-behind and read-ahead techniques for sequential access (free-behind — remove a page from the buffer as soon as the next page is requested; read-ahead — a requested page and several subsequent pages are read and cached); LRU replacement is not best for sequential access → free-behind/read-ahead

From Operating Systems › Free-Space Management

  • FIFO replaces the oldest page; LRU replaces the page unused for the longest time (past); Optimal replaces the page that will not be used for the longest time (future; the lower bound, not implementable). FIFO may show Belady's anomaly; LRU and OPT are stack algorithms that do not. See Unit IV

From OS Lab › Task 14 — Page replacement: FIFO, LRU and Optimal

  • LRU: replace the page not used for the longest time in the past (approximation of OPT using the past). Implemented with counters or a stack.
