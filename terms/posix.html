Term · OS Lab, Operating Systems

POSIX

  • POSIX shared memory: shm_open() → ftruncate() (set size) → mmap() (map into address space) → write/sprintf → munmap, shm_unlink()

From Operating Systems › Interprocess Communication (IPC)

  • API (Application Programming Interface) — programmers normally access system calls via an API, not directly. The three most common APIs: Windows API (Win32), POSIX API (UNIX, Linux, macOS), Java API (for the JVM). A function in the API invokes the actual system call. Why API instead of system calls directly? Portability, and APIs are simpler to use than the actual system calls (e.g. printf() in C library → write() system call; Windows API CreateProcess() → NTCreateProcess() kernel call)

From Operating Systems › System Calls

  • Thread libraries provide the programmer an API for creating and managing threads: POSIX Pthreads (user- or kernel-level; specification, not implementation; pthread_create, pthread_join), Windows threads (kernel-level; CreateThread), Java threads (managed by the JVM; implemented using the host's native thread library; Thread class or Runnable interface; start() → run())

From Operating Systems › Multithreading Models

  • Proportional share scheduling: allocate \(T\) shares among all applications; an application receiving \(N\) shares is assured \(N/T\) of total processor time; needs admission control (don't admit if not enough shares). POSIX real-time scheduling: SCHED_FIFO (FCFS with no time slicing among equal priority), SCHED_RR (like FIFO but time slicing among equal priority), pthread_attr_setschedpolicy()
