Home › Terms A–Z › TLB

Term · OS Lab, Operating Systems

TLB

  • Effective Access Time (EAT): let hit ratio α = percentage of times the page number is found in the TLB; ε = TLB lookup time; memory access time = m (here 100 ns)

From Operating Systems › Paging

  • ARM architecture: 4 KB and 16 KB pages, 1 MB and 16 MB sections; one-level paging for sections, two-level for smaller pages; two levels of TLBs (micro TLBs per core, main TLB)

From Operating Systems › Structure of the Page Table

  • Prepaging — bring in some or all of the pages a process will need before they are referenced (reduces the large number of page faults at process start-up; wasteful if pages are not used). Page size selection: fragmentation (small pages → less internal fragmentation), page-table size (large pages → small table), I/O overhead (seek and latency dominate → bigger is better), number of page faults, locality, TLB size and effectiveness (TLB reach = (TLB size) × (page size) — to increase: larger page size or multiple page sizes); typical 4 KB, trend toward larger. Program structure: e.g. a 128×128 array of ints, page size 128 words — row-major accessing for j { for i { data[i][j] = 0 } } → 128 × 128 = 16,384 page faults, while for i { for j { data[i][j] = 0 } } → 128 page faults — good data-structure and programming choices improve locality. I/O interlock and page locking: pages used for I/O must be pinned (locked) in memory so they are not replaced

From Operating Systems › Thrashing

TLB: associative cache of (page, frame) pairs. Effective access time \(EAT=\alpha(t_{TLB}+m)+(1-\alpha)(t_{TLB}+2m)\). With hit ratio 80 percent, TLB 20 ns, memory 100 ns: \(0.8\times120+0.2\times220=140\) ns.
