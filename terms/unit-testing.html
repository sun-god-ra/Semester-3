Term · Software Eng

Unit testing

  1. Unit testing — concentrates on each unit (component); white-box techniques; exercises control paths and boundary conditions

From Software Eng › A Software Testing Strategy — The Big Picture (Spiral)

  • Unit testing in the OO context: class (encapsulation) = the smallest testable unit; operations within a class cannot be tested in isolation, as in conventional; inheritance means an operation may be tested in the context of each subclass where it is used; class testing uses random testing, partition testing, scenario-based testing (state-based testing)

From Software Eng › Test Strategies for Object-Oriented Software

  • Developer and ITG cooperate; developers are responsible for unit testing and often integration testing

From Software Eng › Organizing for Software Testing

  1. Unit testing: tests each component or module in isolation (interface, local data, boundary conditions, independent paths, error handling). Done by the developer with drivers and stubs.

From Software Engineering Unit V questions › question

In unit testing, we test the interface, local data structures, boundary conditions, independent paths and error-handling paths of a component. Since a component is not a complete program, we need a driver, which acts as a main program that passes test data to the component and prints the results, and stubs, which are dummy modules that stand in for the components that the tested one calls.

From Software Eng › Test Strategies for Conventional Software
