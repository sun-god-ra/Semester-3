Home › Terms A–Z › Interrupt

Term · Digital Logic, OS Lab, Operating Systems, Software Eng

Interrupt

  • Stress testing — executes the system in a manner that demands resources in abnormal quantity, frequency or volume (e.g. 10× interrupts, maximum input data rates, high memory demand). Sensitivity testing is a variation

From Software Eng › Test Strategies for Conventional Software

  • Interrupt features of advanced systems: ability to defer during critical processing; efficient dispatch to the proper handler (vector); multilevel interrupts with priorities (maskable and nonmaskable (NMI) interrupts)

From Operating Systems › Computer-System Organization

  • OS is interrupt driven — if there are no processes to execute, no I/O devices to service and no users to respond, OS sits idle waiting for an event

From Operating Systems › Operating-System Operations

  • Uniprocessors: could disable interrupts — currently running code executes without preemption; generally too inefficient on multiprocessor systems (message passed to all processors → delays entry; affects system clock)

From Operating Systems › Synchronisation Hardware

  • Three major activities: service the interrupt (careful coding: several hundred instructions), read the page (lots of time), restart the process (small)

From Operating Systems › Demand Paging
