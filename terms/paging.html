Term · OS Lab, Operating Systems

Paging

  • Swapping with paging: modern systems swap pages (not whole processes) — page out / page in

From Operating Systems › Swapping

  • ARM architecture: 4 KB and 16 KB pages, 1 MB and 16 MB sections; one-level paging for sections, two-level for smaller pages; two levels of TLBs (micro TLBs per core, main TLB)

From Operating Systems › Structure of the Page Table

  • Performance of demand paging: page-fault rate \(p\), \(0\le p\le 1\): \(p=0\) → no page faults; \(p=1\) → every reference is a fault

From Operating Systems › Demand Paging

  • Shared pages: paging allows sharing common code — reentrant (pure) code: non-self-modifying code, never changes during execution. One copy of read-only (reentrant) code shared among processes (text editors, compilers, window systems); each process has its own copy of registers and data storage; the shared code must appear in the same logical location in the address space of all processes. Example: 40 users each running a text editor of 150 KB code + 50 KB data: without sharing = 40 × 200 KB = 8000 KB; with sharing = 150 + 40 × 50 = 2150 KB. Private code and data can appear anywhere in the logical address space

From Operating Systems › Paging

  • Segmentation with paging (Intel IA-32): logical address → segmentation unit → linear address → paging unit → physical address. IA-32: up to 16 K segments per process (8 K private in the LDT, 8 K shared in the GDT); selector = 13-bit segment number (s) + 1-bit g (GDT/LDT) + 2-bit protection p; segment descriptor → base + limit; linear address 32 bits → two-level paging (10+10+12), with a 4 MB page option (page-size flag) to skip the inner table. x86-64 uses 4-level paging

From Operating Systems › Segmentation (Memory-Management Scheme that supports the User View)
