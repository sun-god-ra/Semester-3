Peterson's solution

Peterson's solution works for two processes, with a turn variable and a flag[2] array. A process sets its own flag, which says "I want to enter", and then gives the turn to the other process ("you go first"). It then waits while the other process wants to enter and it is the other's turn. Since turn has only one value, only one of the two can pass the loop when both want to enter. If the other does not want to enter, the flag is false, and the process enters at once. If it does want to, then after it finishes it clears its flag, and so the waiting process enters after at most one turn of the other, which is bounded waiting. The solution is correct as an algorithm but may fail on modern processors, because the compiler or CPU can reorder the independent store instructions, so memory barriers are needed in real code.

Each thread executes counter++ 200,000 times, so a correct result is 400,000. In Peterson's solution each thread first announces that it wants to enter (flag[i]=1), then gives the turn to the other (turn=j), and waits while the other wants to enter and it is the other's turn. Mutual exclusion holds, so no increment is lost. The atomic variables are essential: with ordinary variables the compiler or the CPU may reorder the store operations and the algorithm may break on modern hardware. The mutex version gives the same total.
