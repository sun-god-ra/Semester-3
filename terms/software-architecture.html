Software architecture

  • Software architecture (Bass, Clements, Kazman) = the structure or structures of the system, which comprise software components, the externally visible properties of those components, and the relationships among them

From Software Eng › Software Architecture

  1. Integration testing — design and construction of the software architecture; black-box (and limited white-box) techniques

From Software Eng › A Software Testing Strategy — The Big Picture (Spiral)

  • Systematic technique for constructing the software architecture while conducting tests to uncover errors associated with interfacing. Non-incremental ("big bang"): all combined at once → chaos, hard to isolate errors. Incremental: construct and test in small segments → errors easier to isolate

From Software Eng › Test Strategies for Conventional Software

Software architecture is the overall structure of the software: the components, the externally visible properties of those components and the relationships among them. It is the first design representation and decides how the system meets its quality needs (performance, security, modifiability).

From Software Engineering Part A › question

Software architecture is the structure of the system: components, their externally visible properties and their relationships. Bass, Clements and Kazman: architecture is a vehicle for stakeholder communication, an early design decision set and a transferable abstraction.
