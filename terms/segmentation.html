Segmentation

  • Segmentation with paging (Intel IA-32): logical address → segmentation unit → linear address → paging unit → physical address. IA-32: up to 16 K segments per process (8 K private in the LDT, 8 K shared in the GDT); selector = 13-bit segment number (s) + 1-bit g (GDT/LDT) + 2-bit protection p; segment descriptor → base + limit; linear address 32 bits → two-level paging (10+10+12), with a 4 MB page option (page-size flag) to skip the inner table. x86-64 uses 4-level paging

From Operating Systems › Segmentation (Memory-Management Scheme that supports the User View)

  • Paging: \(\text{page}=\lfloor \text{logical}/\text{page size}\rfloor\), \(\text{offset}=\text{logical}\bmod\text{page size}\), \(\text{physical}=\text{frame}\times\text{page size}+\text{offset}\); a page number beyond the table is an invalid reference → trap. Segmentation: address = (segment, offset); if offset < limit then physical = base + offset, else trap

From OS Lab › Task 13 — Logical to physical address translation (paging and segmentation)

  • Solutions to external fragmentation: compaction — shuffle memory contents to place all free memory together in one large block; possible only if relocation is dynamic (done at execution time); I/O problem (latch job in memory while it is involved in I/O, or do I/O only into OS buffers); expensive. Other solution: permit the logical address space of processes to be noncontiguous → paging and segmentation

From Operating Systems › Contiguous Memory Allocation

  • External fragmentation: total free memory is enough for a request, but it is split into non-contiguous small holes. Occurs in variable (dynamic) partitioning, segmentation and contiguous allocation; the first-fit/best-fit statistics suggest about one-third of memory may be unusable (50 percent rule: for N allocated blocks about 0.5N are lost).
