Copy-on-write

Copy-on-write (COW) lets parent and child processes initially share the same pages, marked read-only/copy-on-write. Only when either process writes to a shared page is a copy of that page made for the writer.

From Operating Systems Unit IV questions › question

  • Recovery: because files and directories are kept both in main memory and on disk, a system failure might cause data loss and inconsistency. Consistency checking (fsck in UNIX, chkdsk in Windows) — compares data in the directory structure with the data blocks on disk and tries to fix inconsistencies (allocation algorithms and free-space management algorithms dictate what types of problems the checker can find, e.g. with linked allocation, a loss of a link may result in data loss). Log-structured (journaling) file systems: all changes to metadata are written sequentially to a log (journal) as transactions; once the changes are written to the log, they are considered committed and the system call can return; the log entries are replayed asynchronously to the file system structures; when the entire committed transaction has been completed, the entry is removed from the log; on a crash, transactions in the log that were committed but not completed are completed, and uncommitted transactions are undone — fast recovery (ext3/ext4, NTFS, ZFS, XFS, JFS). Other solutions: backup and restore — full backup and incremental backup; snapshots (ZFS), WAFL (Write-Anywhere File Layout of NetApp) — never overwrite blocks, take snapshots by copying the root inode; copy-on-write

From Operating Systems › Free-Space Management

Copy-on-write lets the parent and child share all pages after fork(), and a page is copied only when one of them writes to it. Memory-mapped files map a file into the address space, so file I/O becomes ordinary memory access.
