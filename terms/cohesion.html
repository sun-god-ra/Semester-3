Cohesion

  • Cohesion = how strongly related the elements inside one module are (high is good). Spectrum (worst → best): coincidental → logical → temporal → procedural → communicational → sequential → functional

From Software Eng › Design Concepts

  • Cohesion (kinds: utility, temporal, functional, layer, communicational, sequential) — aim for high

From Software Eng › Designing Class-Based Components

  • Cohesion types (aim for functional): utility, layer, communicational, sequential, procedural, temporal.

From Software Engineering Unit IV questions › question

  1. Functional independence: single-minded modules with low interaction; measured by high cohesion and low coupling.

From Software Engineering Unit III questions › question

Cohesion: how strongly the elements inside a module belong together (high is good). Coupling: how much a module depends on other modules (low is good).
