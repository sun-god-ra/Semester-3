Home › Terms A–Z › Abstraction

Term · Java, Operating Systems, Software Eng

Abstraction

  • Iterative process: requirements → blueprint at high abstraction (traceable to requirements) → refined to lower levels

From Software Eng › The Design Process

  • Dimensions: process dimension (progress as design tasks are executed: from analysis to design) and abstraction dimension (from high abstraction analysis elements to low abstraction design elements)

From Software Eng › The Design Model

  • Open–Closed Principle (OCP): a module/component should be open for extension but closed for modification (use abstractions — interfaces/abstract classes)

From Software Eng › Designing Class-Based Components

  • Monitor = high-level abstraction (an abstract data type, ADT) that provides a convenient and effective mechanism for process synchronisation: internal variables only accessible by code within the procedures; only one process may be active within the monitor at a time (mutual exclusion is automatic, the programmer need not code it)

From Operating Systems › Monitors

  • Abstraction: manage complexity by hiding detail; show only what is essential (e.g. driving a car without knowing the engine). Hierarchical classification
