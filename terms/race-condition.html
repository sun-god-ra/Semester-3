Home › Terms A–Z › Race condition

Term · Java, Java Lab, OS Lab, Operating Systems

Race condition

  • Problem: when two threads use a shared resource at the same time → race condition, inconsistent data (e.g. two threads doing count++ — not atomic: read, add, write)

From Java › Synchronization

  • Preemptive and nonpreemptive scheduling. CPU-scheduling decisions take place when a process: (1) switches from running to waiting (I/O request, wait() for a child); (2) switches from running to ready (interrupt); (3) switches from waiting to ready (I/O completion); (4) terminates. For 1 and 4 there is no choice → nonpreemptive (cooperative) scheduling: once the CPU is allocated to a process, it keeps it until it releases it by terminating or switching to waiting. All other scheduling (2, 3) is preemptive. Preemptive scheduling can result in race conditions when data are shared among processes; also affects kernel design (kernel data structures: interrupts disabled during critical updates)

From Operating Systems › CPU Scheduling — Basic Concepts

  • Kernel-mode race conditions: preemptive kernels (a process can be preempted while running in kernel mode — harder to design, esp. SMP; but more responsive, suitable for real-time and less risk of a kernel process running for an arbitrarily long time) vs nonpreemptive kernels (a process runs until it exits kernel mode, blocks, or voluntarily yields → essentially free of race conditions in kernel data structures). Linux (since 2.6), Windows, Solaris, IRIX are preemptive

From Operating Systems › The Critical-Section Problem

  • Symmetric multiprocessing (SMP) — each processor is self-scheduling: all processes in a common ready queue (possible race condition, so locking needed), or each processor has its own private queue of ready processes (most common: Windows, Linux, macOS)

From Operating Systems › Multiple-Processor Scheduling

  • Atomic variables: provide atomic operations on basic data types (integers, booleans), built on CAS — e.g. an atomic increment(&sequence) ensures no race condition; commonly used for counters and sequence generators; they don't solve all race conditions (e.g., bounded buffer with several consumers)
