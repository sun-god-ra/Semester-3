Critical section

  • Consider n processes {P0, …, P(n−1)}; each has a critical section (segment of code) where it may be changing common variables, updating a table, writing a file. When one process is in its critical section no other process is allowed to be in its critical section (mutual exclusion)

From Operating Systems › The Critical-Section Problem

  • Still has busy waiting but only within wait() and signal() critical sections (short, ~10 instructions), not in application CS (which may be long)

From Operating Systems › Semaphores

  • OS designers build higher-level software tools because hardware solutions are complicated and inaccessible to application programmers. Mutex lock (mutual exclusion) — the simplest tool: protect a critical section by first acquire() a lock then release() the lock; a boolean variable available indicates whether the lock is available

From Operating Systems › Mutex Locks

  • Remedies: allow at most four philosophers to sit at the table; allow a philosopher to pick up chopsticks only if both are available (picking up in a critical section); use an asymmetric solution — an odd philosopher picks left then right, an even one picks right then left; (a monitor solution below)

From Operating Systems › Classic Problems of Synchronisation

  • Shared variables: int turn; — whose turn it is to enter the critical section; boolean flag[2]; — flag[i] = true means Pi is ready to enter
