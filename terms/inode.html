Term · OS Lab, Operating Systems

Inode

  • File attributes (metadata): name (human-readable, the only attribute kept in human-readable form), identifier (unique tag, number — non-human-readable name — e.g. inode number), type (needed for systems that support different types), location (pointer to the device and the file location), size (current size, maybe maximum allowed), protection (access-control info: who can read, write, execute), time, date and user identification (creation, last modification, last use — for protection, security, usage monitoring). Information about files is kept in the directory structure (maintained on disk); a directory entry consists of the file's name and its unique identifier (the identifier locates the other attributes); may take more than a kilobyte per file. Extended attributes — file checksum, character encoding

From Operating Systems › File Concept

  • Virtual file systems (VFS): the OS needs to support multiple types of file systems at the same time → object-oriented techniques, with a VFS layer providing the same system-call interface (the API) for different file-system types; VFS dispatches the operation to the appropriate file-system implementation; layers: file-system interface (open(), read(), write(), close() and file descriptors) → VFS interface (separate the generic operations from implementation; a vnode — network-wide unique file representation (a numerical designator for a network-wide unique file; inode in UNIX is unique within a single file system) → local file system (type 1: ext4, type 2) or remote file system (NFS). Linux VFS object types: inode object (an individual file), file object (an open file), superblock object (an entire file system), dentry object (an individual directory entry)

From Operating Systems › File-System Implementation — Structures and Operations

  • Combined scheme (UNIX inode): the first 15 pointers of the inode (in the FCB): 12 direct blocks, then single indirect, double indirect, triple indirect. With 4 KB blocks and 4-byte pointers: direct = 12 × 4 KB = 48 KB; single indirect = 1,024 × 4 KB = 4 MB; double = 1,024² × 4 KB = 4 GB; triple = 1,024³ × 4 KB = 4 TB; small files (≤ 48 KB) need no index block (fast); max file size ≈ 4 TB + 4 GB + 4 MB + 48 KB (but the 32-bit file-size field limits to 4 GB in many systems)

From Operating Systems › Allocation Methods

A directory is a table that maps file names to file control blocks/inodes. Structures: single-level, two-level, tree-structured, acyclic-graph and general graph directories.

From Operating Systems Part A › question

  • Acyclic-graph directories: allow directories to share subdirectories and files — the same file may be in two different directories (a shared file rather than a copy: changes by one user visible to the other). Implemented via links (a link is a pointer to another file or subdirectory; UNIX symbolic link = file containing a path name; hard link = another directory entry pointing to the same inode, with a reference count) or by duplicating the entries (copy; consistency problem). Problems: a file may have multiple absolute path names (aliasing — when traversing for a total, a shared structure counted twice); deletion — when can the space be deallocated? dangling pointers; solutions: backpointers (list of all references, variable-size), entry-hold-count (reference count) solution — a reference count: when it reaches zero, the file can be deleted; symbolic links are left dangling. UNIX uses a link count in the inode (ln, ln -s)
