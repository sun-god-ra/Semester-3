Data flow diagram

Use cases are good for describing interaction but do not show how data moves. A data flow diagram shows processes, data stores and external entities connected by data flows. The top-level context diagram shows the entire system as one process, and each lower level breaks one process into several. Control-flow models serve software that reacts to events, and entity-relationship diagrams describe the stored data.

From Software Eng › UML Models That Supplement the Use Case

An architecture can be derived from a data flow diagram. In transform flow, data enters, is converted at a transform centre, and leaves. In transaction flow, one incoming item triggers one of several possible action paths, and a transaction centre chooses which. In each case the DFD is factored into a hierarchy of controllers and workers.
