Term · Software Eng

Integration testing

  1. Integration testing — design and construction of the software architecture; black-box (and limited white-box) techniques

From Software Eng › A Software Testing Strategy — The Big Picture (Spiral)

  • Smoke testing: an integration testing approach commonly used for time-critical projects: (1) software components translated into code merged into a build (all data files, libraries, reusable modules, engineered components); (2) a series of tests designed to expose "show-stopper" errors; (3) the build is integrated with other builds and the entire product is smoke tested daily. Benefits: integration risk minimised, quality improved, error diagnosis simplified, progress easy to assess. ("Does it smoke?")

From Software Eng › Test Strategies for Conventional Software

  • Integration testing in the OO context: no obvious "top" for a top-down, no hierarchy; two strategies
    • Thread-based testing — integrates the set of classes required to respond to one input or event; each thread integrated and tested individually; regression testing applied
    • Use-based testing — begins construction by testing those classes that use very few server classes (independent classes), then dependent classes that use independent classes; continues layer by layer
    • Cluster testing — a cluster of collaborating classes is exercised by designing test cases to uncover collaboration errors

From Software Eng › Test Strategies for Object-Oriented Software

  1. Integration testing: tests the interfaces between modules as they are combined. Approaches: top-down, bottom-up, sandwich, big-bang; regression and smoke testing.

From Software Engineering Unit V questions › question

  • Developer and ITG cooperate; developers are responsible for unit testing and often integration testing
