Black-box testing

  • External view — black-box testing: knowing the specified function that a product has been designed to perform, tests demonstrate that each function is fully operational while at the same time searching for errors in each function. Tests conducted at the software interface

From Software Eng › Internal and External Views of Testing

  • External view = black-box testing: tester knows only the specification; tests the functions and the input/output behaviour without regard to the code. Done by testers or users.

From Software Engineering Unit V questions › question

Black-box testing uses the specification to derive tests. Equivalence partitioning splits the inputs into classes whose members are expected to behave in the same way, so that one test from each class is enough. For a range of valid values there is one valid class and two invalid classes, one on each side. Boundary value analysis adds tests at and next to the edges of those classes, because errors cluster at boundaries, usually from mistakes such as using < where <= is needed. For a valid range from 18 to 60 the boundary tests are 17, 18, 19, 59, 60 and 61. Graph-based testing models objects and relationships as a graph and covers its nodes and links. Orthogonal array testing selects a small number of tests that cover all pairs of parameter values, which is helpful when the number of parameters is large and exhaustive testing is impossible.
