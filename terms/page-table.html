Home › Terms A–Z › Page table

Term · OS Lab, Operating Systems

Page table

  1. When the read is complete, modify the internal table (PCB) and the page table (valid bit = v)

From Operating Systems › Demand Paging

  • Process Control Block (PCB / task control block) — OS representation of a process; contains: process state, program counter, CPU registers, CPU-scheduling information (priority, pointers to queues), memory-management information (base/limit registers, page tables), accounting information (CPU used, clock time, time limits, process numbers), I/O status information (list of open files, devices allocated). In Linux the PCB is task_struct

From Operating Systems › Process Concept

  • Memory protection in paging: a protection bit with each frame (read-only / read-write / execute-only); a valid–invalid bit attached to each entry in the page table: "valid" = the associated page is in the process's logical address space, so a legal page; "invalid" = the page is not in the process's logical address space → trap. Or use PTLR. Some pages inside the page table range may be unused; internal fragmentation in addressing: because of the page granularity, process may reference addresses past its end up to the page boundary (still marked valid) — only the PTLR/valid bits catch pages beyond

From Operating Systems › Paging

  • Inverted page table: rather than each process having a page table and tracking all possible logical pages, track all physical pages: one entry for each real page (frame) of memory; the entry consists of the virtual address of the page stored in that real memory location, with information about the process that owns the page (<process-id, page-number> plus offset). Decreases memory needed to store each page table, but increases time needed to search the table when a page reference occurs. Use a hash table to limit the search to one or at most a few page-table entries (TLB can accelerate). Difficulty with shared memory (only one virtual page mapped per physical frame → a shared page needs one mapping at a time). Used in 64-bit UltraSPARC, PowerPC

From Operating Systems › Structure of the Page Table

  • Implementation: needs hardware assistance. Counter implementation: every page-table entry has a time-of-use field; CPU clock/counter is copied into it at every reference; replace the page with the smallest time value (search of page table needed; clock overflow). Stack implementation: keep a stack of page numbers as a doubly linked list: when a page is referenced, move it to the top (requires up to 6 pointers to be changed); no search for replacement (the bottom is the LRU page). Updating on every memory reference must be done in hardware (otherwise slows every reference by a factor of at least 10)
