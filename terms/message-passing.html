Home › Terms A–Z › Message passing

Term · Java, Operating Systems, Software Eng

Message passing

  • Other terms: class = blueprint / template; object = instance of a class (state + behaviour + identity); message passing = calling a method

From Java › Overview of OOP

  • Communications — shared memory or message passing (within a computer or between computers over a network)

From Operating Systems › Operating-System Services

  • Modules (loadable kernel modules, LKM) — best current methodology: kernel has a set of core components and links in additional services via modules, either at boot time or run time. Object-oriented approach: each core component is separate, talks to the others over known interfaces, loadable as needed within the kernel. Similar to layers but more flexible (any module can call any other) and similar to microkernel but more efficient (no message passing). Linux (core kernel + device drivers, file systems, scheduling classes as modules), Solaris

From Operating Systems › Operating-System Structure

  • Examples of IPC systems: POSIX shared memory, Mach message passing (mailboxes called ports; system calls msg_send, msg_receive, msg_rpc; bootstrap port; kernel task self port, notify port), Windows (advanced local procedure call (ALPC) — connection port and communication port, 3 techniques: small messages via port's message queue, larger via section object, huge via callback), pipes

From Operating Systems › Interprocess Communication (IPC)

  • Benefits of multithreaded programming: responsiveness (continues even if part is blocked), resource sharing (default sharing of memory — easier than shared memory/message passing between processes), economy (creating a thread is cheaper than a process; context switching among threads is faster — Solaris: creating a process is ~30× slower, context switching ~5× slower), scalability (use multiple processing cores, utilisation of multiprocessor architectures)
