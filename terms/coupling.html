Term · Software Eng

Coupling

  • Coupling = degree of interdependence between modules (low is good). Spectrum (best → worst): data → stamp → control → external → common → content

From Software Eng › Design Concepts

  • Coupling (kinds: content, common, control, stamp, data, routine call, type use, inclusion/import, external) — aim for low; a "Law of Demeter" (talk only to your friends)

From Software Eng › Designing Class-Based Components

  • Messages: objects communicate by sending messages; coupling is through messages.

From Software Engineering Unit III questions › question

  • Coupling types (aim for low): content, common, control, stamp, data, routine call, type use, inclusion/import, external.

From Software Engineering Unit IV questions › question

  • Analysis rules of thumb: model should focus on requirements visible in the problem/business domain, high level of abstraction; each element adds to overall understanding; delay infrastructure and non-functional models to design; minimise coupling; model must provide value to all stakeholders; keep it as simple as possible
