Term · Java, OS Lab, Operating Systems

Deadlock

  • Order matters: wait(empty) before wait(mutex) — reversed order can deadlock (a producer with the mutex waits on empty while a consumer waits on mutex)

From Operating Systems › Classic Problems of Synchronisation

  • Facts: no cycle → no deadlock. If there is a cycle: only one instance per resource type → deadlock; several instances per type → possibility of deadlock (cycle is necessary but not sufficient)
    • Example with a cycle but no deadlock: P1→R1→P2→R3→P3... where another process (P4 holding an instance of R2) can release and break the cycle

From Operating Systems › Deadlock Characterisation

  • Safe state → no deadlock. Unsafe state → possibility of deadlock (but not all unsafe states are deadlocks). Avoidance = ensure the system never enters an unsafe state

From Operating Systems › Deadlock Avoidance

  1. If Finish[i] == false for some i → system is in deadlock, and Pi is deadlocked. Complexity \(O(m\times n^2)\)

From Operating Systems › Deadlock Detection

  • Abort one process at a time until the deadlock cycle is eliminated — overhead: after each abort, run the detection algorithm
