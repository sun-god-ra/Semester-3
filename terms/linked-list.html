Linked list

  • Lists, stacks, queues (singly/doubly/circular linked lists; stack LIFO; queue FIFO), trees (binary search tree, balanced e.g. Linux's red–black tree for CPU scheduling), hash functions and maps, bitmaps (string of n binary digits representing availability of n items)

From Operating Systems › Operating-System Operations

  • Implementation: needs hardware assistance. Counter implementation: every page-table entry has a time-of-use field; CPU clock/counter is copied into it at every reference; replace the page with the smallest time value (search of page table needed; clock overflow). Stack implementation: keep a stack of page numbers as a doubly linked list: when a page is referenced, move it to the top (requires up to 6 pointers to be changed); no search for replacement (the bottom is the LRU page). Updating on every memory reference must be done in hardware (otherwise slows every reference by a factor of at least 10)

From Operating Systems › Page Replacement

  • Each file is a linked list of disk blocks (blocks may be scattered anywhere on the disk); each block contains a pointer to the next block; directory contains a pointer to the first and last blocks of the file; to create a new file simply create a new entry in the directory with the pointer set to null; write → find a free block and link it at the end; read → follow pointers. Advantages: no external fragmentation; no need to declare file size in advance; file can continue to grow as long as free blocks exist; no compaction. Disadvantages: can be used effectively only for sequential-access files (to find the ith block you must follow i pointers → many disk reads, each a seek); space required for the pointers (e.g., a 512-byte block with 4-byte pointer → 0.78 % of the disk wasted; fix: group blocks into clusters → internal fragmentation, but fewer pointers and improved throughput); reliability — loss or damage of a pointer (a bug or hardware failure → the wrong block picked; partial fix: doubly linked list or store the file name and relative block number in each block → even more overhead). Effective data per block = block size − pointer size (e.g. 512 − 4 = 508 bytes)

From Operating Systems › Allocation Methods

  • LinkedHashSet: hash table + linked list; keeps insertion order

From Java › Set Interface

  • Hash table of buckets; hashCode() of key → bucket index; collisions: linked list → balanced tree when a bucket has more than 8 entries (Java 8)
