Page fault

  • Page fault — first reference to a page not in memory traps to the OS. Steps in handling a page fault
    1. Reference → trap to the OS (internal table in the PCB: is the reference valid or invalid?)
    2. If invalid → terminate the process; if valid but not yet in memory → page it in
    3. Find a free frame (from the free-frame list)
    4. Schedule a disk operation to read the desired page into the newly allocated frame
    5. When the read is complete, modify the internal table (PCB) and the page table (valid bit = v)
    6. Restart the instruction that caused the page fault (the process continues as though the page had always been in memory)

From Operating Systems › Demand Paging

  • Page faults vs number of frames: as the number of frames increases, the number of page faults should decrease (the curve falls)

From Operating Systems › Page Replacement

  • Prepaging — bring in some or all of the pages a process will need before they are referenced (reduces the large number of page faults at process start-up; wasteful if pages are not used). Page size selection: fragmentation (small pages → less internal fragmentation), page-table size (large pages → small table), I/O overhead (seek and latency dominate → bigger is better), number of page faults, locality, TLB size and effectiveness (TLB reach = (TLB size) × (page size) — to increase: larger page size or multiple page sizes); typical 4 KB, trend toward larger. Program structure: e.g. a 128×128 array of ints, page size 128 words — row-major accessing for j { for i { data[i][j] = 0 } } → 128 × 128 = 16,384 page faults, while for i { for j { data[i][j] = 0 } } → 128 page faults — good data-structure and programming choices improve locality. I/O interlock and page locking: pages used for I/O must be pinned (locked) in memory so they are not replaced

From Operating Systems › Thrashing

  • Cost: each first write causes a page fault and a page copy; the pages that are copied come from a pool of zero-filled free frames.

From Operating Systems Unit IV questions › question

  • Allocation schemes: equal allocation — divide m frames among n processes: \(m/n\) each (e.g., 100 frames, 5 processes → 20 each; wasteful for small processes); proportional allocation — allocate according to process size: \(a_i=\dfrac{s_i}{S}\times m\) where \(S=\sum s_i\). Example: \(m=62\) frames, two processes of size \(s_1=10\) pages, \(s_2=127\) pages: \(S=137\); \(a_1=\frac{10}{137}\times62\approx4\); \(a_2=\frac{127}{137}\times62\approx57\). Priority allocation — proportional allocation using priorities rather than size (or a combination of size and priority); on a page fault, select for replacement one of its own frames or a frame from a lower-priority process
