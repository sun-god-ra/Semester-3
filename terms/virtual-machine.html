Term · Java, Operating Systems

Virtual machine

  • JVM (Java Virtual Machine): abstract machine that runs bytecode. Different JVM for each OS/CPU, but the same bytecode runs on all → portability. Parts: class loader, bytecode verifier, interpreter, JIT, garbage collector, runtime data areas (heap, stack, method area)

From Java › Bytecode, JVM, JRE, JDK

  • Virtualisation and emulation: a virtual machine manager (hypervisor/VMM) lets one computer run several guest OSes; emulation simulates hardware (e.g., running ARM code on x86 – slower), VMware, VirtualBox, Java Virtual Machine

From Operating Systems › Free and Open-Source Operating Systems

JVM executes bytecode (the virtual machine). JRE = JVM + class libraries needed to run programs. JDK = JRE + development tools (javac, jar, javadoc, debugger) needed to develop programs.

  1. Virtual machines: a layer that presents the hardware as many separate virtual machines.

  • Hybrid systems — combine multiple approaches: Linux and Solaris — monolithic (performance) + modular (dynamic); Windows — monolithic with some microkernel behaviour (subsystems); macOS and iOS — layered Aqua UI over Cocoa (frameworks) over kernel environment (Mach microkernel + BSD UNIX kernel + I/O Kit + kernel extensions (kexts)); Android — Linux kernel modified, ART virtual machine, Java API, Bionic libc, HAL, libraries (SQLite, SSL, OpenGL)
