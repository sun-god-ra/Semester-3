Term · Java, Operating Systems

Context switch

  • Performance depends on quantum: \(q\) large → FCFS; \(q\) small → too many context switches (overhead) — \(q\) must be large with respect to the context-switch time (e.g., context switch 10 µs, q = 10 ms → 0.1 % overhead; context switch time should be < 10 % of the quantum). Rule of thumb: 80 % of CPU bursts should be shorter than \(q\). Average turnaround time does not necessarily improve as \(q\) increases

From Operating Systems › Scheduling Algorithms

  • Busy waiting (spinning): while a process is in its CS, any other process trying to enter loops continuously in acquire() — wastes CPU cycles. Lock that spins = spinlock. Advantage: no context switch is required when a process must wait on a lock — useful on multiprocessor systems when locks are held for a short time (less than two context switches) — one thread spins on one core while another performs its CS on another core

From Operating Systems › Mutex Locks

  • Context switch: when the CPU switches to another process, the system must save the state of the old process (in its PCB) and load the saved state of the new process; context of a process is represented in the PCB (registers, process state, memory-management info). Context-switch time is pure overhead (system does no useful work); depends on hardware (memory speed, number of registers to copy, special instructions) — typically a few microseconds; some processors provide multiple register sets to cut it. Dispatcher performs it

From Operating Systems › Process Scheduling

  • The two-memory-access problem can be solved by the use of a special fast-lookup hardware cache: associative memory / translation look-aside buffer (TLB) — small (32–1024 entries), fast; each entry has two parts: a key (tag) and a value; the item being searched for is compared with all keys simultaneously; if found, the value is returned. TLB miss → page number looked up in the page table in memory; the entry is then added to the TLB (replacement policies: LRU, round robin, random); some entries can be wired down (kernel code). Some TLBs store address-space identifiers (ASIDs) in each entry — uniquely identify each process to provide address-space protection for that process and allow entries for several processes to coexist in the TLB (otherwise TLB must be flushed at every context switch)

From Operating Systems › Paging

The OS keeps all information about a process in its process control block (PCB): state, program counter, registers, scheduling information, memory-management information, accounting information and I/O status. During a context switch, the OS saves the PCB of the old process and loads the PCB of the new one.
