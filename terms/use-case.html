Home › Terms A–Z › Use case

Term · Java Lab, Software Eng

Use case

  • Elements: actor (stick figure), use case (oval), system boundary (box), association (line), include (mandatory reuse: «include»), extend (optional / conditional extension: «extend»), generalisation

From Software Eng › Developing Use Cases

  • Refining a preliminary use case: (1) define alternative interactions (what could go wrong?), (2) for each step ask: Can the actor take another action? Is it possible that the actor will encounter an error? Can the actor encounter other behaviour?

From Software Eng › Scenario-Based Modeling

  • A sequence diagram shows how events cause flow from one object to another as a function of time; a short-hand version of a use case. Elements: lifelines (vertical dashed lines per object), messages (horizontal arrows; solid = call, dashed = return), activation bars, time runs downward

From Software Eng › State Representations

  • Interface analysis: (1) User analysis — who are the users? skills? (interviews, observation, questionnaires, sales input, support input); (2) Task analysis and modeling — what work will the user perform? use cases, task elaboration (decomposition of tasks into subtasks), object elaboration (identify objects used by tasks), workflow analysis (swimlanes); (3) Analysis of display content — types of data (text, graphs), format, sizes; (4) Analysis of the work environment — physical location, lighting, noise, hardware constraints, platform

From Software Eng › User Interface Analysis and Design

  • Usage scenarios (use cases): as requirements gathering proceeds, scenarios that describe how the system will be used by different classes of users

From Software Eng › Eliciting Requirements
