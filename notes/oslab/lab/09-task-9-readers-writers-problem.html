Task 9 — Readers–writers problem

Operating Systems Lab · Lab: Programming Tasks 1 to 17

Task 9 — Readers–writers problem
Subject
Operating Systems Lab (24CS204)
Unit
Lab: Programming Tasks 1 to 17
Topic
9 of 17
Terms
Semaphore
Notebook notes
  • Aim: Implement the first readers–writers problem (readers' priority) with semaphores.
  • Theory
    • Many readers may read together; a writer needs exclusive access. Shared: rw_mutex = 1 (writers and the first reader), mutex = 1 (protects read_count), read_count = 0. Reader: lock mutex; read_count++; if it is 1 → wait(rw_mutex); unlock; read; lock; read_count--; if it is 0 → signal(rw_mutex); unlock. Writer: wait(rw_mutex); write; signal(rw_mutex). Writers may starve in this version
  • Algorithm
    • Start 4 reader threads and 2 writer threads
    • Each reader repeats the entry protocol, reads, and runs the exit protocol
    • Each writer takes rw_mutex, increments data, and releases
    • Count the violations (a writer active with a reader or another writer)
c
/* Task 9: readers-writers problem (first problem: readers' priority) */
#include <stdio.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>
sem_t rw_mutex;                              /* exclusive access for writers / first reader */
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
int read_count = 0, data = 0, active_readers = 0, active_writers = 0, violations = 0;
int reads_done = 0, writes_done = 0;

void *writer(void *arg) {
    for (int i = 0; i < 5; i++) {
        sem_wait(&rw_mutex);
        active_writers++;
        if (active_writers > 1 || active_readers > 0) violations++;
        data++; writes_done++;               /* write */
        usleep(500);
        active_writers--;
        sem_post(&rw_mutex);
        usleep(300);
    }
    return NULL;
}
void *reader(void *arg) {
    for (int i = 0; i < 8; i++) {
        pthread_mutex_lock(&mutex);
        read_count++;
        if (read_count == 1) sem_wait(&rw_mutex);   /* first reader locks out writers */
        active_readers++;
        pthread_mutex_unlock(&mutex);

        if (active_writers > 0) violations++;
        int v = data; (void)v; usleep(200);          /* read */
        pthread_mutex_lock(&mutex); reads_done++; pthread_mutex_unlock(&mutex);

        pthread_mutex_lock(&mutex);
        active_readers--;
        read_count--;
        if (read_count == 0) sem_post(&rw_mutex);    /* last reader lets writers in */
        pthread_mutex_unlock(&mutex);
        usleep(100);
    }
    return NULL;
}
int main() {
    pthread_t r[4], w[2];
    sem_init(&rw_mutex, 0, 1);
    for (int i = 0; i < 4; i++) pthread_create(&r[i], NULL, reader, NULL);
    for (int i = 0; i < 2; i++) pthread_create(&w[i], NULL, writer, NULL);
    for (int i = 0; i < 4; i++) pthread_join(r[i], NULL);
    for (int i = 0; i < 2; i++) pthread_join(w[i], NULL);
    printf("4 readers x 8 reads = %d reads done\n", reads_done);
    printf("2 writers x 5 writes = %d writes done, final data = %d\n", writes_done, data);
    printf("synchronisation violations = %d\n", violations);
    return 0;
}

Output

text
4 readers x 8 reads = 32 reads done
2 writers x 5 writes = 10 writes done, final data = 10
synchronisation violations = 0
  • Viva questions
    • Why does the first reader lock rw_mutex and the last reader release it?
    • Which version can starve writers? Which can starve readers?
    • Why do we need the mutex for read_count?
    • Where are reader–writer locks used? (databases, file systems)
    • What is the second readers–writers problem?
Explanation

There are 4 readers reading 8 times each (32 reads) and 2 writers writing 5 times each (10 writes), so the final value is 10. The counter of violations is 0, which shows that no writer ever overlapped with a reader or another writer. The order of the lines inside the threads varies between runs, so the program prints only the totals.
