Task 7 — Critical-section problem and Peterson's solution

Operating Systems Lab · Lab: Programming Tasks 1 to 17

Task 7 — Critical-section problem and Peterson's solution
Subject
Operating Systems Lab (24CS204)
Unit
Lab: Programming Tasks 1 to 17
Topic
7 of 17
Terms
Race condition, Mutex, Mutual exclusion, Critical section, Semaphore, Peterson's solution
Notebook notes
  • Aim: Show a race condition and solve the critical-section problem for two threads using Peterson's algorithm and a mutex lock.
  • Theory
    • A race condition occurs when the result depends on the order of access to shared data. A solution must give mutual exclusion, progress and bounded waiting. Peterson's algorithm uses flag[2] and turn: flag[i]=1; turn=j; while(flag[j] && turn==j); — critical section — flag[i]=0. On modern CPUs compilers and processors reorder memory operations, so the program must use atomic operations with sequentially consistent ordering (memory barriers) — here C11 atomic_int
    • A mutex is the simpler tool: pthread_mutex_lock() / pthread_mutex_unlock() (see Unit III)
  • Algorithm
    • Create two threads, each incrementing a shared counter 200,000 times
    • Protect the increment with Peterson's entry/exit code; print the total
    • Repeat with a pthread mutex
    • (Without any protection the total is usually less than 400,000: remove the lock to see it)
c
/* Task 7: critical-section problem: race condition, Peterson's solution, mutex */
#include <stdio.h>
#include <pthread.h>
#include <stdatomic.h>
#define LOOPS 200000

long counter = 0;
/* Peterson's algorithm for two threads; seq_cst atomics supply the memory barriers it needs on modern CPUs */
atomic_int flag[2], turn;
void enter(int i) { int j = 1 - i; atomic_store(&flag[i], 1); atomic_store(&turn, j);
                    while (atomic_load(&flag[j]) && atomic_load(&turn) == j) ; }
void leave(int i) { atomic_store(&flag[i], 0); }

void *worker_peterson(void *arg) {
    int id = *(int *)arg;
    for (int i = 0; i < LOOPS; i++) { enter(id); counter++; leave(id); }
    return NULL;
}
pthread_mutex_t m = PTHREAD_MUTEX_INITIALIZER;
void *worker_mutex(void *arg) {
    for (int i = 0; i < LOOPS; i++) { pthread_mutex_lock(&m); counter++; pthread_mutex_unlock(&m); }
    return NULL;
}
int main() {
    pthread_t t[2]; int id[2] = {0, 1};
    counter = 0;
    pthread_create(&t[0], NULL, worker_peterson, &id[0]);
    pthread_create(&t[1], NULL, worker_peterson, &id[1]);
    pthread_join(t[0], NULL); pthread_join(t[1], NULL);
    printf("Peterson's solution : counter = %ld (expected %d)\n", counter, 2 * LOOPS);
    counter = 0;
    pthread_create(&t[0], NULL, worker_mutex, NULL);
    pthread_create(&t[1], NULL, worker_mutex, NULL);
    pthread_join(t[0], NULL); pthread_join(t[1], NULL);
    printf("Mutex lock          : counter = %ld (expected %d)\n", counter, 2 * LOOPS);
    return 0;
}

Output

text
Peterson's solution : counter = 400000 (expected 400000)
Mutex lock          : counter = 400000 (expected 400000)
  • Viva questions
    • What are the three requirements of a critical-section solution?
    • Why can Peterson's algorithm fail without memory barriers?
    • Why do we use volatile/atomics here?
    • Mutex vs semaphore?
    • What is busy waiting? (spinlock)
Explanation

Each thread executes counter++ 200,000 times, so a correct result is 400,000. In Peterson's solution each thread first announces that it wants to enter (flag[i]=1), then gives the turn to the other (turn=j), and waits while the other wants to enter and it is the other's turn. Mutual exclusion holds, so no increment is lost. The atomic variables are essential: with ordinary variables the compiler or the CPU may reorder the store operations and the algorithm may break on modern hardware. The mutex version gives the same total.
