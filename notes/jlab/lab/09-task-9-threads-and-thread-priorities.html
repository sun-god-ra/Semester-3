Task 9 — Threads and thread priorities

Java Programming Lab · Lab: Tasks 1 to 12

Task 9 — Threads and thread priorities
Subject
Java Programming Lab (24CS281)
Unit
Lab: Tasks 1 to 12
Topic
9 of 12
Terms
Race condition, Inheritance
On this page
  1. Program 1 — Creating threads and multiple threads
  2. Program 2 — Thread priorities
Notebook notes
  • Aim: Create threads by extending Thread and implementing Runnable, run several threads, and set priorities.
  • Key points
    • Two ways: extend Thread and override run(); or implement Runnable and pass it to new Thread(r). Call start() (creates a new call stack and calls run()), not run() (which would be a normal method call in the current thread)
    • Thread life cycle: New → Runnable → Running → Blocked/Waiting/Timed waiting → Terminated
    • join() waits for a thread to finish; sleep(ms); isAlive(); getName(); Thread.currentThread()
    • Race condition: threads updating shared data without protection give wrong results; synchronized methods allow only one thread at a time on an object (monitor lock)
    • Priority 1 (MIN_PRIORITY) to 10 (MAX_PRIORITY), default 5 (NORM_PRIORITY). It is only a hint to the scheduler — no guarantee of execution order. A thread inherits the priority of its creator
  • Procedure
    • Write a class extending Thread with run(); start it and join it
    • Write a Runnable class (or lambda) and start it in a Thread
    • Start several threads which increment a shared counter and join them all
    • Set priorities with setPriority and print with getPriority
Program 1 — Creating threads and multiple threads
java
class Worker extends Thread {                       // way 1: extend Thread
    Worker(String name) { super(name); }
    public void run() {
        for (int i = 1; i <= 3; i++) System.out.println(getName() + " step " + i);
    }
}
class Task implements Runnable {                    // way 2: implement Runnable
    public void run() {
        System.out.println(Thread.currentThread().getName() + " running Task");
    }
}
class Counter {
    private int count = 0;
    synchronized void increment() { count++; }      // remove synchronized to see a race condition
    int get() { return count; }
}
public class ThreadDemo {
    public static void main(String[] args) throws InterruptedException {
        Worker w1 = new Worker("Worker-1");
        w1.start();
        w1.join();                                  // wait so the output order is fixed
        Thread t = new Thread(new Task(), "Task-thread");
        t.start();
        t.join();
        // multiple threads sharing one object
        Counter counter = new Counter();
        Thread[] ts = new Thread[4];
        for (int i = 0; i < ts.length; i++) {
            ts[i] = new Thread(() -> { for (int j = 0; j < 1000; j++) counter.increment(); });
            ts[i].start();
        }
        for (Thread x : ts) x.join();
        System.out.println("Final count = " + counter.get() + " (expected 4000)");
        System.out.println("main thread: " + Thread.currentThread().getName() + ", alive? " + w1.isAlive());
    }
}

Output

text
Worker-1 step 1
Worker-1 step 2
Worker-1 step 3
Task-thread running Task
Final count = 4000 (expected 4000)
main thread: main, alive? false
Program 2 — Thread priorities
java
public class PriorityDemo {
    static long[] result = new long[3];
    public static void main(String[] args) throws InterruptedException {
        Thread[] t = new Thread[3];
        int[] prio = {Thread.MIN_PRIORITY, Thread.NORM_PRIORITY, Thread.MAX_PRIORITY};
        String[] names = {"low", "normal", "high"};
        for (int i = 0; i < 3; i++) {
            final int id = i;
            t[i] = new Thread(() -> {
                long s = 0;
                for (int k = 1; k <= 1000000; k++) s += k;
                result[id] = s;
            }, names[i]);
            t[i].setPriority(prio[i]);
            System.out.println(t[i].getName() + " priority = " + t[i].getPriority());
        }
        System.out.println("main priority = " + Thread.currentThread().getPriority());
        for (Thread x : t) x.start();
        for (Thread x : t) x.join();
        for (int i = 0; i < 3; i++) System.out.println(names[i] + " sum = " + result[i]);
        System.out.println("MIN=" + Thread.MIN_PRIORITY + " NORM=" + Thread.NORM_PRIORITY + " MAX=" + Thread.MAX_PRIORITY);
    }
}

Output

text
low priority = 1
normal priority = 5
high priority = 10
main priority = 5
low sum = 500000500000
normal sum = 500000500000
high sum = 500000500000
MIN=1 NORM=5 MAX=10
  • Viva questions
    • Why start() and not run()?
    • Why is Runnable preferred over extending Thread? (Java has single inheritance)
    • What does synchronized do? What would the count be without it? (Less than 4000, varies)
    • Does a higher priority thread always run first? (No)
    • Difference between sleep() and wait()?
Explanation

Program 1 starts Worker-1 and waits for it with join(), so its three steps print before the next thread starts. The Runnable is wrapped in a Thread named Task-thread. Then four threads each add 1 to a shared counter 1000 times; because increment() is synchronized the final count is always 4000 (the count++ is read-modify-write, and without a lock updates would be lost). In program 2 each thread gets a priority through setPriority; the main thread has priority 5, and new threads inherit it unless it is changed. All three threads compute the same sum, 500000500000, and the priority affects only the likely order of scheduling, not the result.
