Task 6 — Inheritance, `super`, overriding and dynamic dispatch

Java Programming Lab · Lab: Tasks 1 to 12

Task 6 — Inheritance, `super`, overriding and dynamic dispatch
Subject
Java Programming Lab (24CS281)
Unit
Lab: Tasks 1 to 12
Topic
6 of 12
Terms
Method overriding, Polymorphism, Inheritance, Constructor, Dynamic method dispatch
On this page
  1. Program 1 — Multilevel inheritance with super
  2. Program 2 — Overriding and dynamic dispatch
Notebook notes
  • Aim: Build a class hierarchy using extends and super; show method overriding and run-time polymorphism.
  • Key points
    • Inheritance: class B extends A — B gets the non-private members of A (IS-A relationship). Java has single inheritance of classes (multiple through interfaces). Every class extends Object
    • super(...) calls the parent constructor (must be the first statement; the compiler inserts super() if absent) → constructors run top-down: Person → Employee → Manager. super.method() calls the parent's version
    • Overriding: the subclass redefines an inherited method with the same name, same parameters, compatible return type, same or wider access. Cannot override final, static or private methods. Use @Override
    • Dynamic method dispatch: a superclass reference can hold a subclass object; the method that runs is decided at run time by the actual object, not by the reference type. Fields are not overridden (they follow the reference type)
    • Through a superclass reference only the superclass members are visible; use a cast (after instanceof) to call subclass-only methods
  • Procedure
    • Create the parent class with a constructor
    • Create child classes using extends and call super(...)
    • Redefine a method in the child with @Override
    • Declare Animal a = new Dog(); and call the overridden method
Program 1 — Multilevel inheritance with super
java
class Person {
    String name; int age;
    Person(String name, int age) { this.name = name; this.age = age; System.out.println("Person constructor"); }
    void show() { System.out.println("Name: " + name + ", Age: " + age); }
}
class Employee extends Person {
    int salary;
    Employee(String name, int age, int salary) {
        super(name, age);                       // must be the first statement
        this.salary = salary;
        System.out.println("Employee constructor");
    }
    void show() {
        super.show();                           // call the parent version
        System.out.println("Salary: " + salary);
    }
}
class Manager extends Employee {
    String dept;
    Manager(String name, int age, int salary, String dept) {
        super(name, age, salary);
        this.dept = dept;
        System.out.println("Manager constructor");
    }
    void show() { super.show(); System.out.println("Department: " + dept); }
}
public class InheritanceDemo {
    public static void main(String[] args) {
        Manager m = new Manager("Ravi", 40, 90000, "Sales");
        m.show();
        System.out.println(m instanceof Person);
    }
}

Output

text
Person constructor
Employee constructor
Manager constructor
Name: Ravi, Age: 40
Salary: 90000
Department: Sales
true
Program 2 — Overriding and dynamic dispatch
java
class Animal {
    void sound() { System.out.println("Animal makes a sound"); }
    void eat() { System.out.println("Animal eats"); }
}
class Dog extends Animal {
    @Override void sound() { System.out.println("Dog barks"); }
    void fetch() { System.out.println("Dog fetches"); }
}
class Cat extends Animal {
    @Override void sound() { System.out.println("Cat meows"); }
}
public class OverrideDemo {
    public static void main(String[] args) {
        Animal a;                       // superclass reference
        a = new Animal(); a.sound();
        a = new Dog();    a.sound();    // decided at run time -> Dog's version
        a = new Cat();    a.sound();
        a.eat();                        // inherited, not overridden
        Animal[] zoo = { new Dog(), new Cat(), new Animal() };
        for (Animal x : zoo) x.sound();
        // a.fetch();                   // compile error: reference type Animal has no fetch()
        Animal d = new Dog();
        if (d instanceof Dog) ((Dog) d).fetch();   // downcast
    }
}

Output

text
Animal makes a sound
Dog barks
Cat meows
Animal eats
Dog barks
Cat meows
Animal makes a sound
Dog fetches
  • Viva questions
    • Overloading vs overriding?
    • Why does the parent constructor run first?
    • Can a constructor be inherited or overridden? (No)
    • What happens if the parent has no default constructor and the child doesn't call super(args)? (compile error)
    • What is upcasting and downcasting? What does instanceof do?
Explanation

In program 1, creating a Manager runs the constructors from the top: Person, Employee, Manager, each called through super(...). show() in each class prints its own part and starts by calling super.show(), so the output builds up from the parent. In program 2, the reference type is always Animal, but the version of sound() that runs depends on the object assigned at run time (dynamic dispatch): Animal, Dog and Cat print different sounds. eat() is not overridden, so the inherited version is used. a.fetch() would be a compile error, because the compiler only checks the reference type; after instanceof the cast (Dog) makes it legal.
