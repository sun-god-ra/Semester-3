Task 5 — Method overloading, String, StringBuffer and StringTokenizer

Notebook notes
  • Aim: Show compile-time polymorphism through method overloading, and use the string-handling classes.
  • Key points
    • Overloading: same method name, different parameter lists (number, type or order). Return type alone is not enough. Resolved at compile time (static binding) — exact match → widening → boxing → varargs
    • String is immutable (methods return new strings); literals are shared in the string pool, new String(..) creates a separate object → == compares references, equals() compares content
    • StringBuffer is mutable and thread-safe (synchronized); StringBuilder is the same but faster and not synchronized. append, insert, reverse, delete, replace, setCharAt, length(), capacity() (initial 16 + length of the initial string)
    • StringTokenizer (java.util) splits a string by delimiters: hasMoreTokens(), nextToken(), countTokens(); with returnDelims = true the delimiters are tokens too
  • Procedure
    • Write several methods with the same name and different parameters
    • Call them with different arguments and see which one is chosen
    • Use String methods: length, charAt, substring, indexOf, replace, compareTo, equals
    • Modify a StringBuffer and print
    • Tokenize a string with several delimiters
Program 1 — Method overloading
java
public class OverloadDemo {
    static int area(int side) { return side * side; }                     // square
    static int area(int l, int b) { return l * b; }                       // rectangle
    static double area(double r) { return Math.PI * r * r; }              // circle
    static double area(double b, double h, boolean triangle) { return 0.5 * b * h; }
    static void show(int x) { System.out.println("int version " + x); }
    static void show(long x) { System.out.println("long version " + x); }
    static void show(double x) { System.out.println("double version " + x); }
    static void show(Object x) { System.out.println("Object version " + x); }
    static int sum(int... nums) {                                          // varargs
        int s = 0;
        for (int n : nums) s += n;
        return s;
    }
    public static void main(String[] args) {
        System.out.println("square 4         = " + area(4));
        System.out.println("rectangle 4 x 5  = " + area(4, 5));
        System.out.printf("circle r=2.0     = %.2f%n", area(2.0));
        System.out.println("triangle 6, 3    = " + area(6, 3, true));
        show(5);          // exact match int
        show(5L);         // exact match long
        show(5.5f);       // float -> double (widening)
        show('A');        // char -> int (widening)
        show("text");     // Object
        byte bt = 1;
        show(bt);         // byte -> int
        System.out.println("sum() = " + sum() + ", sum(1,2,3) = " + sum(1, 2, 3));
    }
}

Program 2 — String, StringBuffer, StringTokenizer
java
import java.util.StringTokenizer;
public class StringDemo {
    public static void main(String[] args) {
        // ---- String (immutable) ----
        String s = "Java Programming";
        System.out.println(s.length() + " " + s.charAt(5) + " " + s.indexOf("Pro") + " " + s.toUpperCase());
        System.out.println(s.substring(5) + " | " + s.substring(0, 4) + " | " + s.replace('a', 'A'));
        String s1 = "hello", s2 = "hello", s3 = new String("hello");
        System.out.println("s1 == s2 : " + (s1 == s2) + ", s1 == s3 : " + (s1 == s3)
                + ", s1.equals(s3) : " + s1.equals(s3));
        System.out.println("compareTo : " + "apple".compareTo("banana") + ", equalsIgnoreCase : " + "JAVA".equalsIgnoreCase("java"));
        System.out.println("trim : [" + "  hi  ".trim() + "], contains : " + s.contains("gram") + ", startsWith : " + s.startsWith("Java"));
        String t = s.concat("!");
        System.out.println("original unchanged : " + s + ", new : " + t);
        // ---- StringBuffer (mutable) ----
        StringBuffer sb = new StringBuffer("Hello");
        sb.append(" World").insert(0, ">> ").reverse();
        System.out.println(sb);
        sb.reverse();
        sb.setCharAt(3, 'h');
        sb.delete(0, 3).replace(0, 5, "HELLO");
        System.out.println(sb + " length " + sb.length() + " capacity " + sb.capacity());
        // ---- StringTokenizer ----
        StringTokenizer st = new StringTokenizer("one,two;three four", ",; ");
        System.out.println("tokens = " + st.countTokens());
        while (st.hasMoreTokens()) System.out.println(st.nextToken());
        StringTokenizer st2 = new StringTokenizer("a=1&b=2", "=&", true);   // returns delimiters too
        while (st2.hasMoreTokens()) System.out.print("[" + st2.nextToken() + "]");
        System.out.println();
    }
}

  • Viva questions
    • Can we overload main? (yes, but JVM calls only the standard one)
    • Can overloading be done by changing only the return type? (No)
    • Why is String immutable? (security, string pool, thread safety, hash code caching)
    • Difference between String, StringBuffer and StringBuilder?
    • s1 == s2 for two literals with the same content? (true — string pool)
Explanation

In program 1 the compiler picks the version by argument types: show(5) matches int, show(5L) matches long, show(5.5f) is widened to double, show('A') is widened to int (prints 65), show(bt) with a byte goes to int, and a String goes to Object. The varargs method sum(int...) accepts any number of arguments. In program 2, s1 == s2 is true because both literals share one object in the pool, while new String("hello") makes another one, so == is false but equals is true. concat does not change s; it returns a new string. The StringBuffer is changed in place by chained calls. StringTokenizer splits on any character in the delimiter set, so "one,two;three four" gives four tokens.
