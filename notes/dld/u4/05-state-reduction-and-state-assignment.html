State Reduction and State Assignment

Digital Logic Design · Unit IV: Sequential Logic and State Machine Design

State Reduction and State Assignment
Subject
Digital Logic Design (24CS201)
Unit
Unit IV: Sequential Logic and State Machine Design
Topic
5 of 7
Terms
Flip-flop, Gray code

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • State reduction: fewer states → fewer flip-flops and gates. Two states are equivalent if, for every input sequence, they give the same outputs and go to equivalent next states
  • Row-matching method: find two rows with the same next states and same outputs → merge (replace one by the other everywhere) → repeat
  • Example: 7 states reduce to 5
Present \(x=0\) \(x=1\) Output \(x=0,1\)
a a b 0,0
b c d 0,0
c a d 0,0
d e f 0,1
e a f 0,1
f g f 0,1
g a f 0,1
  • \(e\) and \(g\) identical (a,f / 0,1) → replace \(g\) by \(e\)
    • then \(f\) becomes (e,f / 0,1) = same as \(d\) → replace \(f\) by \(d\)
    • reduced: a (a,b), b (c,d), c (a,d), d (e,d / 0,1), e (a,d / 0,1) → 5 states. Still 3 flip-flops (\(\lceil\log_2 5\rceil=\lceil\log_2 7\rceil=3\)) but simpler logic and more don't-cares
  • Number of FFs: \(n\ge\lceil\log_2(\text{states})\rceil\)
  • For incompletely specified machines → implication table method (compatible states)
  • State assignment: give binary codes to states. Different assignments → different logic cost. Rules of thumb: states with the same next state get adjacent codes; Gray code assignment; one-hot assignment (one FF per state; fast, more FFs)
  • Binary (000,001,…), Gray, one-hot (0001,0010,0100,1000)
Explanation

Fewer states can mean fewer flip-flops and simpler logic. Two states are equivalent if no experiment on the outputs can tell them apart. The simple test is that they have the same outputs for each input and lead to the same next states (or to states that are themselves equivalent). In the example \(e\) and \(g\) are identical, so \(g\) is removed and everything that went to \(g\) now goes to \(e\). After that substitution, \(f\) becomes identical to \(d\), and so \(f\) is removed. It is important to repeat the check after each merge, since a merge can create new equal rows.

The number of flip-flops is the ceiling of \(\log_2\) of the number of states, so reducing from 7 to 5 states does not change the count (3 flip-flops either way), but the combinational logic will usually be simpler and there are more unused states to use as don't-cares. State assignment is the choice of binary codes. Different choices give different logic costs, and there is no formula for the best one. A practical rule is to give adjacent codes to states that share a next state or that follow each other. One-hot encoding uses one flip-flop per state, which needs more flip-flops but very simple next-state logic, and is common in FPGAs.
