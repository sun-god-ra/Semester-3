Tabulation (Quine–McCluskey) Method

Digital Logic Design · Unit II: Boolean Function Simplification and Combinational Logic Design

Tabulation (Quine–McCluskey) Method
Subject
Digital Logic Design (24CS201)
Unit
Unit II: Boolean Function Simplification and Combinational Logic Design
Topic
5 of 10
Terms
K-map, Minterm, Prime implicant

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Systematic method — works for any number of variables, programmable. K-map is limited to ~5–6 variables
  • Steps
    1. List minterms (and don't-cares) in binary, group by number of 1s
    2. Compare adjacent groups. If two terms differ in one bit, combine; write – in the changed place; tick both
    3. Repeat on the new column until no more combining. Untick-ed terms = prime implicants
    4. Build the prime implicant chart (rows = PIs, columns = minterms; don't-cares are not columns)
    5. Pick essential PIs (column with a single ×). Cover the rest with fewest PIs (Petrick's method if needed)
  • Terms only combine if the dash is in the same position

Example: \(F=\sum m(0,1,2,5,6,7,8,9,10,14)\)

Col 1 (by number of 1s) Col 2 (pairs) Col 3 (quads)
0 : 0000 0,1 : 000– 0,2,8,10 : –0–0
1 : 0001 0,2 : 00–0 0,1,8,9 : –00–
2 : 0010 0,8 : –000 2,6,10,14 : ––10
8 : 1000 1,5 : 0–01
5 : 0101 1,9 : –001
6 : 0110 2,6 : 0–10
9 : 1001 2,10 : –010
10 : 1010 8,9 : 100–
7 : 0111 8,10 : 10–0
14 : 1110 5,7 : 01–1
6,7 : 011–
6,14 : –110
10,14 : 1–10
  • Prime implicants: \(A'C'D\) (1,5), \(A'BD\) (5,7), \(A'BC\) (6,7), \(B'D'\) (0,2,8,10), \(B'C'\) (0,1,8,9), \(CD'\) (2,6,10,14)
  • Essential: minterm 9 only in \(B'C'\); minterm 14 only in \(CD'\). These two cover 0,1,2,6,8,9,10,14. Left: 5, 7 → both in \(A'BD\)
  • \(F=B'C'+CD'+A'BD\)
Explanation

The K-map breaks down above five or six variables, and it relies on a human to see the groups. The Quine–McCluskey method does the same job with a fixed procedure, so it can be programmed. Terms are sorted by their number of 1s, because only terms in neighbouring groups can differ in a single bit. Terms that differ in exactly one position are merged and the position is marked with a dash. A term that cannot be merged any further is a prime implicant. The merging requires dashes in the same position, so (0,2) cannot combine with (1,9).

The second stage is the prime-implicant chart. Rows are the prime implicants and columns the minterms that must be covered. A column with a single mark identifies an essential prime implicant. After choosing those, we cover the leftover minterms with as few additional implicants as possible. Don't-care minterms take part in the merging but are not listed as columns in the chart, since they need not be covered.
