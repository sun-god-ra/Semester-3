Binary Codes

Digital Logic Design · Unit I: Number Systems, Boolean Algebra, and Logic Gates

Binary Codes
Subject
Digital Logic Design (24CS201)
Unit
Unit I: Number Systems, Boolean Algebra, and Logic Gates
Topic
5 of 12
Terms
BCD, Excess-3, Gray code, Encoder, K-map, ASCII, Parity bit, Hamming code

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • BCD (8421): each decimal digit → 4-bit binary. \(457=0100\ 0101\ 0111\). Codes 1010–1111 invalid
    • BCD addition: if sum of digits \(>9\) (or carry out) → add 0110 (6) to correct
  • Excess-3: BCD + 3. \(457\to0111\ 1000\ 1010\). Self-complementing (9's complement = flip all bits)
  • 2421, 84-2-1: other weighted BCD codes; 2421 and excess-3 are self-complementing
  • Gray code (reflected, unweighted): only one bit changes between consecutive numbers
    • binary → Gray: \(g_{n-1}=b_{n-1}\), \(g_i=b_{i+1}\oplus b_i\)
    • Gray → binary: \(b_{n-1}=g_{n-1}\), \(b_i=b_{i+1}\oplus g_i\)
    • 3-bit: 000 001 011 010 110 111 101 100
    • uses: shaft/position encoders, K-maps, avoid glitches
  • Alphanumeric: ASCII 7-bit (128 chars; 'A' = 65 = 1000001, 'a' = 97, '0' = 48); EBCDIC 8-bit (IBM); Unicode 16+ bit
  • Error-detecting: parity bit — even parity: total number of 1s even; odd parity: odd. Detects single-bit (odd number of) errors, cannot correct
  • Error-correcting: Hamming code — extra parity bits at positions \(2^k\) (1, 2, 4, 8…). Number of parity bits \(p\): \(2^p\ge m+p+1\). Single-error correct, double-error detect (with extra bit)
    • minimum Hamming distance \(d\): detects \(d-1\) errors, corrects \(\lfloor (d-1)/2\rfloor\)
Explanation

BCD stores each decimal digit in four bits, which makes decimal input and output simple but wastes the six unused patterns. When two BCD digits are added in a normal binary adder, a digit sum above 9 lands in the invalid range, or produces a carry, so we add 6 to skip the six invalid patterns and get the correct digit and carry.

Excess-3 is BCD plus 3. Its useful feature is that the 9's complement of a digit is obtained by flipping all four bits, so it is used in decimal subtraction. The Gray code changes exactly one bit between consecutive values. This matters in mechanical encoders, where several bits might change at slightly different times in a binary count and give a false reading in between. With Gray code the worst error is one position.

Parity adds one bit so the total count of ones is even (or odd). If one bit is flipped in transit, the parity no longer matches, so the error is detected, but we cannot say which bit failed and two errors cancel. Hamming codes place several parity bits at the power-of-2 positions, each covering a different group of bits. The pattern of failing parity checks is a binary number that points directly at the wrong bit, so the error can be corrected. The inequality \(2^p\ge m+p+1\) says that the \(p\) check bits must be able to name any of the \(m+p\) positions, or say that nothing is wrong.
