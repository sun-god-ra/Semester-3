Integer and Floating-Point Representation

Digital Logic Design · Unit I: Number Systems, Boolean Algebra, and Logic Gates

Integer and Floating-Point Representation
Subject
Digital Logic Design (24CS201)
Unit
Unit I: Number Systems, Boolean Algebra, and Logic Gates
Topic
6 of 12
Terms
Floating point, IEEE 754

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Unsigned \(n\) bits: \(0\) to \(2^n-1\)
  • Signed integer (MSB = sign bit; 0 = +, 1 = −). Three forms for \(n\) bits:
Form Range (\(n\) bits) Zero Note
Sign-magnitude \(-(2^{n-1}-1)\) to \(+(2^{n-1}-1)\) two (+0, −0) MSB sign, rest magnitude
Signed 1's complement same two negative = flip all bits
Signed 2's complement \(-2^{n-1}\) to \(+(2^{n-1}-1)\) one most used
  • 8-bit: \(-45\) → \(+45=00101101\) → flip → \(11010010\) → +1 → \(11010011\)
  • Extending a 2's complement number: copy the sign bit (sign extension)
  • Floating point: \(N=\pm\,m\times b^{e}\) (mantissa/significand, exponent, base). Normalised so \(1\le m<2\)
  • IEEE 754 single precision (32 bit): 1 sign | 8 exponent (bias 127) | 23 fraction

\[(-1)^s\times(1.f)\times2^{\,E-127}\]

  • Double (64 bit): 1 | 11 (bias 1023) | 52
  • Example \(-13.25\): \(13.25=1101.01_2=1.10101\times2^3\); \(E=3+127=130=10000010\); → 1 10000010 10101000…0 = C1540000h
  • \(1.0=0\ 01111111\ 0…0\) = 3F800000h ; \(5.75=1.0111\times2^2\)
  • Special: \(E=0,f=0\) → ±0; \(E=255,f=0\) → ±∞; \(E=255,f\ne0\) → NaN; \(E=0,f\ne0\) → denormal
  • Floating-point addition: align exponents → add mantissas → normalise → round
Explanation

Sign-magnitude is the natural way to write a signed number, but it has two zeros and needs special logic for addition. 2's complement avoids both problems, because the same adder works for signed and unsigned numbers, and there is only one zero. The range is not symmetric: an 8-bit number covers −128 to +127.

A floating-point number is like scientific notation. IEEE 754 stores the sign, a biased exponent, and the fraction. The leading 1 of a normalised mantissa is always 1, so it is not stored (the hidden bit), which gives 24 bits of precision from 23 stored bits. The exponent is stored with a bias of 127 so that it is an unsigned field and comparing two floating-point numbers can be done like comparing integers. To encode −13.25: convert 13.25 to binary (1101.01), shift to 1.10101 × 2³, add 127 to the exponent to get 130, and write the fraction bits 10101 padded with zeros.
