Number Base Conversions

Digital Logic Design · Unit I: Number Systems, Boolean Algebra, and Logic Gates

Number Base Conversions
Subject
Digital Logic Design (24CS201)
Unit
Unit I: Number Systems, Boolean Algebra, and Logic Gates
Topic
3 of 12

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Any base → decimal: multiply each digit by its weight \(r^i\) and add
    • \((1101011)_2=64+32+8+2+1=(107)_{10}\)
    • \((7F)_{16}=7\times16+15=(127)_{10}\)
    • \((725)_8=7\times64+2\times8+5=(469)_{10}\)
    • \((101.101)_2=4+1+0.5+0.125=(5.625)_{10}\)
  • Decimal → any base, integer part: divide repeatedly by \(r\), collect remainders, read bottom to top
    • \(156\div2\): remainders 0,0,1,1,1,0,0,1 → \((10011100)_2\). Also \((234)_8\), \((9C)_{16}\)
  • Decimal → any base, fraction part: multiply repeatedly by \(r\), collect integer parts, read top to bottom
    • \(0.6875\): ×2=1.375 →1; 0.375×2=0.75 →0; 0.75×2=1.5 →1; 0.5×2=1.0 →1 → \((0.1011)_2\)
    • \(0.1_{10}\) = 0.0001100110011… → never ends (recurring). So 0.1 can't be stored exactly in binary!
  • Binary ↔ octal: group bits in 3's from the binary point (pad with 0s)
    • \((10\,110\,101)_2=(265)_8\)
  • Binary ↔ hex: group in 4's
    • \((1011\,0101)_2=(B5)_{16}\), \((B5)_{16}=181_{10}\)
  • Octal ↔ hex: go through binary
  • Fractions: group outwards from the point in both directions, pad left of integer part and right of fraction part
Explanation

A positional system gives each digit a weight equal to a power of the base. In binary the weights are 1, 2, 4, 8 and so on, so 1101 means 8+4+0+1=13. To convert to decimal, add up the weights of the digits that are non-zero.

Going from decimal to another base needs two separate methods for the two parts of a number. For the integer part we divide by the base repeatedly and write the remainders from last to first, because the first remainder is the least significant digit. For the fraction we multiply by the base repeatedly and write the integer parts in the order they appear, because the first one is the most significant fractional digit. Many decimal fractions, such as 0.1, never terminate in binary. This is why floating-point arithmetic cannot store 0.1 exactly and why \(0.1+0.2\) is not exactly \(0.3\) on a computer.

Octal and hexadecimal exist because 8 and 16 are powers of 2, so conversion from binary needs no arithmetic, only grouping. Group in 3's for octal and 4's for hexadecimal, starting at the binary point and moving outwards. A common mistake is to group from the left of the number, which gives wrong results when the number of bits is not a multiple of the group size.
