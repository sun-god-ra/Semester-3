System Calls

Operating Systems · Unit I: Introduction and Operating System Structures

System Calls
Subject
Operating Systems (24CS204)
Unit
Unit I: Introduction and Operating System Structures
Topic
9 of 12
Terms
System call, POSIX, UNIX, JVM, Kernel, Shared memory, Message passing

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • System calls = interface to the services made available by the OS; written in C/C++, some low-level tasks in assembly
  • Example: copy the contents of one file to another file
    • acquire input file name → prompt → accept; acquire output file name; open the input file (if file doesn't exist → abort); create output file (if file exists → abort or delete); loop: read from input file, write to output file; close both files; write completion message to screen; terminate normally
  • API (Application Programming Interface) — programmers normally access system calls via an API, not directly. The three most common APIs: Windows API (Win32), POSIX API (UNIX, Linux, macOS), Java API (for the JVM). A function in the API invokes the actual system call. Why API instead of system calls directly? Portability, and APIs are simpler to use than the actual system calls (e.g. printf() in C library → write() system call; Windows API CreateProcess() → NTCreateProcess() kernel call)
  • System-call interface: the run-time environment (RTE) — full suite of software needed to execute applications written in a given language (compilers, interpreters, libraries, loaders) — provides a system-call interface that links to the system calls in the OS. A number is associated with each system call, the interface maintains a table indexed by these numbers; it invokes the intended system call in the OS kernel and returns the status and any return values. The caller need not know anything about how the system call is implemented
  • Passing parameters to the OS: (1) in registers (fastest; but maybe more parameters than registers); (2) in a block (table) in memory with the address of the block in a register (Linux, Solaris); (3) on the stack (pushed by the program, popped by the OS). Block and stack methods do not limit the number of parameters
Types of system calls
Type Examples
Process control create process (fork), terminate process (exit), load/execute (exec), end/abort, get/set process attributes, wait for time, wait event/signal event, allocate and free memory, debugger (single-step)
File management create file, delete file, open, close, read, write, reposition (lseek), get/set file attributes
Device management request device, release device, read, write, reposition, get/set device attributes, logically attach/detach devices
Information maintenance get/set time or date, get/set system data, get/set process, file or device attributes
Communications create/delete communication connection, send/receive messages, transfer status information, attach/detach remote devices (shared memory or message passing)
Protection get/set file permissions (chmod), allow/deny user access (umask, chown)

CreateProcess() fork()
ExitProcess() exit()
WaitForSingleObject() wait()
CreateFile() open()
ReadFile() read()
WriteFile() write()
CloseHandle() close()
SetFileSecurity() chmod()
Sleep() sleep()
  • Single-tasking (MS-DOS: command interpreter loads the program, runs it, memory freed on exit) vs multitasking (FreeBSD: shell uses fork() to create a new process and exec() to load the program, then wait() — or runs in background with &; on termination exit() returns status code: 0 = no error, nonzero = error)
Explanation

A system call is the entry point to the kernel's services. Even a simple task such as copying a file needs a series of calls: read the names, open the input file, create the output file, loop reading and writing, close both, and exit. Programmers do not use system calls directly but use an API such as POSIX, Windows API or Java API, because it is portable and easier. The run-time environment's system-call interface keeps a table indexed by the system-call number, calls the corresponding routine in the kernel and returns the status. The programmer needs to know only the API.

Parameters can be passed in registers (fast, but limited in number), in a block of memory whose address is in a register (Linux), or on the stack.

The six types of system calls are process control, file management, device management, information maintenance, communications, and protection. In UNIX fork() creates a process, exec() loads a new program into it, wait() waits for the child, and exit() ends it with a status code (0 means no error).
