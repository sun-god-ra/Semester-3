Notebook notes
  • OS is interrupt driven — if there are no processes to execute, no I/O devices to service and no users to respond, OS sits idle waiting for an event
  • Multiprogramming (batch) systems: keep several jobs in memory at once; when one job must wait (e.g., for I/O) the OS switches to another → CPU never idle, increasing CPU utilisation. Job pool on disk; job scheduling picks which jobs to load into memory
  • Multitasking (time-sharing) systems: extension of multiprogramming where the CPU switches among jobs so frequently that users can interact with each program while it is running → response time < 1 s. Each user has at least one program in memory = process; CPU scheduling; swapping; virtual memory
  • Dual-mode operation — to ensure that an incorrect program cannot cause other programs or the OS itself to execute incorrectly: hardware has a mode bit: kernel mode (0) — OS code, privileged instructions allowed; user mode (1) — user code. On interrupt/trap/system call, hardware switches to kernel mode; return from system call → user mode (set bit to 1)
    • Privileged instructions (only in kernel mode): I/O control, timer management, interrupt management, switching to kernel mode, modifying memory-management registers, halting
    • Attempt to execute a privileged instruction in user mode → hardware traps to OS
    • Modern CPUs: more than two modes (virtualisation: VMM mode; Intel rings 0–3)
  • Timer: to prevent a user program from getting stuck in an infinite loop or never returning control, a timer interrupts the computer after a specified period; OS sets the counter (privileged), decrements with the clock; when it reaches 0 → interrupt; so OS can regain control. Used to implement time sharing and compute the current time
  • Resource management: process management, memory management, file-system management, mass-storage management, cache management, I/O-system management
    • Process management: a process = program in execution (unit of work); program is a passive entity, process is active. OS activities: creating and deleting user and system processes; suspending and resuming; mechanisms for process synchronisation; process communication; deadlock handling
    • Memory management: keep track of which parts of memory are being used and by whom; decide which processes/data to move in and out; allocate and deallocate memory
    • File-system management: create/delete files and directories; primitives to manipulate them; map files onto secondary storage; back up files
    • Mass-storage management: free-space management, storage allocation, disk scheduling, partitioning; tertiary storage
    • I/O subsystem: memory-management component including buffering (storing data temporarily while it is being transferred), caching, spooling (overlapping output of one job with input of other jobs); general device-driver interface; drivers for specific hardware devices
  • Security and protection: protection = mechanism for controlling access of processes or users to resources defined by the OS; security = defence of the system against internal and external attacks (viruses, worms, DoS, identity theft). User IDs (UID), group IDs (GID); privilege escalation
Other kernel data structures
  • Lists, stacks, queues (singly/doubly/circular linked lists; stack LIFO; queue FIFO), trees (binary search tree, balanced e.g. Linux's red–black tree for CPU scheduling), hash functions and maps, bitmaps (string of n binary digits representing availability of n items)
Computing environments
  • Traditional (PCs, portals, network computers, thin clients); mobile (smartphones, tablets: GPS, accelerometer, gyroscope; augmented reality; Android, iOS); client–server (compute-server system and file-server system); peer-to-peer (P2P) — all nodes are peers; each can act as client or server; register with a centralised lookup service (Napster) or discovery protocol (Gnutella); cloud computing — computing, storage, even apps delivered as a service across a network: public, private, hybrid cloud; SaaS (software as a service), PaaS (platform as a service), IaaS (infrastructure as a service); real-time embedded systems (hard and soft real-time) — rigid time requirements on the operation of a processor or flow of data
Explanation

To keep the CPU busy, multiprogramming holds several jobs in memory. When one has to wait for I/O, the OS gives the CPU to another one. Multitasking, or time-sharing, extends this by switching so quickly that every user feels interactive.

Dual-mode operation is the basic protection. The hardware has a mode bit: 0 for kernel mode, 1 for user mode. Instructions that are dangerous, such as I/O instructions, changing the memory-management registers, or disabling interrupts, are privileged and can only be executed in kernel mode. When a user program tries to do it, the hardware traps to the OS. A system call is the legitimate way: it switches to kernel mode, the OS does the work, and then returns to user mode.

The timer ensures that a program cannot hold the CPU forever. The OS loads a counter, the counter decreases with the clock, and when it reaches zero, an interrupt returns control to the OS.

The OS manages several resources: processes (a process is a program in execution, which is an active entity, while a program is a passive file), memory, files, mass storage, and the I/O system, which includes buffering, caching and spooling. Protection controls the access of processes and users to resources, while security defends against attacks from inside and outside.

The other kernel data structures are lists, stacks and queues, trees (Linux uses a red-black tree in its scheduler), hash maps, and bitmaps. Computing environments include traditional, mobile, client-server, peer-to-peer, cloud (public, private, hybrid, with SaaS, PaaS and IaaS) and real-time embedded.
