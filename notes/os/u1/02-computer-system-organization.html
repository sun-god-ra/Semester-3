Operating Systems · Unit I: Introduction and Operating System Structures

Practice: Part B questions for Unit I and Part A short questions.

On this page
  1. Interrupts
  2. Storage structure
Notebook notes
  • One or more CPUs and device controllers connected through a common bus providing access to shared memory; CPU and devices compete for memory cycles (concurrent execution)
  • Device controller — in charge of one type of device (disk controller, USB controller); has local buffer storage and special-purpose registers. Device driver — OS component that understands the controller and gives the rest of the OS a uniform interface
  • Bootstrap program: the initial program run when the computer is powered up/rebooted; stored in ROM or EEPROM = firmware; initialises all aspects of the system (CPU registers, device controllers, memory contents) and then loads the OS kernel and starts executing it. Then the OS starts the first process (init) and waits for an event
Interrupts
  • Interrupt: a signal from hardware (device) or software that makes the CPU stop what it is doing, save the state, and transfer control to a fixed interrupt service routine (ISR)
  • Sequence: device controller raises an interrupt (via the bus) → CPU catches it and dispatches to ISR → ISR handles the device → CPU resumes the interrupted work (return from interrupt)
  • Interrupt vector = table of addresses of ISRs, indexed by device number, in low memory. The interrupt-handling routine saves the state (PC and registers) of the interrupted code
  • Software interrupt = trap or exception (error such as divide by zero, or a system call request by a user program)
  • I/O structure: synchronous I/O (control returns to the user program only after I/O completes — wait instruction/loop) vs asynchronous I/O (control returns without waiting; the OS keeps track of devices with a device-status table)
  • Interrupt-driven I/O is fine for small data but has high overhead for bulk transfers → Direct Memory Access (DMA): controller transfers a whole block between buffer and main memory without CPU intervention; only one interrupt per block instead of one per byte
  • Interrupt features of advanced systems: ability to defer during critical processing; efficient dispatch to the proper handler (vector); multilevel interrupts with priorities (maskable and nonmaskable (NMI) interrupts)
Storage structure
  • Main memory (RAM) — only large storage the CPU can access directly; volatile; usually DRAM
  • Secondary storage — extension of main memory; non-volatile: HDD, SSD/NVM
  • Storage hierarchy (speed ↓, size ↑, cost per bit ↓): registers → cache → main memory → solid-state disk (NVM) → hard disk → optical disk → magnetic tape. Above main memory = volatile; below = non-volatile
  • Caching — copying information into a faster storage on a temporary basis; check the cache first; if present (hit) use it, else (miss) get from lower level and copy into cache. Cache coherency problem in multiprocessor environments (cache coherency maintained by hardware). In the hierarchy each level acts as a cache for the level below it (registers cache the cache, cache caches main memory, main memory caches disk)
  • Von Neumann cycle: fetch instruction from memory → store in instruction register → decode → fetch operands → execute → store result
Explanation

A modern computer has one or more CPUs and several device controllers joined by a bus, all competing for access to memory. Each controller handles one type of device and has its own small buffer. The OS has a device driver for each controller that hides the details and gives a uniform interface.

When the power comes on, the bootstrap program stored in firmware (ROM/EEPROM) runs. It initialises the CPU registers, the controllers, and memory, then loads the kernel and starts it.

The OS is interrupt-driven. An interrupt is a signal that makes the CPU stop what it is doing, save its state, and jump to the interrupt service routine for that device. The address of every routine is kept in the interrupt vector, which is indexed by the device number. After the routine is done, the CPU goes back to the interrupted work. Interrupts from hardware are for devices. Software interrupts, called traps, come from errors (division by zero) or from system calls. For large transfers it would be a waste to interrupt the CPU for every byte, so DMA is used. The DMA controller moves a whole block between the device buffer and the memory and interrupts the CPU only once at the end.

Storage forms a hierarchy: registers, cache, main memory, then non-volatile devices such as SSD, HDD, optical disk and tape. As we go down, the capacity grows and the cost per bit and the speed fall. The idea of caching is to keep a copy of the frequently used data in the faster level. If it is found there, it is a hit; if not, it is a miss and data is brought from the lower level.
