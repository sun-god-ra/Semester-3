Operating-System Design and Implementation

Operating Systems · Unit I: Introduction and Operating System Structures

Operating-System Design and Implementation
Subject
Operating Systems (24CS204)
Unit
Unit I: Introduction and Operating System Structures
Topic
11 of 12
Terms
Kernel, Interrupt

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Design goals: user goals (convenient to use, easy to learn, reliable, safe, fast) and system goals (easy to design, implement, maintain; flexible, reliable, error-free, efficient). No unique solution
  • Mechanism vs policy: mechanism = how to do something (e.g. the timer construct for CPU protection); policy = what will be done (how long the timer is set for a particular user). Separation is important for flexibility — policies change over time or place; a general mechanism is better so only parameters change
  • Implementation: early OSes in assembly; now C/C++ (kernel in C, higher-level routines in C++); some low-level routines in assembly. Advantages of high-level languages: faster to write, more compact, easier to understand and debug, easier to port to other hardware. Disadvantages: reduced speed and increased storage (but modern compilers are good); major performance improvements come from better data structures and algorithms, not from assembly. Only small critical routines (interrupt handler, I/O manager, memory manager, CPU scheduler) need hand-tuning
Explanation

The goals are divided into user goals (easy, reliable, fast) and system goals (easy to design and maintain, efficient). A basic rule is to separate mechanism from policy. The mechanism is how something is done (a timer), the policy is what will be done (the timer value for a user). With a general mechanism, a change of policy needs only a change of parameters. Most OSes are in C and C++ because they are faster to write, compact, easy to debug and portable; only small critical routines are in assembly.
