Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Monolithic structure (simple) — the simplest structure: place all functionality of the kernel into a single static binary file running in a single address space. Fast (little overhead in system-call interface and communication within the kernel) but difficult to implement and extend. Original UNIX (two separable parts: the kernel — everything below the system-call interface and above the physical hardware, providing file system, CPU scheduling, memory management — and the system programs); Linux (also monolithic but modular); MS-DOS (written to provide the most functionality in the least space, not carefully divided into modules; interfaces and levels of functionality not well separated, application programs can access basic I/O routines → vulnerable to errant programs; Intel 8088 had no dual mode or hardware protection)
  • Layered approach — OS divided into a number of layers (levels); bottom layer (layer 0) is the hardware; highest layer (N) is the user interface; each layer uses only functions (operations) and services of lower-level layers. Advantage: simplicity of construction and debugging (verification layer by layer). Problems: defining layers carefully (a layer can use only lower ones — e.g. backing-store driver sits below memory manager); less efficient — each layer adds overhead (system call passes through many layers). Rarely used purely today; a few layers with more functionality, e.g. TCP/IP, THE system
  • Microkernels — move as much from the kernel into user space; Mach (Carnegie Mellon); kernel provides minimal process and memory management and communication facility (message passing between client program and the services running in user space). Benefits: easier to extend (new services added to user space; no kernel modification), easier to port the OS to new architectures, more reliable (less code in kernel mode), more secure. Drawback: performance overhead of user space to kernel space communication (Windows NT 4.0 moved layers back into kernel space and speed improved; Windows XP closer to monolithic). Examples: QNX (real-time; Mach-style message passing), Darwin (macOS kernel — hybrid of Mach microkernel + BSD)
  • Modules (loadable kernel modules, LKM) — best current methodology: kernel has a set of core components and links in additional services via modules, either at boot time or run time. Object-oriented approach: each core component is separate, talks to the others over known interfaces, loadable as needed within the kernel. Similar to layers but more flexible (any module can call any other) and similar to microkernel but more efficient (no message passing). Linux (core kernel + device drivers, file systems, scheduling classes as modules), Solaris
  • Hybrid systems — combine multiple approaches: Linux and Solaris — monolithic (performance) + modular (dynamic); Windows — monolithic with some microkernel behaviour (subsystems); macOS and iOS — layered Aqua UI over Cocoa (frameworks) over kernel environment (Mach microkernel + BSD UNIX kernel + I/O Kit + kernel extensions (kexts)); Android — Linux kernel modified, ART virtual machine, Java API, Bionic libc, HAL, libraries (SQLite, SSL, OpenGL)
Structure Idea Plus Minus Example
Monolithic everything in one kernel fast hard to extend, a bug can crash all UNIX, Linux
Layered layer n uses layer n−1 easy debugging overhead, layer design hard THE, TCP/IP
Microkernel minimal kernel, services in user space extensible, reliable message-passing overhead Mach, QNX
Modules core + loadable modules flexible, efficient — Linux, Solaris
Hybrid mix of above best of each complex Windows, macOS, Android
Building and booting an OS
  • System generation (SYSGEN) — configure an OS for a specific machine; collect hardware info (CPU, memory, devices, options). Booting = starting a computer by loading the kernel. Bootstrap program (in firmware) locates the kernel, loads it into memory and starts it. Two-step process on big systems: a small boot block at a fixed location loads the full bootstrap program from disk, then the kernel; GRUB is a common open-source bootstrap for Linux
  • Operating-system debugging: failure analysis — log files with error info; core dump (capture of process memory) and crash dump (kernel memory) written to a file for analysis; performance tuning — trace listings, profiling (periodic sampling of the instruction pointer), top, strace, DTrace (Solaris, FreeBSD, macOS), BCC/eBPF (Linux). Kernighan's law: "Debugging is twice as hard as writing the code in the first place."
Explanation

In a monolithic kernel, all services are in one binary in one address space: fast but hard to extend and debug. A layered OS has layers, each using only the one below it; this makes verification simple but adds overhead and makes defining layers difficult. A microkernel keeps only the minimum in the kernel (basic process and memory management and message passing) and moves other services to user space. It is easier to extend and more reliable, but the message passing between user space and the kernel slows it down. Modern systems use loadable kernel modules: a small core plus modules loaded at boot or run time, which is flexible and efficient. Practically every real OS is a hybrid: Linux is monolithic and modular, Windows is mostly monolithic with microkernel features, macOS combines the Mach microkernel and BSD, and Android is built on a Linux kernel with ART and its own libraries.

To start a system, the bootstrap program (in firmware) loads the kernel, often in two steps through a boot block, and GRUB is a common bootstrap on Linux. For debugging, the OS writes log files, core dumps of process memory and crash dumps of kernel memory, and tools such as DTrace, strace and profilers are used for performance tuning.
