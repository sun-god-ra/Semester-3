Disk Scheduling

Operating Systems · Unit V: Storage Management and File System

Disk Scheduling

Operating Systems (24CS204)
Unit
Unit V: Storage Management and File System
Topic
2 of 10
Terms
Starvation, C-SCAN, FCFS, Demand paging, Kernel, Virtual memory, RAID

Practice: Part B questions for Unit V and Part A short questions.

On this page
  1. FCFS (First-Come First-Served)
  2. SSTF (Shortest-Seek-Time-First)
  3. SCAN (Elevator algorithm)
  4. C-SCAN (Circular SCAN)
  5. LOOK and C-LOOK
Notebook notes
  • OS is responsible for using hardware efficiently — for disk drives, this means a fast access time and high disk bandwidth. Seek time ≈ seek distance. Disk bandwidth = total number of bytes transferred divided by the total time between the first request and the completion of the last transfer. Many sources of disk I/O requests: OS, system processes, user processes. An I/O request specifies: input or output, disk address, memory address, number of sectors. OS maintains a queue of requests per disk or device; with a busy disk, scheduling can improve performance; idle drive → serve immediately. Minimise seek time (since seek time dominates)
  • Example request queue (cylinders 0–199): 98, 183, 37, 122, 14, 124, 65, 67; head starts at 53
FCFS (First-Come First-Served)
  • Serves requests in order of arrival; fair but doesn't give the fastest service. Head movement: 53→98 (45) →183 (85) →37 (146) →122 (85) →14 (108) →124 (110) →65 (59) →67 (2) = 640 cylinders ("wild swing" from 122 to 14 and back to 124)
SSTF (Shortest-Seek-Time-First)
  • Select the request with the minimum seek time from the current head position; SJF-like, may cause starvation (a far request may wait forever as nearer ones keep arriving); not optimal. Order: 53→65 (12) →67 (2) →37 (30) →14 (23) →98 (84) →122 (24) →124 (2) →183 (59) = 236 cylinders
SCAN (Elevator algorithm)
  • The disk arm starts at one end of the disk and moves toward the other end, servicing requests as it reaches each cylinder, then reverses direction and continues (like an elevator). If a request arrives just in front of the head, it is serviced immediately; just behind it → waits for the head to come back. Need to know the direction of head movement. Example (moving toward 0 first): 53→37→14→0 then reverse →65→67→98→122→124→183: total = 53 + 183 = 236 cylinders. (Moving toward 199 first: (199−53) + (199−14) = 331.) Heavy density of requests at the other end after reversal (the cylinders just visited have fewer requests; the farthest end has waited longest)
C-SCAN (Circular SCAN)
  • More uniform wait time than SCAN: the head moves from one end to the other servicing requests; when it reaches the other end, it immediately returns to the beginning of the disk without servicing any requests on the return trip; treats the cylinders as a circular list that wraps around from the final cylinder to the first. Example (toward 199): 53→65→67→98→122→124→183→199 (146), jump 199→0 (199), 0→14→37 (37) = 146 + 199 + 37 = 382 cylinders (counting the return jump)
LOOK and C-LOOK
  • LOOK — a version of SCAN: the arm goes only as far as the last request in each direction, then reverses immediately without going to the end of the disk. Example (toward 0): 53→37→14, then →183: (53−14) + (183−14) = 208 cylinders. C-LOOK — version of C-SCAN: the arm goes only as far as the last request in one direction, then jumps to the first request at the other end and continues: 53→183 (130), jump to 14 (169), →37 (23) = 322 cylinders

FCFS 640 fair; wild swings
SSTF 236 may starve; greedy
SCAN 236 (toward 0 first) elevator; no starvation
C-SCAN 382 (with return jump) uniform wait
LOOK 208 goes only to last request
C-LOOK 322
  • Selection of a disk-scheduling algorithm: SSTF common, natural appeal; SCAN and C-SCAN perform better for systems that place a heavy load on the disk (less starvation, but starvation still possible with some variants); performance depends on the number and types of requests (file-allocation method and location of directories/index blocks influence it); the disk-scheduling algorithm should be a separate module of the OS (replaceable); default: SSTF or LOOK. Modern disks do their own scheduling using physical layout knowledge; OS also guarantees priorities (e.g., demand paging requests over application I/O, writes with order constraints); Linux has deadline, NOOP and CFQ schedulers — NOOP (FCFS with merging) is used for SSDs; NVM scheduling: FCFS with merging adjacent requests, since there is no seek time
  • Disk management: low-level (physical) formatting — dividing a disk into sectors that the controller can read and write; each sector has header, data area, trailer (ECC — error-correcting code). Partition the disk into one or more groups of cylinders, each treated as a logical disk; logical formatting — "making a file system" (store initial file-system data structures: maps of free and allocated space, an initial empty directory). Cluster (group of blocks) for efficiency; raw I/O (no file-system services) used by some apps (databases); boot block (bootstrap loader): ROM has a tiny bootstrap that loads the full bootstrap program from the boot block (the first sector; MBR — master boot record) of the boot partition, which loads the kernel. Bad blocks: sector sparing (forwarding) — controller replaces a bad sector logically with a spare sector; sector slipping; soft error vs hard error
  • Swap-space management: swap space — virtual memory uses disk space as an extension of main memory; raw partition or a file in the file system; swap space is less than the disk's file system — usually allocated in larger chunks, often contiguous, with a swap map. Linux: swap partitions or swap files; Solaris: swap space only for pages evicted, anonymous memory (stack, heap)
  • RAID structure: Redundant Arrays of Independent Disks — improve reliability via redundancy and performance via parallelism. Mean time to failure (MTTF) of a single disk, e.g. 100,000 h; with 100 disks, MTTF of some disk = 100,000/100 = 1,000 h (≈ 41.7 days) — so redundancy needed. Mean time to repair; mean time to data loss for a mirrored pair: MTTF²/(2 × MTTR) = \((100{,}000)^2/(2\times10)=5\times10^8\) h ≈ 57,000 years (with MTTR = 10 h). Mirroring (RAID 1): duplicate every disk — reliability, read speed-up (but writes to both). Striping: bit-level / block-level striping across several disks — parallelism for throughput. RAID levels: 0 (non-redundant block striping), 1 (mirrored disks), 2 (memory-style ECC), 3 (bit-interleaved parity, single parity disk), 4 (block-interleaved parity), 5 (block-interleaved distributed parity — parity spread across all disks; no bottleneck parity disk), 6 (P + Q redundancy, double parity — tolerates two disk failures), 0+1 and 1+0 (striping + mirroring — RAID 10 is better: a single disk failure only affects its mirror pair)
Explanation

For the request queue 98, 183, 37, 122, 14, 124, 65, 67, with the head at 53 on a disk of 200 cylinders:

  • FCFS serves requests in the order of arrival, and the head moves a total of 640 cylinders. It is fair, but there are wild swings.
  • SSTF always picks the nearest request. It moves 236 cylinders, but far requests can starve.
  • SCAN (elevator) moves to one end, serving requests on the way, and then reverses. Going towards 0 first, the total is 53 + 183 = 236. Going towards 199 first, it is 146 + 185 = 331.
  • C-SCAN moves in one direction only; at the end, it jumps back to the start without serving on the return, and gives a more uniform wait. The total is 146 + 199 + 37 = 382, counting the return jump.
  • LOOK and C-LOOK are like SCAN and C-SCAN, but the head goes only as far as the last request in the direction instead of to the end of the disk: LOOK is 208 and C-LOOK is 322.

SCAN and C-SCAN work better under heavy load because they avoid starvation, while SSTF or LOOK is a common default. For SSDs, there is no seek, so a simple FCFS (NOOP) with merging is enough.

Disk management includes low-level formatting (sectors with header, data and ECC), partitioning, and logical formatting (creating the file system), the boot block and MBR for booting, and bad-block handling by sector sparing. Swap space can be a raw partition or a file.

RAID combines disks for reliability and performance. Mirroring (RAID 1) keeps a copy of every disk. Striping spreads data over disks for speed. RAID 0 is striping only, RAID 4 uses block-level striping with a dedicated parity disk, RAID 5 spreads the parity over all disks so no disk becomes a bottleneck, RAID 6 has two parity blocks and tolerates two failures, and RAID 10 stripes over mirrors.
