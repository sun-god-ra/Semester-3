File Concept

Operating Systems · Unit V: Storage Management and File System

File Concept
Subject
Operating Systems (24CS204)
Unit
Unit V: Storage Management and File System
Topic
3 of 10
Terms
Inode, System call, UNIX, Internal fragmentation

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • File system = the part of the OS that provides the mechanism for online storage and access to both data and programs: collection of files (data) and a directory structure; partitions (for separate file systems). Files are mapped by the OS onto physical devices (nonvolatile)
  • File = named collection of related information recorded on secondary storage; smallest allotment of logical secondary storage (data cannot be written unless inside a file); types: data (numeric, character, binary), programs; contents defined by the file's creator (text file = sequence of characters organised into lines; source file = functions; executable file = series of code sections the loader can bring into memory)
  • File attributes (metadata): name (human-readable, the only attribute kept in human-readable form), identifier (unique tag, number — non-human-readable name — e.g. inode number), type (needed for systems that support different types), location (pointer to the device and the file location), size (current size, maybe maximum allowed), protection (access-control info: who can read, write, execute), time, date and user identification (creation, last modification, last use — for protection, security, usage monitoring). Information about files is kept in the directory structure (maintained on disk); a directory entry consists of the file's name and its unique identifier (the identifier locates the other attributes); may take more than a kilobyte per file. Extended attributes — file checksum, character encoding
  • File operations (OS provides system calls): create (find space; add an entry to the directory), write (write pointer at the location of the next write), read (read pointer / current-file-position pointer), reposition within file (seek), delete (release space, erase the directory entry), truncate (erase contents but keep attributes; file length reset to zero). Others: append, rename, copy
  • Open-file table: to avoid constant searching, open(Fi) searches the directory structure on disk for entry Fi and moves the content of the entry to memory; close(Fi) moves the content of entry Fi in memory back to the directory structure on disk. Per-process open-file table (pointer to the entry in the system-wide table, current file position pointer, access rights) and system-wide open-file table (open count, file attributes, location on disk; one entry per open file); information associated with an open file: file pointer (per process, last read/write location), file-open count (number of times the file is open; allows removal of the entry when the last process closes it), disk location of the file (cached to avoid reading from disk for each operation), access rights (per-process). Open-file locking — provided by some OS and file systems (like reader–writer locks): shared lock (several processes can acquire concurrently) vs exclusive lock (only one process); mandatory (access denied depending on locks held and requested) vs advisory (processes can find the lock status and decide what to do); Java FileChannel.lock(), Windows mandatory, UNIX advisory (flock()/fcntl())
  • File types: commonly implemented by including the type as part of the file name — name split into name + extension (e.g. .exe, .com, .bin = executable; .obj, .o = object; .c, .cc, .java, .py = source; .bat, .sh = batch/shell; .txt, .doc = text/word processor; .zip, .tar, .rar = archive; .jpg, .gif, .mp3, .mp4). UNIX uses a magic number stored at the beginning of some files to indicate roughly the type (the file type is not enforced by extension, only hints); macOS stores a creator attribute (the program that created it)
  • File structure: none (a sequence of words or bytes), simple record structure (lines; fixed length; variable length), complex structures (formatted document, relocatable load file). Can simulate the last two with the first by inserting appropriate control characters. Who decides? OS or the program. UNIX — a file is a sequence of bytes, no structure imposed (maximum flexibility); the OS must support at least one structure — an executable file (so it can load and run). Internal file structure: physical disk blocks (e.g. 512 bytes) vs logical records of varying length → packing several logical records into physical blocks; internal fragmentation in the last block
Explanation

A file is a named collection of related information stored on secondary storage, and it is the smallest unit of logical secondary storage. Its attributes are name, identifier, type, location, size, protection, and time, date and user. The attributes are stored in the directory structure. The operations are create, write, read, reposition (seek), delete and truncate, plus open and close. To avoid searching the directory for each operation, open() copies the file's entry into the open-file tables. There is a system-wide table (one entry per open file, with an open count) and a per-process table (a pointer to the system entry plus the current position). Files can be locked, with shared or exclusive locks, which can be mandatory or advisory (UNIX uses advisory).

Types are usually indicated by the extension. UNIX treats a file as a stream of bytes and uses a magic number at the start of some files as a hint.
