File-System Implementation — Structures and Operations

Operating Systems · Unit V: Storage Management and File System

File-System Implementation — Structures and Operations
Subject
Operating Systems (24CS204)
Unit
Unit V: Storage Management and File System
Topic
7 of 10
Terms
Inode, UNIX, Kernel, Hash table, Linked list

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • On-disk structures: boot control block (per volume; information needed to boot an OS from that volume; typically the first block of the volume; UFS: boot block; NTFS: partition boot sector); volume control block (per volume) (superblock in UFS, master file table (MFT) in NTFS): volume details — number of blocks in the partition, size of the blocks, free-block count and free-block pointers, free-FCB count and FCB pointers; directory structure per file system (file names and associated inode numbers in UFS; master file table in NTFS); per-file file-control block (FCB) — contains many details about the file: unique identifier (inode number), permissions, file size, dates (create, access, write), owner, group, ACL, file data blocks or pointers to the data blocks
  • In-memory structures (for file-system management and performance improvement via caching; loaded at mount time, updated during operations, discarded at dismount): in-memory mount table (info about each mounted volume), in-memory directory-structure cache (recently accessed directories; pointer to the volume table for directories at the mount point), system-wide open-file table (copy of the FCB of each open file + other info), per-process open-file table (pointer to the entry in the system-wide table + other info); buffers hold file-system blocks when they are being read from or written to a file system
  • Creating a new file: an application calls the logical file system, which knows the directory structure; it allocates a new FCB (if all FCBs were created at file-system creation time, allocate one from the free list); reads the appropriate directory into memory, updates it with the new file name and FCB, and writes it back to the disk
  • Opening a file (open()): the file name is passed to the logical file system; it searches the system-wide open-file table to see if the file is already in use by another process → if so, a per-process open-file table entry is created pointing to the existing system-wide entry (saves overhead); if not, search the directory structure for the file name (parts of the directory structure usually cached in memory to speed up directory operations), then copy the FCB into the system-wide open-file table in memory (it also tracks the number of processes that have the file open), then create a per-process open-file table entry with a pointer to the entry in the system-wide table (+ pointer to current location in the file + access mode). open() returns a pointer (index) to the appropriate entry in the per-process open-file table = file descriptor (UNIX), file handle (Windows); all file operations are performed via this pointer. The file name need not be part of the open-file table (once the FCB is located) but may be cached to speed up later opens
  • Closing a file (close()): the per-process table entry is removed, and the system-wide entry's open count is decremented; when all processes that have opened the file close it, any updated metadata is copied back to the disk-based directory structure and the system-wide open-file table entry is removed
  • Partitions and mounting: a disk can be sliced into multiple partitions, or a volume can span multiple partitions on multiple disks. Raw partition (no file system — e.g. UNIX swap space, some databases); cooked (with a file system). Boot information can be stored in a separate partition with its own format (since the system has no file-system code to interpret yet) — usually a sequential series of blocks loaded as an image into memory; dual-boot (boot loader that understands multiple file systems and multiple OSes; GRUB). Root partition (contains the OS kernel and sometimes other system files) is mounted at boot time; other volumes can be automatically mounted at boot or mounted manually later. At mount: the OS verifies the file system is valid — asks the device driver to read the device directory and verifies that the format is as expected; if not, consistency checking (fsck) is run and corrected if possible. Dismount — flushes
  • Virtual file systems (VFS): the OS needs to support multiple types of file systems at the same time → object-oriented techniques, with a VFS layer providing the same system-call interface (the API) for different file-system types; VFS dispatches the operation to the appropriate file-system implementation; layers: file-system interface (open(), read(), write(), close() and file descriptors) → VFS interface (separate the generic operations from implementation; a vnode — network-wide unique file representation (a numerical designator for a network-wide unique file; inode in UNIX is unique within a single file system) → local file system (type 1: ext4, type 2) or remote file system (NFS). Linux VFS object types: inode object (an individual file), file object (an open file), superblock object (an entire file system), dentry object (an individual directory entry)
  • Directory implementation: linear list of file names with pointers to the data blocks — simple to program but time-consuming to execute (linear search to find a file: create and delete need the search; a software cache or a sorted list with binary search helps; or a B+ tree: NTFS); hash table — linear list with a hash data structure (decreases directory search time; collisions — situations where two file names hash to the same location; fixed size of the hash table, and the hash function depends on it → chained-overflow hash table; entry = linked list)
Explanation

The file system is built in layers: I/O control (device drivers), basic file system (generic read/write of physical blocks, buffers), file-organisation module (logical to physical block mapping, free-space manager), logical file system (directory structure, metadata, the FCB or inode, protection) and the application programs. Layering reduces duplication but adds overhead.

On disk there are the boot control block, the volume control block (superblock), the directory structure, and an FCB for every file. In memory there are the mount table, the directory cache, the system-wide open-file table, the per-process open-file table and buffers. To create a file, a new FCB is allocated and the directory is updated. To open a file, the system looks in the system-wide table; if the file is already open, a per-process entry is added to point at it; if not, the directory is searched, the FCB is copied into the system-wide table and a per-process entry is created. open() returns an index into the per-process table, the file descriptor in UNIX. On close, the per-process entry is removed and the open count is decreased, and when it reaches zero the entry is removed and the updated metadata is written back.

The virtual file system (VFS) layer lets an OS support several file-system types with one system-call interface. The directory can be a linear list (simple but slow to search), or a hash table (faster, but collisions and fixed size are problems).
