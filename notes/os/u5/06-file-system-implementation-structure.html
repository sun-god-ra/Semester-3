File-System Implementation — Structure

Operating Systems · Unit V: Storage Management and File System

File-System Implementation — Structure
Subject
Operating Systems (24CS204)
Unit
Unit V: Storage Management and File System
Topic
6 of 10
Terms
Interrupt, Inode, UNIX, Hash table

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • File system resides on secondary storage (disks): provides efficient and convenient access to the disk by allowing data to be stored, located and retrieved easily. File-system design problems: defining how the file system should look to the user (file, attributes, operations, directory structure) and creating algorithms and data structures to map the logical file system onto the physical secondary-storage devices. Disk characteristics: it can be rewritten in place (read a block, modify, write back to the same place); can directly access any block of information (random access) → easy to sequentially or randomly access any file
  • Layered file system:
    1. I/O control — device drivers and interrupt handlers that transfer information between the main memory and the disk system (input: "retrieve block 123" → hardware-specific low-level instructions that tell the controller which bit locations to use)
    2. Basic file system — issues generic commands to the appropriate device driver to read and write physical blocks on the disk (identified by drive number, cylinder, track, sector); also manages memory buffers and caches (allocation, freeing, replacement of buffers holding file-system, directory and data blocks)
    3. File-organisation module — knows files and their logical blocks and physical blocks; translates logical block addresses to physical block addresses; includes the free-space manager (tracks unallocated blocks)
    4. Logical file system — manages metadata information (everything about the file system except the actual data): directory structure to give the file-organisation module the information it needs given a symbolic file name; file-control block (FCB) (inode in UNIX) — maintains file structure; also protection
    5. Application programs - Code reuse: layering minimises duplication of code — the I/O control and sometimes the basic file-system code can be used by multiple file systems, each defining its own logical file system and file-organisation modules; disadvantage: layering can introduce more OS overhead. Many file systems in use: ISO 9660 (CD-ROM), UNIX file system (UFS) (Berkeley Fast File System, FFS), FAT, FAT32, NTFS (Windows), ext2, ext3, ext4 (Linux), Z file system (ZFS), APFS (Apple), HFS+, network file systems (NFS)
Explanation

The file system is built in layers: I/O control (device drivers), basic file system (generic read/write of physical blocks, buffers), file-organisation module (logical to physical block mapping, free-space manager), logical file system (directory structure, metadata, the FCB or inode, protection) and the application programs. Layering reduces duplication but adds overhead.

On disk there are the boot control block, the volume control block (superblock), the directory structure, and an FCB for every file. In memory there are the mount table, the directory cache, the system-wide open-file table, the per-process open-file table and buffers. To create a file, a new FCB is allocated and the directory is updated. To open a file, the system looks in the system-wide table; if the file is already open, a per-process entry is added to point at it; if not, the directory is searched, the FCB is copied into the system-wide table and a per-process entry is created. open() returns an index into the per-process table, the file descriptor in UNIX. On close, the per-process entry is removed and the open count is decreased, and when it reaches zero the entry is removed and the updated metadata is written back.

The virtual file system (VFS) layer lets an OS support several file-system types with one system-call interface. The directory can be a linear list (simple but slow to search), or a hash table (faster, but collisions and fixed size are problems).
