Directory Structure

Operating Systems · Unit V: Storage Management and File System

Directory Structure
Subject
Operating Systems (24CS204)
Unit
Unit V: Storage Management and File System
Topic
5 of 10
Terms
RAID, UNIX, Inode, Garbage collection

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • A collection of nodes containing information about all files; both the directory structure and the files reside on disk. Disk structure: a disk can be subdivided into partitions; disks or partitions can be RAID protected; partition: also called minidisks or volumes; each containing a file system (raw partitions without one); entity containing a file system = a volume; each volume tracks the file-system info in a device directory (volume table of contents); device directory records information such as name, location, size, type of all files on the partition. Operations performed on a directory: search for a file, create a file, delete a file, list a directory, rename a file, traverse the file system. Goals: efficiency (locating a file quickly), naming (convenient to users: two users can have the same name for different files, the same file can have several different names), grouping (logical grouping of files by properties, e.g. all Java programs)
  • Single-level directory: a single directory for all users; naming problem (all files must have unique names; with many users, hard to remember), grouping problem. Simple
  • Two-level directory: a separate directory for each user: master file directory (MFD) and user file directory (UFD); path name (user name + file name); can have the same file name for different users; efficient searching; no grouping capability; isolation of users (protection) but hard to share/cooperate; system files: a special user directory for the system programs (search path: the sequence of directories searched when a command is given)
  • Tree-structured directories: extension of the two-level into a tree of arbitrary height; the most common. Root directory; every file has a unique path name; a directory is simply another file with a bit defining it as a directory; efficient searching; grouping capability; current directory (working directory). Absolute path name (begins at the root) vs relative path name (from the current directory). Creating a new file is done in the current directory; creating a new subdirectory in the current directory (mkdir). Deleting a directory: if empty, simply delete; if not empty: option 1 — do not delete unless empty (MS-DOS), option 2 — delete all its files and subdirectories (UNIX rm -r). Efficient searching
  • Acyclic-graph directories: allow directories to share subdirectories and files — the same file may be in two different directories (a shared file rather than a copy: changes by one user visible to the other). Implemented via links (a link is a pointer to another file or subdirectory; UNIX symbolic link = file containing a path name; hard link = another directory entry pointing to the same inode, with a reference count) or by duplicating the entries (copy; consistency problem). Problems: a file may have multiple absolute path names (aliasing — when traversing for a total, a shared structure counted twice); deletion — when can the space be deallocated? dangling pointers; solutions: backpointers (list of all references, variable-size), entry-hold-count (reference count) solution — a reference count: when it reaches zero, the file can be deleted; symbolic links are left dangling. UNIX uses a link count in the inode (ln, ln -s)
  • General graph directory: allows cycles (when links are added to an ordinary tree). Problems: avoid traversing shared sections twice → algorithms to avoid infinite loops; deleting — reference count may not be zero even when it's no longer possible to refer to the directory or file (a self-referencing cycle) → garbage collection (traverse the whole file system, mark everything that can be accessed, then collect the unmarked — time-consuming). Easier: allow only links to files, not subdirectories, and ensure no cycles when a new link is added (cycle-detection algorithms — expensive)
  • Protection — see later; mounting: a file system must be mounted before it can be accessed. Mount point — the location within the file structure where the file system is attached (an empty directory); the OS verifies the device contains a valid file system (asking the device driver to read the device directory); unmounted file system (i.e., partition not yet mounted) can be mounted at a mount point (UNIX mount; Windows assigns drive letters). Mounting can hide existing files in the mount point
Explanation

A single-level directory has the problem that all file names must be unique. A two-level directory gives each user a directory, so the same name can be used by different users, but there is no grouping. A tree-structured directory is the most common: every file has a unique path name, absolute from the root or relative to the current directory. An acyclic-graph directory allows sharing of files through links; a symbolic link holds the path, a hard link is another directory entry pointing to the same inode and a reference count tells when the file can be deleted. A general graph allows cycles, which complicates the traversal and deletion, so garbage collection or restrictions on links are needed.

A file system must be mounted before use, at a mount point, which is an empty directory.
