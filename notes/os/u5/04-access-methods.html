Access Methods

Operating Systems · Unit V: Storage Management and File System

Access Methods
Subject
Operating Systems (24CS204)
Unit
Unit V: Storage Management and File System
Topic
4 of 10

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • Sequential access: information in the file is processed in order, one record after the other — most common (editors, compilers). Operations: read_next() — read the next portion and advance the file pointer; write_next() — append to the end and advance to the end of newly written material (new end of file); reset (rewind to the beginning); (on some systems skip forward or backward n records). Based on a tape model of a file; works on sequential-access devices as well as random-access ones
  • Direct access (relative access): a file is made of fixed-length logical records that allow programs to read and write records rapidly in no particular order; based on a disk model (a disk allows random access to any file block). Operations use the relative block number n (an index relative to the beginning of the file; the first relative block is 0): read(n), write(n), position_file(n) then read_next(), write_next() (some systems). The OS translates the relative block number into an absolute disk address; useful for immediate access to large amounts of information (databases, airline reservation system — block for flight 713 holds its information). Simulate sequential access on a direct-access file: keep a counter cp (current position): read_next → read(cp); cp = cp + 1; write_next → write(cp); cp = cp + 1; the reverse (direct on sequential) is inefficient
  • Other access methods — Indexed (index-sequential) — built on top of direct access: construct an index for the file (a pointer to various blocks — like an index in the back of a book); to find a record: search the index to find the pointer, then use the pointer to access the file directly. Large files → index is too large to keep in memory → create an index for the index file (multilevel index; primary index pointing to secondary index files, which point to the actual data items). IBM's indexed sequential access method (ISAM): a small master index points to disk blocks of a secondary index; the file is kept sorted on a defined key; binary search to find the entry. VMS index and relative files
Explanation

Sequential access processes the records one after another, with read_next, write_next and reset. Direct access treats the file as numbered fixed-length blocks, which can be read in any order using read(n), where n is the relative block number counted from 0. Sequential access is easy to simulate on direct access, using a counter. Indexed access builds an index (like the index of a book) and a multilevel index for big files, as ISAM does.
