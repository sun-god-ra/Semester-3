Demand Paging

Operating Systems · Unit IV: Memory Management

Demand Paging
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
8 of 12
Terms
Paging, Swapping, Page fault, Page table, Demand paging, Interrupt, Virtual memory, Copy-on-write

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Bring a page into memory only when it is needed → less I/O, less memory, faster response, more users (like paging system with swapping; lazy swapper — never swaps a page into memory unless that page will be needed; a swapper that deals with pages is a pager). Page is needed ⇒ reference to it: invalid reference ⇒ abort; not-in-memory ⇒ bring to memory
  • Valid–invalid bit with each page-table entry: v ⇒ in memory (memory resident); i ⇒ not in memory (or illegal). Initially valid–invalid bit is i on all entries. During MMU address translation, if the bit is i ⇒ page fault
  • Page fault — first reference to a page not in memory traps to the OS. Steps in handling a page fault
    1. Reference → trap to the OS (internal table in the PCB: is the reference valid or invalid?)
    2. If invalid → terminate the process; if valid but not yet in memory → page it in
    3. Find a free frame (from the free-frame list)
    4. Schedule a disk operation to read the desired page into the newly allocated frame
    5. When the read is complete, modify the internal table (PCB) and the page table (valid bit = v)
    6. Restart the instruction that caused the page fault (the process continues as though the page had always been in memory)
  • Extreme case — pure demand paging: start a process with no pages in memory; the OS sets the instruction pointer to the first instruction, which is not memory resident → page fault; and so on for every other first-time page. Locality of reference (programs tend to have locality) → reasonable performance. Hardware support needed: page table with valid/invalid bit, secondary memory (swap device with swap space), instruction restart
  • Instruction restart: a critical problem — when the fault occurs in the middle of an instruction (e.g., a block move with overlapping source and destination; auto-increment/decrement addressing) must be able to restart: solutions — access both ends of the block before moving, or use temporary registers to hold the values of overwritten locations
  • Free-frame list: a pool of free frames for satisfying page-fault requests; OS typically allocates free frames using zero-fill-on-demand (content of the frames zeroed out before allocation)
  • Performance of demand paging: page-fault rate \(p\), \(0\le p\le 1\): \(p=0\) → no page faults; \(p=1\) → every reference is a fault

\[\text{EAT}=(1-p)\times\text{memory access}+p\times\text{page-fault time}\]

  • Page-fault service time includes: trap to OS; save registers and process state; determine that the interrupt was a page fault; check page reference legality and find the page on disk; issue a disk read to a free frame (wait in queue, wait for seek/latency, transfer); while waiting, allocate the CPU to another process; receive interrupt from disk I/O subsystem; save registers/state of the other process; determine the interrupt was from disk; correct the page table; wait for the CPU to be allocated again; restore registers, process state, new page table → resume
    • Three major activities: service the interrupt (careful coding: several hundred instructions), read the page (lots of time), restart the process (small)
    • Example: memory access time = 200 ns; average page-fault service time = 8 ms = 8,000,000 ns: EAT \(=(1-p)\times200+p\times8{,}000{,}000=200+7{,}999{,}800\,p\) ns. If one access out of 1,000 causes a page fault (\(p=0.001\)): EAT \(=200+7{,}999.8=\) 8,199.8 ns ≈ 8.2 µs → slowdown by a factor of 40! For performance degradation < 10 %: \(220>200+7{,}999{,}800p\Rightarrow p<2.5\times10^{-6}\) → fewer than one page fault in 400,000 accesses
    • Swap space: I/O to swap space (contiguous, larger chunks) is faster than to the file system; options: copy the entire file image to swap space at process start, then page from swap; or demand page from the program binary on disk but discard rather than paging out when freeing a frame (read-only code); anonymous memory (stack, heap — not backed by a file) uses swap. Mobile systems typically don't support swapping and demand-page from the file system
Explanation

Virtual memory separates the logical memory from physical memory, so a program can be larger than the physical memory. Only part of the program need be in memory, because much of it is rarely used. The virtual address space may have a hole between the heap and the stack.

In demand paging, a page is brought in only when it is needed. Each page-table entry has a valid-invalid bit, where valid means the page is in memory. A reference to a page that is not in memory causes a page fault. The OS checks whether the reference was valid, finds a free frame, reads the page from disk, updates the page table, and restarts the instruction. In pure demand paging the process starts with no page in memory. Instruction restart needs care for instructions like block moves.

With page-fault rate \(p\), the effective access time is \((1-p)\times\) memory access \(+\,p\times\) fault service time. If the memory access is 200 ns and the fault service is 8 ms, EAT = 200 + 7,999,800p ns. For p = 0.001 this is about 8.2 µs, a slowdown of 40 times. To lose less than 10%, p must be below \(2.5\times10^{-6}\), that is, fewer than one fault in 400,000 accesses.

Copy-on-write lets the parent and child share all pages after fork(), and a page is copied only when one of them writes to it. Memory-mapped files map a file into the address space, so file I/O becomes ordinary memory access.
