Virtual Memory — Background

Operating Systems · Unit IV: Memory Management

Virtual Memory — Background
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
7 of 12
Terms
Virtual memory, Shared memory, Demand paging, Page fault, Page table, Copy-on-write

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Virtual memory — separation of user logical memory from physical memory: only part of the program needs to be in memory for execution; therefore the logical address space can be much larger than the physical address space; allows address spaces to be shared by several processes; allows more efficient process creation; more programs running concurrently; less I/O needed to load or swap processes. Virtual address space = logical view of how a process is stored in memory — usually starts at address 0, contiguous addresses until the end of the space, while the physical memory is organised in page frames and the MMU maps logical to physical
  • Why is the entire program not needed at once? Error-handling code rarely executed; arrays, lists, tables often allocated more memory than they need; options and features of a program rarely used. Benefits: a program no longer constrained by the limits of physical memory; each program takes less memory while running → more programs at once → increased CPU utilisation and throughput with no increase in response or turnaround time
  • Sparse address space: virtual address spaces that include holes between the heap and stack (which grow), filled when a stack/heap grows or when dynamically linked libraries are loaded. System libraries shared via mapping into virtual address space; shared memory by mapping pages read–write into virtual address space; pages can be shared during fork(), speeding process creation
Explanation

Virtual memory separates the logical memory from physical memory, so a program can be larger than the physical memory. Only part of the program need be in memory, because much of it is rarely used. The virtual address space may have a hole between the heap and the stack.

In demand paging, a page is brought in only when it is needed. Each page-table entry has a valid-invalid bit, where valid means the page is in memory. A reference to a page that is not in memory causes a page fault. The OS checks whether the reference was valid, finds a free frame, reads the page from disk, updates the page table, and restarts the instruction. In pure demand paging the process starts with no page in memory. Instruction restart needs care for instructions like block moves.

With page-fault rate \(p\), the effective access time is \((1-p)\times\) memory access \(+\,p\times\) fault service time. If the memory access is 200 ns and the fault service is 8 ms, EAT = 200 + 7,999,800p ns. For p = 0.001 this is about 8.2 µs, a slowdown of 40 times. To lose less than 10%, p must be below \(2.5\times10^{-6}\), that is, fewer than one fault in 400,000 accesses.

Copy-on-write lets the parent and child share all pages after fork(), and a page is copied only when one of them writes to it. Memory-mapped files map a file into the address space, so file I/O becomes ordinary memory access.
