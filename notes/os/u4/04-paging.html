Paging

Operating Systems · Unit IV: Memory Management

Paging
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
4 of 12
Terms
External fragmentation, Page table, Internal fragmentation, Paging, TLB, Round robin, LRU, Kernel, Context switch

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Physical address space of a process can be noncontiguous; the process is allocated physical memory whenever the latter is available. Avoids external fragmentation and the problem of varying-sized memory chunks
  • Method: divide physical memory into fixed-sized blocks called frames (size is a power of 2, between 512 bytes and 16 MB); divide logical memory into blocks of the same size called pages. Keep track of all free frames. To run a program of n pages, find n free frames and load the program. Set up a page table to translate logical to physical addresses. Backing store is also split into fixed-sized blocks. Still have internal fragmentation
  • Address translation scheme: the address generated by the CPU is divided into page number (p) — used as an index into a page table which contains the base address (frame number) of each page in physical memory; and page offset (d) — combined with the base address to define the physical memory address sent to the memory unit

\[\text{logical address of }m\text{ bits}=\underbrace{p}_{m-n\text{ bits}}\;\underbrace{d}_{n\text{ bits}},\qquad \text{page size}=2^{n},\ \text{number of pages}=2^{m-n}\]

\[\text{physical address}=(\text{frame number})\times(\text{page size})+d\]

  • Example (tiny): logical address space 16 bytes (m = 4), page size 4 bytes (n = 2) → 4 pages; physical memory 32 bytes = 8 frames. Page table: page 0 → frame 5, page 1 → frame 6, page 2 → frame 1, page 3 → frame 2. Logical address 0 (page 0, offset 0) → frame 5 × 4 + 0 = 20; logical 3 (p0, d3) → 5×4+3 = 23; logical 4 (p1, d0) → 6×4+0 = 24; logical 13 (p3, d1) → 2×4+1 = 9
  • Internal fragmentation: process size need not be a multiple of the page size — last frame may not be completely full. Worst case: 1 frame − 1 byte; average internal fragmentation ≈ ½ frame per process. Tradeoff: small frames reduce fragmentation but increase the page table size; frames have grown larger as memory and data sets grow. Example: page size 2,048 bytes, process 72,766 bytes = 35 pages + 1,086 bytes → needs 36 frames; internal fragmentation = 2,048 − 1,086 = 962 bytes
  • Free frame list: OS must be aware of the allocation details of physical memory: which frames are allocated, which are available, total number of frames — kept in a frame table (one entry per physical frame: free or allocated, and to which page of which process). The OS maintains a copy of the page table for each process (used by the dispatcher to define the hardware page table when the process is allocated the CPU) → paging increases context-switch time
  • Implementation of page table
    • The page table is kept in main memory; page-table base register (PTBR) points to the page table; page-table length register (PTLR) indicates the size of the page table. In this scheme every data/instruction access requires two memory accesses (one for the page table and one for the data/instruction) → slow
    • The two-memory-access problem can be solved by the use of a special fast-lookup hardware cache: associative memory / translation look-aside buffer (TLB) — small (32–1024 entries), fast; each entry has two parts: a key (tag) and a value; the item being searched for is compared with all keys simultaneously; if found, the value is returned. TLB miss → page number looked up in the page table in memory; the entry is then added to the TLB (replacement policies: LRU, round robin, random); some entries can be wired down (kernel code). Some TLBs store address-space identifiers (ASIDs) in each entry — uniquely identify each process to provide address-space protection for that process and allow entries for several processes to coexist in the TLB (otherwise TLB must be flushed at every context switch)
    • Effective Access Time (EAT): let hit ratio α = percentage of times the page number is found in the TLB; ε = TLB lookup time; memory access time = m (here 100 ns)

\[\text{EAT}=\alpha\,(\varepsilon+m)+(1-\alpha)\,(\varepsilon+2m)\]

  • Example: \(\alpha=80\%\), \(\varepsilon=20\) ns, \(m=100\) ns: EAT \(=0.80(20+100)+0.20(20+200)=96+44=\) 140 ns (40 % slowdown over 100 ns). For \(\alpha=99\%\): EAT \(=0.99\times120+0.01\times220=118.8+2.2=\) 121 ns (21 % slowdown)
  • Memory protection in paging: a protection bit with each frame (read-only / read-write / execute-only); a valid–invalid bit attached to each entry in the page table: "valid" = the associated page is in the process's logical address space, so a legal page; "invalid" = the page is not in the process's logical address space → trap. Or use PTLR. Some pages inside the page table range may be unused; internal fragmentation in addressing: because of the page granularity, process may reference addresses past its end up to the page boundary (still marked valid) — only the PTLR/valid bits catch pages beyond
  • Shared pages: paging allows sharing common code — reentrant (pure) code: non-self-modifying code, never changes during execution. One copy of read-only (reentrant) code shared among processes (text editors, compilers, window systems); each process has its own copy of registers and data storage; the shared code must appear in the same logical location in the address space of all processes. Example: 40 users each running a text editor of 150 KB code + 50 KB data: without sharing = 40 × 200 KB = 8000 KB; with sharing = 150 + 40 × 50 = 2150 KB. Private code and data can appear anywhere in the logical address space
Explanation

Paging cuts the physical memory into fixed-size frames and the logical memory into pages of the same size. The page table gives for each page the frame holding it, so the process can be spread over any free frames, with no external fragmentation. A logical address is split into the page number p and the offset d. The frame number is found from the page table, and the physical address is frame × page size + d. With 4-byte pages and the table 0→5, 1→6, 2→1, 3→2, logical address 13 is page 3 offset 1, so the physical address is 2×4+1 = 9.

There is some internal fragmentation, on average half a page per process. A 72,766-byte process with 2,048-byte pages needs 36 frames and wastes 962 bytes.

Since the page table is in memory, each access needs two memory accesses. The TLB is a small, fast associative cache of page-table entries, searched in parallel. The effective access time is \(\alpha(\varepsilon+m)+(1-\alpha)(\varepsilon+2m)\). With an 80% hit ratio, 20 ns TLB search and 100 ns memory it is 140 ns; at 99% it is 121 ns. ASIDs in the TLB entries let it hold entries of several processes, so it need not be flushed at every context switch.

Protection comes from the protection bits (read-only, read-write) and the valid-invalid bit of each page-table entry. Reentrant (never self-modifying) code can be shared by processes. For 40 users of a 150 KB editor with 50 KB of private data each, sharing needs 150 + 40×50 = 2,150 KB instead of 8,000 KB.
