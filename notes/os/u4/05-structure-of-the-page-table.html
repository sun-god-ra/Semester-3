Structure of the Page Table

Operating Systems · Unit IV: Memory Management

Structure of the Page Table
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
5 of 12
Terms
Paging, Page table, TLB, Hash table, Shared memory, Kernel

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Problem: memory structures for paging can get huge using straightforward methods. Consider a 32-bit logical address space and page size 4 KB (2¹²): page table would have 2²⁰ = 1,048,576 entries; if each entry is 4 bytes → 4 MB of physical memory for the page table alone per process — don't allocate it contiguously in main memory. Solutions: hierarchical paging, hashed page tables, inverted page tables
  • Hierarchical (multilevel) paging: break up the logical address space into multiple page tables; a simple technique is a two-level page table (the page table itself is paged). Two-level paging example: 32-bit address, 4 KB page: a logical address is divided into a 20-bit page number and a 12-bit page offset; since the page table is paged, the page number is further divided into a 10-bit outer page number \(p_1\) and a 10-bit inner page offset \(p_2\) → \(p_1\) (10) | \(p_2\) (10) | \(d\) (12); \(p_1\) is an index into the outer page table, \(p_2\) is the displacement within the page of the inner page table. Known as a forward-mapped page table. Address translation: outer table → inner table → frame + offset (3 memory accesses without a TLB). Pentium-style 32-bit. For 64-bit: a two-level scheme is not appropriate (e.g., 4 KB pages → \(2^{52}\) entries; outer table too large) → three-level, four-level paging; ARM uses 1–4 levels (4 KB/16 KB/1 MB/16 MB pages); x86-64 uses 48-bit addresses with 4-level paging (9+9+9+9+12)
  • Hashed page tables: common in address spaces > 32 bits; the virtual page number is hashed into a page table; each entry has a chain of elements hashing to the same location (collisions) — each element has (1) virtual page number, (2) value of the mapped page frame, (3) pointer to the next element; virtual page numbers are compared along the chain; if a match → the frame is extracted. Clustered page tables: each entry refers to several pages (e.g., 16) — good for sparse address spaces with non-contiguous references
  • Inverted page table: rather than each process having a page table and tracking all possible logical pages, track all physical pages: one entry for each real page (frame) of memory; the entry consists of the virtual address of the page stored in that real memory location, with information about the process that owns the page (<process-id, page-number> plus offset). Decreases memory needed to store each page table, but increases time needed to search the table when a page reference occurs. Use a hash table to limit the search to one or at most a few page-table entries (TLB can accelerate). Difficulty with shared memory (only one virtual page mapped per physical frame → a shared page needs one mapping at a time). Used in 64-bit UltraSPARC, PowerPC
  • Oracle SPARC Solaris (example): 64-bit, two hash tables (kernel, user); each entry is a TSB (translation storage buffer); TLB holds translation table entries (TTEs)
  • ARM architecture: 4 KB and 16 KB pages, 1 MB and 16 MB sections; one-level paging for sections, two-level for smaller pages; two levels of TLBs (micro TLBs per core, main TLB)
Explanation

With a 32-bit address and 4 KB pages, a page table has \(2^{20}\) entries, 4 MB if each entry is 4 bytes, so it cannot be kept in one contiguous area for every process. Hierarchical paging pages the page table itself. With two levels, the 32-bit address is split 10-10-12 (outer index, inner index, offset). For 64-bit addresses more levels are needed (x86-64 uses four, 9+9+9+9+12). A hashed page table hashes the virtual page number into a table of chains. The inverted page table has one entry for each physical frame, giving the process and page that owns it, so the table is small but the search takes longer, and a hash table is used to speed this up. Sharing is difficult with it.
