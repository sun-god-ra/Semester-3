Page Replacement

Operating Systems · Unit IV: Memory Management

Page Replacement
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
10 of 12
Terms
Kernel, Page fault, Belady's anomaly, LRU, Page table, Linked list, Interrupt, Virtual memory, Paging

Practice: Part B questions for Unit IV and Part A short questions.

On this page
  1. FIFO page replacement
  2. Optimal page replacement (OPT / MIN)
  3. LRU (Least Recently Used) page replacement
Notebook notes
  • What happens if there is no free frame? Memory is over-allocated (used up by process pages, buffers for I/O, kernel). Page replacement — find some page in memory that is not really in use and page it out: needs an algorithm with minimal number of page faults; the same page may be brought into memory several times. Prevent over-allocation of memory by modifying the page-fault service routine to include page replacement
  • Basic page replacement
    1. Find the location of the desired page on disk
    2. Find a free frame: if there is a free frame, use it; if there is no free frame, use a page-replacement algorithm to select a victim frame; write the victim frame to disk (if modified), change the page and frame tables
    3. Read the desired page into the (newly) free frame; update the page and frame tables
    4. Continue the process by restarting the instruction - Modify (dirty) bit — to reduce overhead of page transfers: only modified pages are written to disk (if the page is not modified, no write is needed — cuts I/O in half); also read-only pages (code) are never written
  • Two major problems: frame-allocation algorithm (how many frames to give each process) and page-replacement algorithm (which frames to replace). Want the lowest page-fault rate on both first access and re-access. Evaluate by running on a particular string of memory references (reference string) and computing the number of page faults; the reference string is given as page numbers (not full addresses — consecutive references to the same page produce no further faults)
  • Page faults vs number of frames: as the number of frames increases, the number of page faults should decrease (the curve falls)
FIFO page replacement
  • Replace the oldest page (the one that was brought in earliest); keep a FIFO queue. Easy to implement. Reference string: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1, 7, 0, 1 — 3 frames
Ref 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1
Fault? F F F F – F F F F F F – – F F – – F F F
  • 15 page faults (FIFO). Belady's anomaly — for some algorithms, page-fault rate may increase as the number of allocated frames increases. Example reference string 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5: 3 frames → 9 page faults; 4 frames → 10 page faults (FIFO). Anomaly affects FIFO; stack algorithms (LRU, optimal) never suffer from it (the set of pages in memory with n frames is always a subset of the set with n+1 frames)
Optimal page replacement (OPT / MIN)
  • Replace the page that will not be used for the longest period of time — lowest page-fault rate of all algorithms; never suffers from Belady's anomaly. Impossible to implement since it needs future knowledge of the reference string; used for comparison (how close another algorithm is to optimal). Same string, 3 frames → 9 page faults (6 fewer than FIFO)
LRU (Least Recently Used) page replacement
  • Replace the page that has not been used for the longest period of time — uses past knowledge as an approximation of the future (looking backward); associate time of last use with each page. Generally good and frequently used. Same string, 3 frames → 12 page faults (better than FIFO's 15, worse than optimal's 9)
  • Implementation: needs hardware assistance. Counter implementation: every page-table entry has a time-of-use field; CPU clock/counter is copied into it at every reference; replace the page with the smallest time value (search of page table needed; clock overflow). Stack implementation: keep a stack of page numbers as a doubly linked list: when a page is referenced, move it to the top (requires up to 6 pointers to be changed); no search for replacement (the bottom is the LRU page). Updating on every memory reference must be done in hardware (otherwise slows every reference by a factor of at least 10)
  • LRU-approximation algorithms (few systems give full LRU hardware support)
    • Reference bit: with each page associate a bit, initially 0; when the page is referenced, the bit is set to 1 by hardware; replace any page with reference bit = 0 (if one exists) — order of use unknown
    • Additional-reference-bits algorithm: keep an 8-bit byte for each page in a table in memory; at regular intervals (e.g. every 100 ms) a timer interrupt shifts the reference bit into the high-order bit of the byte (shifting the others right, discarding the low bit): the byte holds the history of page use for the last 8 periods; page with the lowest unsigned value is the LRU page (e.g. 11000100 used more recently than 01110111)
    • Second-chance (clock) algorithm: FIFO with a reference bit; if page to be replaced has reference bit = 0 → replace it; if reference bit = 1 → set the bit to 0, leave the page in memory (its arrival time is reset) and move to the next page (subject to the same rules). Implemented as a circular queue with a clock-hand pointer: if all bits are 1, it degenerates into FIFO
    • Enhanced second-chance algorithm: consider (reference bit, modify bit) as an ordered pair: (0,0) neither recently used nor modified — best to replace; (0,1) not recently used but modified — not quite as good (must be written out); (1,0) recently used but clean — probably used again soon; (1,1) recently used and modified — probably used again, and need to write out before replacement. Replace the first page encountered in the lowest nonempty class (may have to scan the circular queue several times) — used in old Macintosh virtual memory
  • Counting-based page replacement: LFU (Least Frequently Used) — replaces the page with the smallest count (problem: a page used heavily initially then never again retains a high count; fix: shift counts right by 1 bit at regular intervals); MFU (Most Frequently Used) — argument: the page with the smallest count was probably just brought in and has yet to be used. Neither is common (expensive, poor approximation of OPT)
  • Page-buffering algorithms: keep a pool of free frames (always) — read the new page into a free frame before writing out the victim (restart sooner); keep a list of modified pages — when the paging device is idle, write modified pages out and reset their modify bits (higher chance the victim is clean); keep the contents of the free frames — if the old page is referenced again before reuse, reuse it without disk I/O
  • Applications and page replacement: some applications (databases) know better than the OS → raw disk (a disk partition without file-system structure) gives the application direct I/O access, bypassing OS buffering, locking and file services
Explanation

When there is no free frame, a victim page must be chosen. The page is written to disk only if the modify (dirty) bit is set, then the desired page is read in. Algorithms are compared on a reference string, and with 3 frames on the string 7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1:

  • FIFO replaces the oldest page: 15 faults. It can show Belady's anomaly, in which more frames give more faults (the string 1,2,3,4,1,2,5,1,2,3,4,5 gives 9 faults with 3 frames and 10 with 4 frames).
  • Optimal replaces the page that will not be used for the longest time: 9 faults, which is the minimum, but it needs the future, so it is only a yardstick.
  • LRU replaces the page not used for the longest time in the past: 12 faults. It needs hardware support (a counter or a stack), and so approximations are used.

The approximations are the reference bit, additional reference bits (an 8-bit history shifted at each timer interrupt, with the smallest value being the LRU), second chance, or clock (FIFO that gives a page with reference bit 1 another chance by clearing the bit), and the enhanced second chance using the (reference, modify) pair, where (0,0) is the best victim. LFU and MFU count references. Both are rare. Page buffering keeps a pool of free frames and a list of modified pages to write out when the disk is idle.
