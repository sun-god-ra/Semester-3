Contiguous Memory Allocation

Operating Systems · Unit IV: Memory Management

Contiguous Memory Allocation
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
2 of 12
Terms
Operating system, Interrupt, External fragmentation, Internal fragmentation, Latch, Paging, Segmentation

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Main memory must support both the OS and user processes; limited resource, must be allocated efficiently. Usually divided into two partitions: resident operating system, usually held in low memory with the interrupt vector; user processes, held in high memory. Each process contained in a single contiguous section of memory
  • Memory protection: relocation register (value of smallest physical address) + limit register (range of logical addresses): each logical address must be less than the limit register; the MMU maps logically dynamic: physical = logical + relocation. Allows the OS to change size dynamically (e.g., transient OS code such as device drivers not often used, can be loaded and unloaded)
  • Memory allocation — fixed-partition (multiple-partition) scheme: memory divided into fixed-sized partitions; each holds one process; degree of multiprogramming bound by the number of partitions; when a process terminates, partition becomes available. Variable-partition scheme: the OS keeps a table of available memory (holes) and occupied parts; initially all memory is one big hole; when a process arrives it is allocated memory from a hole large enough; the hole is split (one part allocated, other returned to the set of holes); on termination, adjacent holes are merged. Dynamic storage-allocation problem: how to satisfy a request of size n from a list of free holes
    • First fit: allocate the first hole that is big enough (fast; search can start at the beginning or where the previous search ended)
    • Best fit: allocate the smallest hole that is big enough; must search the entire list unless ordered by size; produces the smallest leftover hole
    • Worst fit: allocate the largest hole; must also search the entire list; produces the largest leftover hole (which may be more useful than the small one)
    • First fit and best fit are better than worst fit in terms of speed and storage utilisation (simulations)
    • Example: holes in memory order: 100 K, 500 K, 200 K, 300 K, 600 K; processes 212 K, 417 K, 112 K, 426 K (in order)
      • First fit: 212 → 500 (leaves 288); 417 → 600 (leaves 183); 112 → 288 (the leftover of 500; leaves 176); 426 must wait (largest hole now = 300? holes 100, 176, 200, 300, 183 → none ≥ 426)
      • Best fit: 212 → 300 (leaves 88); 417 → 500 (leaves 83); 112 → 200 (leaves 88); 426 → 600 (leaves 174) → all four placed (best here)
      • Worst fit: 212 → 600 (leaves 388); 417 → 500 (leaves 83); 112 → 388 (leaves 276); 426 must wait
  • Fragmentation
    • External fragmentation — total memory space exists to satisfy a request, but it is not contiguous (scattered holes). Statistical analysis of first fit: given N allocated blocks, another 0.5 N blocks will be lost to fragmentation → one-third of memory may be unusable (50-percent rule)
    • Internal fragmentation — allocated memory may be slightly larger than requested; the size difference is memory internal to a partition but unused (e.g., hole of 18,464 bytes, request 18,462 → 2 bytes left; overhead to keep track of the tiny hole > the hole itself → allocate whole hole)
    • Solutions to external fragmentation: compaction — shuffle memory contents to place all free memory together in one large block; possible only if relocation is dynamic (done at execution time); I/O problem (latch job in memory while it is involved in I/O, or do I/O only into OS buffers); expensive. Other solution: permit the logical address space of processes to be noncontiguous → paging and segmentation
Explanation

In contiguous allocation each process occupies a single block of memory. The relocation register and limit register give protection. In variable partitions the OS maintains a list of holes. When a process arrives, a hole is split. When a process ends, neighbouring holes merge. Three strategies exist for choosing a hole: first fit takes the first hole that is large enough, best fit takes the smallest sufficient hole (leaving the smallest leftover), and worst fit takes the largest hole. First fit and best fit are better than worst fit in speed and utilisation. In the example with holes 100, 500, 200, 300, 600 and processes 212, 417, 112, 426, best fit places all four, while first fit and worst fit cannot place the 426 KB process.

External fragmentation means that enough total free memory exists but not in one piece. The 50-percent rule says that, for first fit, with N allocated blocks about 0.5 N blocks are lost, so about one-third of memory can be unusable. Internal fragmentation is wasted space inside an allocated block. Compaction moves the contents together to make one large hole, which is possible only when relocation is dynamic and costs time. The better answer is to allow a non-contiguous address space, which is what paging and segmentation do.
