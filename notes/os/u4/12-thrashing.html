Thrashing

Operating Systems · Unit IV: Memory Management

Thrashing
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
12 of 12
Terms
Page fault, Operating system, Thrashing, Swapping, Paging, Interrupt, Working set, Internal fragmentation, TLB, Page table

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • If a process does not have "enough" pages, the page-fault rate is very high: page fault to get a page → replace an existing frame → but quickly need the replaced frame back. This leads to low CPU utilisation → the operating system thinks it needs to increase the degree of multiprogramming → another process added to the system → even more faults. Thrashing ≡ a process is busy swapping pages in and out (spending more time paging than executing)
  • Why does paging work? The locality model: a locality is a set of pages that are actively used together; process migrates from one locality to another; localities may overlap. (e.g. a function call defines a new locality: instructions, local variables, a subset of global variables.) Thrashing occurs when \(\sum \text{size of locality} > \text{total memory size}\). Can limit effects by using local or priority page replacement
  • Working-set model: \(\Delta\) = working-set window = a fixed number of page references (e.g. 10,000 instructions). \(WSS_i\) (working-set size of process \(P_i\)) = total number of pages referenced in the most recent \(\Delta\) (varies in time). If \(\Delta\) too small → won't encompass the entire locality; too large → will encompass several localities; \(\Delta=\infty\) → the entire program. \(D=\sum WSS_i\) = total demand for frames; if \(D>m\) → thrashing → the OS selects a process to suspend (swap out). Policy: if \(D>m\), then suspend or swap out one of the processes. Working-set model prevents thrashing while keeping the degree of multiprogramming as high as possible; difficulty: keeping track of the moving window — approximated with a fixed-interval timer interrupt and reference bits
    • Example: reference string ... with \(\Delta=10\): \(WS(t_1)=\{1,2,5,6,7\}\) (WSS = 5)
  • Page-fault frequency (PFF) scheme: a more direct approach than working set — establish an "acceptable" page-fault frequency rate and use a local replacement policy: if the actual rate is too low (below the lower bound), the process loses a frame; if too high (above the upper bound), the process gains a frame; if no free frames, suspend a process
  • Current practice: working sets and page-fault rates have an indirect relationship (a direct measure of PFF); in practice install enough physical memory to avoid thrashing; Linux: OOM killer; memory compression on mobile (Windows 10, iOS: compress several frames into one before paging out)
Other considerations (briefly)
  • Prepaging — bring in some or all of the pages a process will need before they are referenced (reduces the large number of page faults at process start-up; wasteful if pages are not used). Page size selection: fragmentation (small pages → less internal fragmentation), page-table size (large pages → small table), I/O overhead (seek and latency dominate → bigger is better), number of page faults, locality, TLB size and effectiveness (TLB reach = (TLB size) × (page size) — to increase: larger page size or multiple page sizes); typical 4 KB, trend toward larger. Program structure: e.g. a 128×128 array of ints, page size 128 words — row-major accessing for j { for i { data[i][j] = 0 } } → 128 × 128 = 16,384 page faults, while for i { for j { data[i][j] = 0 } } → 128 page faults — good data-structure and programming choices improve locality. I/O interlock and page locking: pages used for I/O must be pinned (locked) in memory so they are not replaced
Explanation

A process that does not have enough frames faults continually, and the OS, seeing low CPU use, adds more processes, which makes it worse. This is thrashing. It works because of the locality model: a process uses a set of pages together and moves from one locality to another. Thrashing happens when the sum of the localities is larger than the memory. The working-set model uses a window of the last Δ references. The working-set size is the number of distinct pages referenced in the window. If the total demand \(D=\sum WSS_i\) exceeds the number of frames m, the OS suspends a process. The page-fault frequency scheme sets an upper and a lower limit on the fault rate: a process with a too-high rate gets another frame, and one with a too-low rate loses a frame.

Other points are prepaging, the page-size trade-off (small pages mean less fragmentation, but larger page tables), the TLB reach = TLB entries × page size, and program structure (when a 128×128 array is stored row by row with one row per page, zeroing it column-wise causes 16,384 faults, while row-wise causes only 128). Pages used for I/O must be locked in memory.
