Segmentation (Memory-Management Scheme that supports the User View)

Operating Systems · Unit IV: Memory Management

Segmentation (Memory-Management Scheme that supports the User View)
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
6 of 12
Terms
Segmentation, External fragmentation, Paging, Page table, Internal fragmentation

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • User view of memory: a program is a collection of segments — a segment is a logical unit: main program, procedure, function, method, object, local variables, global variables, common block, stack, symbol table, arrays. Segmentation supports this view: logical address space = collection of segments; each segment has a name (number) and length; addresses specify segment number and offset within the segment: <segment-number, offset>
  • Segment table: maps two-dimensional logical addresses to one-dimensional physical addresses; each entry has base (starting physical address of the segment) and limit (length of the segment). STBR (segment-table base register) — location of the segment table in memory; STLR (segment-table length register) — number of segments used by a program; segment number s is legal if s < STLR. Protection: with each entry, validation bit = 0 → illegal segment, read/write/execute privileges. Sharing at the segment level (code segments). Allocation: first fit/best fit → external fragmentation (but segments are small)
  • Translation: if offset d < limit → physical address = base + d, else trap (addressing error)
    • Example: segment table: seg 0 (base 1400, limit 1000), seg 1 (base 6300, limit 400), seg 2 (base 4300, limit 400), seg 3 (base 3200, limit 1100), seg 4 (base 4700, limit 1000). Reference to byte 53 of segment 2 → 4300 + 53 = 4353; byte 852 of segment 3 → 3200 + 852 = 4052; byte 1222 of segment 0 → 1222 > 1000 → trap
  • Segmentation with paging (Intel IA-32): logical address → segmentation unit → linear address → paging unit → physical address. IA-32: up to 16 K segments per process (8 K private in the LDT, 8 K shared in the GDT); selector = 13-bit segment number (s) + 1-bit g (GDT/LDT) + 2-bit protection p; segment descriptor → base + limit; linear address 32 bits → two-level paging (10+10+12), with a 4 MB page option (page-size flag) to skip the inner table. x86-64 uses 4-level paging
Paging Segmentation
fixed-size pages variable-size segments
invisible to the user (physical division) visible to the user (logical division)
internal fragmentation external fragmentation
address = (page no., offset) address = (segment no., offset)
page table: frame number segment table: base and limit
does not support the user view supports user view, protection, sharing at logical level
Explanation

Segmentation divides the address space the way the programmer sees it, into segments such as main program, functions, stack and symbol table. An address is a pair (segment number, offset). The segment table gives the base and the limit of each segment. If the offset is less than the limit, then physical address = base + offset, or else a trap occurs. In the example, byte 53 of segment 2 is at 4300+53 = 4353, byte 852 of segment 3 is at 3200+852 = 4052, and byte 1222 of segment 0 traps, because the limit of segment 0 is 1000. Segmentation has external fragmentation, whereas paging has internal fragmentation, and paging is invisible to the programmer. IA-32 combines the two: the segmentation unit makes a linear address and the paging unit then maps it.
