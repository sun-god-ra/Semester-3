Main Memory — Background

Operating Systems · Unit IV: Memory Management

Main Memory — Background
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
1 of 12
Terms
Kernel, Operating system

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Program must be brought (from disk) into memory and placed within a process for it to run. Main memory and registers are the only storage the CPU can access directly. Register access = one CPU clock (or less); main memory access can take many cycles → CPU stalls; cache sits between main memory and CPU registers. Protection of memory is required to ensure correct operation
  • Base and limit registers define the logical address space of a process: base = smallest legal physical address; limit = size of the range. CPU must check every memory access generated in user mode to be sure it is between base and base + limit; otherwise trap to the OS (addressing error, fatal). Only the OS (kernel mode, privileged instructions) can load the base and limit registers
  • Address binding: programs on disk, ready to be brought into memory to execute form an input queue. Addresses are symbolic in source (e.g. count); a compiler binds symbolic addresses to relocatable addresses ("14 bytes from beginning of this module"); the linker or loader binds relocatable addresses to absolute addresses. Binding of instructions and data to memory addresses can happen at three different stages
    • Compile time: if memory location is known a priori, absolute code can be generated; must recompile if the starting location changes (MS-DOS .COM programs)
    • Load time: if memory location is not known at compile time, must generate relocatable code; binding delayed until load time (if the starting address changes, reload the user code)
    • Execution time: if the process can be moved during execution from one memory segment to another → binding delayed until run time; needs hardware support for address maps (base and limit registers, MMU); used by most general-purpose OS
  • Logical vs physical address space
    • Logical (virtual) address — generated by the CPU; physical address — address seen by the memory unit (loaded into the memory-address register). Same in compile-time and load-time binding; differ in execution-time binding
    • Logical address space = set of all logical addresses generated by a program; physical address space = set of all physical addresses generated by a program
    • Memory-Management Unit (MMU) — hardware device that maps virtual to physical addresses at run time. Simple scheme: the value in the relocation register (= base register) is added to every address generated by a user process at the time it is sent to memory. The user program deals with logical addresses; it never sees the real physical addresses. Execution-time binding occurs when a reference is made to a location in memory; logical address bound to physical address
  • Dynamic loading: a routine is not loaded until it is called → better memory-space utilisation; unused routine is never loaded; all routines kept on disk in relocatable load format; useful when large amounts of code are infrequently needed (error routines); no special support from the OS required (implemented through program design; OS can provide library routines)
  • Dynamic linking: linking postponed until execution time; static linking = system libraries and program code combined by the loader into the binary program image. Dynamic linking: a stub is included in the image for each library routine reference — small piece of code that locates the appropriate memory-resident library routine; the stub replaces itself with the address of the routine and executes it. OS checks if the routine is in the process's memory address, if not, adds it. Dynamically linked libraries (DLLs, shared libraries) — extensively used for system libraries; saves memory (one copy shared) and allows library updates (versioning). Requires help from the OS (protection: only OS can check whether the routine is in another process's memory space or allow multiple processes to access the same memory addresses)
Explanation

The CPU can directly access only registers and main memory. A program must therefore be brought into memory to run. To protect processes from each other, the hardware uses a base register (the smallest legal address) and a limit register (the size of the range). Every address generated in user mode is checked to be at least the base and below base + limit; otherwise the hardware traps to the OS. Only the OS can load these registers, since the instruction is privileged.

Addresses are bound at three stages. Compile-time binding gives absolute code, and works only if the location is known beforehand. Load-time binding generates relocatable code, which is bound when loaded. Execution-time binding allows the process to move in memory during its life, needs hardware (the MMU), and is used by general-purpose operating systems. The address generated by the CPU is the logical (virtual) address, and the address seen by the memory is the physical address. The MMU maps logical to physical addresses at run time; in the simplest scheme it adds the value of the relocation register to every address. The user program works only with logical addresses and never sees the physical ones.

In dynamic loading a routine is not loaded until it is called, which saves memory for rarely used code such as error handling. In dynamic linking the linking is postponed to the run time, and a stub in the image finds the library routine in memory (or loads it) and replaces itself with the routine's address. A shared library (DLL) is kept in memory once and shared by many processes.
