Allocation of Frames

Operating Systems · Unit IV: Memory Management

Allocation of Frames
Subject
Operating Systems (24CS204)
Unit
Unit IV: Memory Management
Topic
11 of 12
Terms
Page fault, Paging, Kernel

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Each process needs a minimum number of frames — determined by the instruction-set architecture (the instruction must be restartable; e.g. an instruction with indirect addressing may need up to more pages: instruction page + indirect pages), and the maximum is the total available frames. Example (IBM 370): an SS MOVE instruction can span 6 pages (instruction 6 bytes spanning 2 pages; from operand 2 pages; to operand 2 pages)
  • Allocation schemes: equal allocation — divide m frames among n processes: \(m/n\) each (e.g., 100 frames, 5 processes → 20 each; wasteful for small processes); proportional allocation — allocate according to process size: \(a_i=\dfrac{s_i}{S}\times m\) where \(S=\sum s_i\). Example: \(m=62\) frames, two processes of size \(s_1=10\) pages, \(s_2=127\) pages: \(S=137\); \(a_1=\frac{10}{137}\times62\approx4\); \(a_2=\frac{127}{137}\times62\approx57\). Priority allocation — proportional allocation using priorities rather than size (or a combination of size and priority); on a page fault, select for replacement one of its own frames or a frame from a lower-priority process
  • Global vs local replacement: global replacement — a process selects a replacement frame from the set of all frames; one process can take a frame from another — greater throughput, more common; but process execution time can vary greatly (depends on the paging behaviour of other processes). Local replacement — each process selects only from its own set of allocated frames — more consistent per-process performance, but possibly underutilised memory. Reapers and kernel threads: reaper reclaims memory when the free-memory list falls below a minimum threshold until it reaches a maximum threshold; if all else fails, out-of-memory (OOM) killer (Linux) selects a process to kill
  • Non-uniform memory access (NUMA): in NUMA systems memory access time varies; allocate frames close to the CPU on which the thread is scheduled (Linux lgroups — Solaris: locality groups) → improves cache hits and decreases memory-access time
Explanation

Each process needs a minimum number of frames set by the instruction set. Equal allocation gives m/n frames to each, and proportional allocation gives \(a_i=s_i m/S\). For 62 frames and processes of 10 and 127 pages, they receive about 4 and 57 frames. Global replacement chooses a victim from all frames, giving higher throughput but variable behaviour of each process, and local replacement chooses from the process's own frames. On NUMA systems the frames should be close to the CPU on which the thread runs.
