Deadlock Characterisation

Operating Systems · Unit III: Process Synchronization and Deadlocks

Deadlock Characterisation
Subject
Operating Systems (24CS204)
Unit
Unit III: Process Synchronization and Deadlocks
Topic
10 of 15
Terms
Deadlock, Mutual exclusion

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Four necessary conditions — deadlock can arise if all four hold simultaneously
    1. Mutual exclusion — only one process at a time can use a resource (nonsharable)
    2. Hold and wait — a process holding at least one resource is waiting to acquire additional resources held by other processes
    3. No preemption — a resource can be released only voluntarily by the process holding it after it has completed its task
    4. Circular wait — there exists a set {P0, P1, …, Pn} of waiting processes such that P0 waits for a resource held by P1, P1 for P2, …, P(n−1) for Pn, and Pn waits for a resource held by P0
  • Resource-allocation graph (RAG): a directed graph \(G=(V,E)\); \(V\) = set of processes \(P=\{P_1,\dots,P_n\}\) (circles) and resource types \(R=\{R_1,\dots,R_m\}\) (rectangles, with dots = instances); request edge \(P_i\to R_j\) (Pi is waiting); assignment edge \(R_j\to P_i\) (an instance of Rj is allocated to Pi). When a request is fulfilled, the request edge converts into an assignment edge; on release the assignment edge is deleted. Claim edge \(P_i \dashrightarrow R_j\) (dashed; Pi may request Rj in the future) — used in avoidance (resource-allocation-graph algorithm)
  • Facts: no cycle → no deadlock. If there is a cycle: only one instance per resource type → deadlock; several instances per type → possibility of deadlock (cycle is necessary but not sufficient)
    • Example with a cycle but no deadlock: P1→R1→P2→R3→P3... where another process (P4 holding an instance of R2) can release and break the cycle
  • In the graph above: P1 holds R2 and requests R1; P2 holds R1 and requests R2 → cycle P1→R1→P2→R2→P1, one instance each → deadlock
Explanation

A deadlock is a situation where each process in a set is waiting for a resource held by another process in the set, so none can proceed. A process uses a resource by requesting it, using it and releasing it. Livelock is different: the processes are not blocked but keep repeating an action that fails and make no progress.

All four conditions must hold at the same time for a deadlock: mutual exclusion, hold and wait, no preemption, and circular wait.

The resource-allocation graph has process nodes and resource nodes. A request edge goes from a process to a resource, and an assignment edge goes from a resource to a process. If there is no cycle, there is no deadlock. If there is a cycle and every resource has one instance, there is a deadlock; if the resources have several instances, there may be a deadlock but not necessarily. The cycle is necessary but not sufficient in that case.
