Synchronisation Hardware

Operating Systems · Unit III: Process Synchronization and Deadlocks

Synchronisation Hardware
Subject
Operating Systems (24CS204)
Unit
Unit III: Process Synchronization and Deadlocks
Topic
4 of 15
Terms
Critical region, Interrupt, Multiprocessor, Mutual exclusion, Race condition, Expected value

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Many systems provide hardware support for implementing the critical-section code. All solutions are based on locking — protecting critical regions via locks
  • Uniprocessors: could disable interrupts — currently running code executes without preemption; generally too inefficient on multiprocessor systems (message passed to all processors → delays entry; affects system clock)
  • Hardware instructions — atomic (non-interruptible), i.e., as one uninterruptible unit
    • test_and_set(): sets the target to true and returns its old value
c
boolean test_and_set(boolean *target) {
    boolean rv = *target;
    *target = true;
    return rv;
}
/* shared: boolean lock = false; */
do {
    while (test_and_set(&lock))
        ;                    /* do nothing */
    /* critical section */
    lock = false;
    /* remainder section */
} while (true);
  • compare_and_swap(value, expected, new_value) (CAS): sets value = new_value only if value == expected; always returns the original value
c
int compare_and_swap(int *value, int expected, int new_value) {
    int temp = *value;
    if (*value == expected)
        *value = new_value;
    return temp;
}
/* shared: int lock = 0; */
do {
    while (compare_and_swap(&lock, 0, 1) != 0)
        ;                    /* do nothing */
    /* critical section */
    lock = 0;
} while (true);
  • Both give mutual exclusion but not bounded waiting (a process may be unlucky and spin forever)
  • Bounded-waiting mutual exclusion with test_and_set: shared boolean waiting[n]; boolean lock; all false. Process Pi: waiting[i] = true; key = true; while (waiting[i] && key) key = test_and_set(&lock); waiting[i] = false; /* CS */ j = (i+1) % n; while ((j != i) && !waiting[j]) j = (j+1) % n; if (j == i) lock = false; else waiting[j] = false; /* remainder */. Hands the lock over in cyclic order, so any waiting process enters within n − 1 turns
  • Atomic variables: provide atomic operations on basic data types (integers, booleans), built on CAS — e.g. an atomic increment(&sequence) ensures no race condition; commonly used for counters and sequence generators; they don't solve all race conditions (e.g., bounded buffer with several consumers)
Explanation

On a single processor one could disable interrupts, but that does not work well on multiprocessors. Hardware therefore provides atomic instructions. test_and_set sets a variable to true and returns the old value, so the process that gets false knows it has taken the lock. compare_and_swap changes the variable to a new value only if it has the expected value and returns the old value. Locks built with them give mutual exclusion, but not bounded waiting, because an unlucky process can spin forever. A longer algorithm using the waiting array hands the lock over to the next waiting process in the cyclic order and so achieves bounded waiting within n−1 turns. Atomic variables are the same idea for simple data types like integer counters.
