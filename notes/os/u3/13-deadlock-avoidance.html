Deadlock Avoidance

Operating Systems · Unit III: Process Synchronization and Deadlocks

Deadlock Avoidance
Subject
Operating Systems (24CS204)
Unit
Unit III: Process Synchronization and Deadlocks
Topic
13 of 15
Terms
Deadlock, Banker's algorithm

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Requires additional information in advance about how resources are to be requested: the simplest and most useful model — each process declares the maximum number of resources of each type it may need. The deadlock-avoidance algorithm dynamically examines the resource-allocation state to ensure there can never be a circular-wait condition. Resource-allocation state = number of available and allocated resources, and the maximum demands of the processes

  • Safe state: when a process requests an available resource, the system must decide if immediate allocation leaves the system in a safe state. The system is in a safe state if there exists a safe sequence \(\langle P_1,\dots,P_n\rangle\) of all processes such that for each \(P_i\) the resources that \(P_i\) can still request can be satisfied by the currently available resources plus the resources held by all \(P_j\) with \(j<i\). If not available, \(P_i\) can wait until all \(P_j\) have finished; then it obtains the resources, completes, returns them, and terminates

    • Safe state → no deadlock. Unsafe state → possibility of deadlock (but not all unsafe states are deadlocks). Avoidance = ensure the system never enters an unsafe state
    • Example (12 tape drives): P0 max 10 (holds 5), P1 max 4 (holds 2), P2 max 9 (holds 2); available 3. Safe sequence ⟨P1, P0, P2⟩: P1 needs 2 ≤ 3 → after finishing, 5 available; P0 needs 5 ≤ 5 → finishes, 10 available; P2 needs 7 ≤ 10 ✓. If P2 is granted one more drive (3 held, available 2) → unsafe: P1 can finish (4 available) but P0 needs 5, P2 needs 6 → may deadlock

  • Relationship: deadlock states ⊂ unsafe states; safe and unsafe states together make up all states. The system can go from safe → unsafe (by a bad grant), and an unsafe state may lead to deadlock

  • Resource-allocation-graph algorithm (single instance per resource type): claim edges; a request is granted only if converting the request edge to an assignment edge does not result in a cycle in the graph (cycle detection \(O(n^2)\))

  • Banker's algorithm (Dijkstra; for multiple instances per resource type): each process must declare its maximum use in advance; when a process requests resources, the system determines whether allocation leaves the system in a safe state; if not, the process waits; when a process gets all its resources, it must return them in a finite time. Named from a banker who never allocates cash so as not to be unable to satisfy all customers
    • Data structures (\(n\) = number of processes, \(m\) = number of resource types)
      • Available[m] — Available[j] = k means \(k\) instances of \(R_j\) are available
      • Max[n][m] — Max[i][j] = maximum demand of \(P_i\) for \(R_j\)
      • Allocation[n][m] — instances of \(R_j\) currently allocated to \(P_i\)
      • Need[n][m] — remaining need; Need[i][j] = Max[i][j] − Allocation[i][j]
    • Safety algorithm
      1. Work = Available; Finish[i] = false for all i
      2. Find an \(i\) such that Finish[i] == false and Need_i ≤ Work; if none → step 4
      3. Work = Work + Allocation_i; Finish[i] = true; go to step 2
      4. If Finish[i] == true for all i → safe; else unsafe. Complexity \(O(m\times n^2)\)
    • Resource-request algorithm for \(P_i\) with request vector \(Request_i\)
      1. If \(Request_i \le Need_i\) go to 2, else error (process exceeded its maximum claim)
      2. If \(Request_i \le Available\) go to 3, else \(P_i\) must wait
      3. Pretend to allocate: Available -= Request_i; Allocation_i += Request_i; Need_i -= Request_i. If the resulting state is safe → grant; else restore the old state and \(P_i\) waits
    • Worked example (5 processes P0–P4; resource types A (10), B (5), C (7)); snapshot at \(T_0\)
Allocation A B C Max A B C Available A B C Need = Max − Alloc
P0 0 1 0 7 5 3 3 3 2 7 4 3
P1 2 0 0 3 2 2 1 2 2
P2 3 0 2 9 0 2 6 0 0
P3 2 1 1 2 2 2 0 1 1
P4 0 0 2 4 3 3 4 3 1
  • Safety check: Work = (3,3,2). P0: need (7,4,3) ≤ (3,3,2)? no. P1: (1,2,2) ≤ (3,3,2) ✓ → Work = (5,3,2). P2: (6,0,0) ≤ (5,3,2)? no. P3: (0,1,1) ✓ → (7,4,3). P0: (7,4,3) ≤ (7,4,3) ✓ → (7,5,3). P2: (6,0,0) ✓ → (10,5,5). P4: (4,3,1) ✓ → (10,5,7). Safe sequence ⟨P1, P3, P0, P2, P4⟩ (⟨P1, P3, P4, P0, P2⟩ is also valid). System is safe; total allocation (7,2,5) + available (3,3,2) = (10,5,7) = total resources A=10, B=5, C=7 ✓
    • P1 requests (1,0,2): (1,0,2) ≤ Need₁ (1,2,2) ✓; ≤ Available (3,3,2) ✓. Pretend: Available = (2,3,0); Alloc₁ = (3,0,2); Need₁ = (0,2,0). Safety: ⟨P1, P3, P4, P0, P2⟩ found → safe → request granted
    • Then P4 requests (3,3,0): ≤ Need₄ (4,3,1) ✓, but not ≤ Available (2,3,0) → P4 must wait
    • Then P0 requests (0,2,0): ≤ Need₀ ✓, ≤ Available (2,3,0) ✓; pretend: Available = (2,1,0); Need₀ = (7,2,3); no process's need ≤ (2,1,0) → unsafe → request denied, P0 waits
Explanation

Avoidance needs each process to declare in advance the maximum resources it may need. The system is in a safe state if there is an order (safe sequence) of all the processes such that each one can obtain what it still needs from the available resources plus those released by the earlier processes. A safe state cannot deadlock, an unsafe state may deadlock, and avoidance keeps the system always safe. For example, with 12 tape drives, P0 has 5 of at most 10, P1 has 2 of 4, P2 has 2 of 9, and 3 are free; ⟨P1, P0, P2⟩ is a safe sequence. If P2 is given one more drive, the state becomes unsafe.

For resources with a single instance, the resource-allocation-graph algorithm is used: a request is granted only if converting the request edge to an assignment edge does not create a cycle, using claim edges. For multiple instances, the Banker's algorithm is used. It keeps four structures, Available, Max, Allocation and Need = Max − Allocation. The safety algorithm tries to find a process whose Need is at most Work, pretends to run it to completion and adds its Allocation to Work. If all processes can finish, the state is safe. The resource-request algorithm checks that the request is within the Need and the Available, tentatively grants it, and runs the safety algorithm. If the state is unsafe, the request is refused and the process waits.

In the worked example, the system is safe with the sequence P1, P3, P0, P2, P4. P1's request for (1,0,2) is granted, as the new state is safe. P4's request for (3,3,0) must wait, because only (2,3,0) is available. P0's request for (0,2,0) is refused, because it would leave Available as (2,1,0) and no process could then complete.
