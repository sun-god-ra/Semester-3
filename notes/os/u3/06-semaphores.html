Semaphores

Operating Systems · Unit III: Process Synchronization and Deadlocks

Semaphores
Subject
Operating Systems (24CS204)
Unit
Unit III: Process Synchronization and Deadlocks
Topic
6 of 15
Terms
Semaphore, Mutex, Mutual exclusion, Starvation, Critical section, Deadlock, Inheritance

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Semaphore S (Dijkstra) — an integer variable that, apart from initialisation, is accessed only through two standard atomic operations: wait() (P — "proberen", to test) and signal() (V — "verhogen", to increment). Atomic: when one process modifies the semaphore value, no other process can simultaneously modify the same value
c
wait(S) {
    while (S <= 0)
        ;        /* busy wait */
    S--;
}
signal(S) {
    S++;
}
  • Types: counting semaphore — integer value ranges over an unrestricted domain (used to control access to a resource with a finite number of instances; initialised to the number of resources available; wait() to use one, signal() to release one; at 0, all resources are in use → processes block); binary semaphore — value 0 or 1 (can behave like a mutex lock; for systems without mutex locks)
  • Uses: mutual exclusion (mutex initialised to 1: wait(mutex); CS; signal(mutex)); ordering / synchronisation — to execute statement S2 in P2 only after S1 in P1: share semaphore synch initialised to 0: P1: S1; signal(synch); P2: wait(synch); S2;
  • Semaphore implementation without busy waiting: each semaphore has an integer value and a list (queue) of waiting processes. wait(): value--; if value < 0, add this process to the list and block() (suspend: place in waiting queue, state waiting). signal(): value++; if value <= 0, remove a process P from the list and wakeup(P) (move to ready queue). Semaphore value may be negative: magnitude = number of processes waiting
c
typedef struct { int value; struct process *list; } semaphore;
wait(semaphore *S) {
    S->value--;
    if (S->value < 0) {
        add this process to S->list;
        block();
    }
}
signal(semaphore *S) {
    S->value++;
    if (S->value <= 0) {
        remove a process P from S->list;
        wakeup(P);
    }
}
  • List can use FIFO queue (bounded waiting) — any order can lead to starvation
    • Still has busy waiting but only within wait() and signal() critical sections (short, ~10 instructions), not in application CS (which may be long)
  • Deadlock and starvation with semaphores: deadlock — two or more processes waiting indefinitely for an event that can be caused only by one of the waiting processes (e.g., S and Q initialised to 1: P0: wait(S); wait(Q); … signal(S); signal(Q); P1: wait(Q); wait(S); … signal(Q); signal(S); → P0 holds S waits for Q, P1 holds Q waits for S). Starvation (indefinite blocking) — a process may never be removed from the semaphore queue (e.g., LIFO)
  • Priority inversion: a higher-priority process needs a resource held by a lower-priority process (low-priority L holds lock; H waits; medium-priority M preempts L → H waits for M effectively). Solution: priority-inheritance protocol — all processes accessing resources needed by a higher-priority process inherit the higher priority until they finish. Mars Pathfinder (1997) is the classic case: a meteorological task holding a bus mutex got preempted by a medium-priority communications task, the high-priority bus management task missed its deadline → watchdog reset; fixed by enabling priority inheritance remotely
Explanation

A semaphore is an integer variable accessed only through the atomic wait() (decrement, and wait if it cannot) and signal() (increment). A counting semaphore is used for a resource with n instances, initialised to n. A binary semaphore (0 or 1) works as a mutex. To make statement S2 of process P2 run after S1 of P1, use a semaphore initialised to 0: P1 runs S1 then signal; P2 does wait then S2.

To avoid busy waiting, each semaphore has a queue. wait decrements the value and, if it becomes negative, blocks the process in the queue. signal increments the value, and if the value is not positive, it wakes up one waiting process. A negative value shows how many processes are waiting.

Semaphores can cause deadlock, for example when two processes take two semaphores in opposite orders, and starvation, for example when the waiting queue is LIFO. Priority inversion happens when a low-priority process holds a lock needed by a high-priority one and a medium-priority process preempts the low one, so the high one waits indirectly for the medium one. The solution is the priority-inheritance protocol, where the low-priority process temporarily takes the priority of the waiting high-priority process. The Mars Pathfinder mission of 1997 is the well-known example.
