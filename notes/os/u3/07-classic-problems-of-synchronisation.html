Notebook notes
Bounded-buffer (producer–consumer) problem
  • n buffers, each holds one item; semaphores: mutex = 1 (mutual exclusion for buffer access), empty = n (number of empty buffers), full = 0 (number of full buffers)
c
/* producer */
do {
    /* produce an item in next_produced */
    wait(empty);
    wait(mutex);
    /* add next_produced to the buffer */
    signal(mutex);
    signal(full);
} while (true);

/* consumer */
do {
    wait(full);
    wait(mutex);
    /* remove an item from buffer to next_consumed */
    signal(mutex);
    signal(empty);
    /* consume the item */
} while (true);
  • Order matters: wait(empty) before wait(mutex) — reversed order can deadlock (a producer with the mutex waits on empty while a consumer waits on mutex)
Readers–writers problem
  • A data set is shared among concurrent processes: readers only read (can read simultaneously), writers can update (exclusive access). Problem: allow multiple readers at the same time, but only one writer (and no readers while a writer is writing)
  • First readers–writers problem: no reader is kept waiting unless a writer has already obtained permission to use the shared object (readers' priority) → writers may starve. Second: once a writer is ready, it performs the write as soon as possible (writers' priority) → readers may starve
  • Shared data: semaphore rw_mutex = 1; (common to readers and writers), semaphore mutex = 1; (protects read_count), int read_count = 0;
c
/* writer */
do {
    wait(rw_mutex);
    /* writing is performed */
    signal(rw_mutex);
} while (true);

/* reader */
do {
    wait(mutex);
    read_count++;
    if (read_count == 1)
        wait(rw_mutex);        /* first reader locks out writers */
    signal(mutex);
    /* reading is performed */
    wait(mutex);
    read_count--;
    if (read_count == 0)
        signal(rw_mutex);      /* last reader lets writers in */
    signal(mutex);
} while (true);
  • Reader–writer locks are provided by some systems (multiple processes acquire in read mode, only one in write mode) — useful when many more readers than writers, or when it is easy to identify readers and writers
Dining-philosophers problem
  • Five philosophers sit at a round table, thinking and eating; a bowl of rice in the center; five chopsticks (one between each pair of neighbours). A hungry philosopher needs both left and right chopsticks to eat; picks up one at a time; puts both down when finished. Represents allocating several resources among several processes in a deadlock-free and starvation-free manner
  • Semaphore solution: semaphore chopstick[5] all initialised to 1; philosopher i: wait(chopstick[i]); wait(chopstick[(i+1)%5]); /* eat */ signal(chopstick[i]); signal(chopstick[(i+1)%5]); /* think */. Guarantees no two neighbours eat simultaneously but can create a deadlock: if all five pick up left chopstick at the same time → all wait forever
  • Remedies: allow at most four philosophers to sit at the table; allow a philosopher to pick up chopsticks only if both are available (picking up in a critical section); use an asymmetric solution — an odd philosopher picks left then right, an even one picks right then left; (a monitor solution below)
Explanation

In the bounded-buffer problem, three semaphores are used: mutex=1 protects the buffer, empty=n counts empty slots and full=0 counts filled slots. The producer waits on empty then mutex, adds the item, and signals mutex then full. The consumer is the mirror image. The order of the waits is important: if the producer did wait(mutex) before wait(empty), it could hold the mutex while waiting for an empty slot that only a consumer can create, but the consumer cannot enter, so there would be a deadlock.

In the readers-writers problem, many readers may read together, but a writer needs exclusive access. In the first version readers have priority, so a writer may starve; in the second, writers have priority, so readers may starve. The solution uses rw_mutex for exclusive access, mutex to protect the read_count, and the rule that the first reader locks the writers out and the last reader lets them in.

In the dining-philosophers problem, five philosophers need two chopsticks each. If each philosopher picks up the left chopstick first, all five may hold one and wait for the other forever, which is a deadlock. The remedies are to allow at most four at the table, to pick up both chopsticks only if both are available, or to use an asymmetric rule (odd philosophers pick left first, even ones pick right first).
