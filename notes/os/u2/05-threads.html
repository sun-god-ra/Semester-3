Operating Systems · Unit II: Process Management and Scheduling

Threads

Unit

Topic
5 of 14
Terms
Kernel, Interrupt, Shared memory, Message passing, Multiprocessor, Debugging

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Thread = basic unit of CPU utilisation; comprises a thread ID, program counter, register set and stack. Threads of the same process share the code section, data section, heap and OS resources (open files, signals)
  • A traditional (heavyweight) process has a single thread of control; with multiple threads → can perform more than one task at a time
  • Example uses: web browser (one thread for display, another fetching data), word processor (display, keystroke handling, spelling check in the background), web server (a thread per request rather than a process per request — much lighter), RPC servers, OS kernels (device or interrupt handling), Linux kthreads
  • Benefits of multithreaded programming: responsiveness (continues even if part is blocked), resource sharing (default sharing of memory — easier than shared memory/message passing between processes), economy (creating a thread is cheaper than a process; context switching among threads is faster — Solaris: creating a process is ~30× slower, context switching ~5× slower), scalability (use multiple processing cores, utilisation of multiprocessor architectures)
  • Multicore programming: concurrency (progress of more than one task — on a single core, interleaved) vs parallelism (perform more than one task simultaneously — needs multiple cores). Programming challenges (Amdahl and others): identifying tasks (independent, divisible), balance (equal work/value), data splitting, data dependency (synchronise), testing and debugging
    • Amdahl's Law — speedup with N cores and serial fraction S:

\[\text{speedup} \le \frac{1}{S + \dfrac{1-S}{N}}\]

  • E.g. application is 75 % parallel, 25 % serial (\(S=0.25\)): on 2 cores speedup \(=1/(0.25+0.375)=1.6\); on 4 cores \(=1/(0.25+0.1875)=2.29\); as \(N\to\infty\), speedup \(\to 1/S = 4\)
    • Types of parallelism: data parallelism (same operation on different subsets of the same data across cores), task parallelism (different operations/threads on different cores)
Explanation

A thread is the basic unit of CPU use, with its own thread id, program counter, registers and stack. Threads of a process share code, data, heap and open files. A multithreaded program is more responsive, shares resources easily, is cheaper to create and switch than separate processes, and can use many cores.

Concurrency means more than one task makes progress, which can be done on a single core by interleaving. Parallelism means more than one task executes at the same instant, which needs more than one core. Amdahl's law says that if a fraction S of the program is serial, the speed-up with N cores is at most \(1/(S+(1-S)/N)\). For 25% serial it is 1.6 on two cores and 2.29 on four cores, and can never exceed 4 however many cores are added.
