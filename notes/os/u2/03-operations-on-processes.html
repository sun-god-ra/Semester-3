Notebook notes
Process creation
  • A parent process creates children, which create other processes, forming a tree. Each identified by a process identifier (pid) (unique integer). In UNIX init (pid 1) is the root parent of all user processes; ps -el, pstree
  • Resource sharing options: parent and children share all resources, children share a subset of the parent's resources, or parent and child share no resources
  • Execution options: parent and children execute concurrently, or parent waits until some or all children terminate
  • Address-space options: child is a duplicate of the parent (same program and data), or child has a new program loaded into it
  • UNIX: fork() creates a new process (copy of the parent's address space); exec() family replaces the process's memory space with a new program; parent can call wait() to move itself off the ready queue until the child terminates. fork() returns 0 to the child and the child's pid to the parent (negative on error)
c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
int main() {
    pid_t pid = fork();
    if (pid < 0) { fprintf(stderr, "Fork failed"); return 1; }
    else if (pid == 0) { execlp("/bin/ls", "ls", NULL); }   /* child */
    else { wait(NULL); printf("Child complete\n"); }          /* parent */
    return 0;
}
  • Number of processes created by n calls of fork() in a program (no conditions) = \(2^n\) total (so \(2^n-1\) children)
  • Windows: CreateProcess() — parent's address space not copied; loads a program with 10 parameters (application name, command line, security attributes, inherit handles, creation flags, environment, directory, STARTUPINFO, PROCESS_INFORMATION)
Process termination
  • Process executes last statement and asks the OS to delete it using exit(); may return a status value (integer) to the parent via wait(); the OS deallocates all its resources (memory, open files, I/O buffers)
  • A parent may terminate a child using abort()/TerminateProcess()/kill() when: the child has exceeded allocated resources; the task assigned to the child is no longer required; the parent is exiting and the OS does not allow a child to continue without a parent (cascading termination)
  • Zombie process: a process that has terminated, but whose parent has not yet called wait(); the process table entry (pid, exit status) stays. Once the parent calls wait(), the entry is released
  • Orphan process: parent terminated without invoking wait(); UNIX makes init the new parent, which periodically calls wait() to collect them
  • Android: process importance hierarchy — foreground, visible, service, background, empty; terminate in the reverse order to reclaim memory
Explanation

A parent creates children by fork(). The child is a copy of the parent. fork() returns 0 in the child and the child's pid in the parent, which is how the two parts of the program know which one they are. The child can replace itself with another program with exec(). The parent can wait for the child with wait(). If a program calls fork() n times (without conditions), it ends up with \(2^n\) processes in total.

A process ends by calling exit(), and its resources are freed. A zombie is a process that has finished but whose parent has not yet called wait(), so its entry in the process table remains. An orphan is a process whose parent has terminated; in UNIX init adopts it and calls wait() for it.
