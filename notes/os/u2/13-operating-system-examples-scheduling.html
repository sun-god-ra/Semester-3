Operating System Examples (scheduling)

Operating Systems · Unit II: Process Management and Scheduling

Operating System Examples (scheduling)
Subject
Operating Systems (24CS204)
Unit
Unit II: Process Management and Scheduling
Topic
13 of 14
Terms
Real-time, System call

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Linux — Completely Fair Scheduler (CFS): scheduling classes each with a specific priority (default for normal tasks, real-time class); scheduler picks the highest-priority task in the highest-priority class. CFS assigns a proportion of CPU time based on the nice value (−20 to +19; lower nice = higher priority; default 0), and records virtual run time (vruntime) per task; picks the task with the smallest vruntime, stored in a red–black tree (leftmost node, O(log N) insert, cached leftmost). Targeted latency = interval in which every runnable task should run at least once. Linux real-time priorities 0–99, normal 100–139
  • Windows: priority-based, preemptive scheduling; dispatcher is the scheduler; thread runs until preempted by a higher-priority thread, terminates, its time quantum ends, or it calls a blocking system call; 32-level priority scheme: variable class (1–15), real-time class (16–31), memory-management thread at priority 0; queue for each priority; idle thread when no ready thread. Priority classes: REALTIME, HIGH, ABOVE_NORMAL, NORMAL, BELOW_NORMAL, IDLE; relative priorities within classes. Priority boost on wait for I/O or after a wait
Explanation

Linux's Completely Fair Scheduler tracks the virtual run time of each task, which grows more slowly for tasks with a low nice value (higher priority). It picks the task with the smallest virtual run time, which is the leftmost node of a red-black tree. Windows uses a 32-level preemptive priority scheme, with 16–31 for real-time and 1–15 for variable priorities.

To choose an algorithm, there are four evaluation methods: deterministic modelling (exact but only for the given workload), queueing models (Little's formula \(n=\lambda W\)), simulation (with random or trace data), and actual implementation (most accurate and the most expensive).
