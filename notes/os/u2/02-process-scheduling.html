Process Scheduling

Operating Systems · Unit II: Process Management and Scheduling

Process Scheduling
Subject
Operating Systems (24CS204)
Unit
Unit II: Process Management and Scheduling
Topic
2 of 14
Terms
Linked list, Interrupt, Swapping, Context switch

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Objective of multiprogramming: have some process running at all times to maximise CPU utilisation; time sharing — switch CPU among processes so frequently that users can interact. Process scheduler selects an available process for execution on the CPU
  • Scheduling queues
    • Job queue — all processes in the system
    • Ready queue — processes in main memory, ready and waiting to execute (linked list of PCBs: header with pointers to first and last PCB)
    • Device (I/O) queues — processes waiting for a particular I/O device (each device has its own)
  • Queueing diagram: a new process is put in the ready queue and waits until selected for execution (dispatched). Once running, one of the following: issues an I/O request → placed in an I/O queue; creates a new child process and waits for its termination; is removed forcibly from the CPU as a result of an interrupt (or time slice expiry) and put back in the ready queue; or waits for an event
  • Schedulers
    • Long-term scheduler (job scheduler): selects which processes should be brought into the ready queue (memory) from the pool on disk; invoked infrequently (seconds, minutes) → can be slow; controls the degree of multiprogramming; should select a good mix of I/O-bound (spends more time doing I/O than computation) and CPU-bound (more time computing) processes
    • Short-term scheduler (CPU scheduler): selects which process should be executed next and allocated the CPU; invoked very frequently (milliseconds) → must be fast
    • Medium-term scheduler: swapping — remove a process from memory (and from active contention for the CPU), store it on disk and reintroduce later to continue; reduces the degree of multiprogramming; useful when memory is overcommitted
  • Context switch: when the CPU switches to another process, the system must save the state of the old process (in its PCB) and load the saved state of the new process; context of a process is represented in the PCB (registers, process state, memory-management info). Context-switch time is pure overhead (system does no useful work); depends on hardware (memory speed, number of registers to copy, special instructions) — typically a few microseconds; some processors provide multiple register sets to cut it. Dispatcher performs it
Explanation

The OS keeps several queues: the job queue for all processes, the ready queue for those in memory waiting for the CPU, and a device queue for each device. A process moves between them.

There are three kinds of schedulers. The long-term scheduler picks jobs from disk to bring into memory and so controls the degree of multiprogramming. It runs rarely. The short-term (CPU) scheduler picks the next ready process for the CPU and runs very frequently, so it must be quick. The medium-term scheduler swaps processes out of and back into memory when memory is overloaded. A good long-term scheduler chooses a mix of I/O-bound and CPU-bound processes, so that both the CPU and the devices are busy.

A context switch saves the state of one process and restores the state of another. It is pure overhead because no useful work is done in that time, so it should be kept as small as possible.
