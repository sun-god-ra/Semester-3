Scheduling Criteria

Operating Systems · Unit II: Process Management and Scheduling

Scheduling Criteria
Subject
Operating Systems (24CS204)
Unit
Unit II: Process Management and Scheduling
Topic
8 of 14
Terms
Variance

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • CPU utilisation — keep the CPU as busy as possible (40 % lightly loaded to 90 % heavily loaded)
  • Throughput — number of processes completed per time unit
  • Turnaround time — interval from submission to completion = waiting to get into memory + waiting in ready queue + executing on the CPU + doing I/O
  • Waiting time — sum of periods spent waiting in the ready queue (scheduling affects only this, not the CPU burst or I/O time)
  • Response time — time from submission of a request until the first response is produced (not output complete) — important in interactive systems
  • Optimisation criteria: maximise CPU utilisation and throughput; minimise turnaround time, waiting time and response time (or minimise the variance of response time — predictability)

\[\text{TAT}=\text{CT}-\text{AT},\qquad \text{WT}=\text{TAT}-\text{BT},\qquad \text{RT}=\text{first CPU time}-\text{AT}\]

  • CT = completion time, AT = arrival time, BT = burst time
Explanation

A process alternates between CPU bursts and I/O bursts. The CPU scheduler picks a process from the ready queue when the CPU is idle. Scheduling is nonpreemptive when it happens only because the process ends or waits, and preemptive otherwise. The dispatcher hands the CPU to the chosen process, and the time taken is the dispatch latency.

The criteria are CPU utilisation, throughput, turnaround time, waiting time and response time. Turnaround time is completion time minus arrival time, waiting time is turnaround minus burst time, and response time is the time from arrival to the first CPU allocation.
