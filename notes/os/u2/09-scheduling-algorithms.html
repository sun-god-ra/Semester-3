Notebook notes
First-Come, First-Served (FCFS)
  • Nonpreemptive; implemented with a FIFO queue; the process that requests the CPU first is allocated the CPU first
  • Example (all arrive at 0): P1 = 24, P2 = 3, P3 = 3 (order P1, P2, P3)
| P1                       | P2 | P3 |
0                          24   27   30
  • Waiting times: P1 = 0, P2 = 24, P3 = 27 → average = (0+24+27)/3 = 17
    • If the order is P2, P3, P1: waiting 0, 3, 6 → average = 3. Much better — convoy effect: short processes stuck behind a long CPU-bound process (low CPU and device utilisation). FCFS is not suitable for time-sharing (nonpreemptive)
Shortest-Job-First (SJF)
  • Associate with each process the length of its next CPU burst; allocate the CPU to the process with the smallest next CPU burst; tie → FCFS. Provably optimal — gives minimum average waiting time for a given set of processes (moving a short process before a long one decreases the short's waiting time more than it increases the long's)
  • Difficulty: knowing the length of the next CPU request — cannot be known; used in long-term (job) scheduling with the user-specified time limit. For short-term scheduling: predict with exponential averaging:

\[\tau_{n+1}=\alpha\, t_n+(1-\alpha)\,\tau_n,\qquad 0\le\alpha\le 1\]

  • \(t_n\) = actual length of the \(n\)-th CPU burst; \(\tau_{n+1}\) = predicted value for the next burst; \(\alpha\) commonly ½. \(\alpha=0\): \(\tau_{n+1}=\tau_n\) (recent history has no effect); \(\alpha=1\): \(\tau_{n+1}=t_n\) (only the most recent burst matters). Expanding: \(\tau_{n+1}=\alpha t_n+(1-\alpha)\alpha t_{n-1}+\dots+(1-\alpha)^{n+1}\tau_0\) — older terms weigh less
  • Nonpreemptive SJF example (all arrive at 0): P1 = 6, P2 = 8, P3 = 7, P4 = 3
| P4 | P1    | P3      | P2        |
0    3       9         16          24
  • Waiting: P4 = 0, P1 = 3, P3 = 9, P2 = 16 → average = (0+3+9+16)/4 = 7; (FCFS would give 10.25)
  • Preemptive SJF = Shortest-Remaining-Time-First (SRTF): if a new process arrives with a CPU burst shorter than the remaining time of the running one → preempt. Example: P1 (AT 0, BT 8), P2 (1, 4), P3 (2, 9), P4 (3, 5)
| P1 | P2       | P4        | P1           | P3              |
0    1          5           10             17                26
  • Completion: P2 = 5, P4 = 10, P1 = 17, P3 = 26. Waiting = CT − AT − BT: P1 = 17−0−8 = 9, P2 = 5−1−4 = 0, P3 = 26−2−9 = 15, P4 = 10−3−5 = 2 → average = 26/4 = 6.5. (Nonpreemptive SJF would give 7.75)
    • Starvation is possible for long processes
Round-Robin (RR)
  • Designed for time-sharing: like FCFS but with preemption; each process gets a small unit of CPU time — time quantum (time slice) \(q\) — usually 10–100 ms; after \(q\), the process is preempted and added to the end of the ready queue. Ready queue is a circular queue; the scheduler goes around it, allocating the CPU to each process for up to one quantum. Timer interrupts after every quantum
  • If n processes and quantum q: each waits no more than \((n-1)q\) time units until its next quantum; each process gets \(1/n\) of the CPU time
  • Example: P1 = 24, P2 = 3, P3 = 3 (all at 0), q = 4
| P1 | P2 | P3 | P1 | P1 | P1 | P1 | P1 |
0    4    7    10   14   18   22   26   30
  • Waiting: P1 = 30−24 = 6; P2 = 7−3 = 4; P3 = 10−3 = 7 → average = 17/3 ≈ 5.67. Typically higher average turnaround than SJF but better response
  • Performance depends on quantum: \(q\) large → FCFS; \(q\) small → too many context switches (overhead) — \(q\) must be large with respect to the context-switch time (e.g., context switch 10 µs, q = 10 ms → 0.1 % overhead; context switch time should be < 10 % of the quantum). Rule of thumb: 80 % of CPU bursts should be shorter than \(q\). Average turnaround time does not necessarily improve as \(q\) increases
Priority Scheduling
  • A priority number (integer) is associated with each process; CPU is allocated to the process with the highest priority (smallest integer = highest priority by convention in the book; check the exam's convention!). SJF is priority scheduling where priority = inverse of predicted next CPU burst. Preemptive or nonpreemptive
  • Problem: starvation (indefinite blocking) — low-priority processes may never execute (rumour: when IBM 7094 at MIT shut down in 1973, a low-priority process submitted in 1967 had not yet run). Solution: aging — gradually increase the priority of processes that wait in the system for a long time
  • Example (all at 0; lower number = higher priority): P1 (10, pr 3), P2 (1, pr 1), P3 (2, pr 4), P4 (1, pr 5), P5 (5, pr 2)
| P2 | P5    | P1         | P3  | P4 |
0    1       6            16    18   19
  • Waiting: P2 = 0, P5 = 1, P1 = 6, P3 = 16, P4 = 18 → average = 41/5 = 8.2
  • Priority + Round-Robin: run the highest-priority process; processes with the same priority use RR
Multilevel Queue Scheduling
  • The ready queue is partitioned into separate queues (e.g., foreground (interactive) and background (batch)); a process is permanently assigned to one queue, based on a property (memory size, priority, process type). Each queue has its own scheduling algorithm — foreground: RR; background: FCFS. Scheduling among the queues — fixed-priority preemptive (serve all foreground, then background → starvation possible) or time slice among queues (e.g. 80 % to foreground in RR, 20 % to background in FCFS)
  • Typical queues from highest priority: real-time processes → system processes → interactive processes → interactive editing processes → batch processes → student processes
Multilevel Feedback Queue Scheduling
  • A process can move between queues (aging can be implemented this way). Idea: separate processes by CPU-burst characteristics — if a process uses too much CPU time, move it to a lower-priority queue; I/O-bound and interactive processes stay in higher-priority queues; a process that waits too long in a lower queue may be moved to a higher queue (prevents starvation)
  • Parameters that define an MLFQ scheduler: number of queues; scheduling algorithm for each queue; method to upgrade a process; method to demote a process; method to determine which queue a process enters when it needs service. Most general (can be configured to match any system) but most complex
  • Example: three queues — Q0: RR, q = 8 ms; Q1: RR, q = 16 ms; Q2: FCFS. A new job enters Q0; if it does not finish in 8 ms it is moved to Q1; at Q1, if it does not complete in 16 ms, it is preempted and moved to Q2. Q1 is served only when Q0 is empty; Q2 only when Q0 and Q1 are empty
Algorithm Preemptive? Starvation? Notes
FCFS no no convoy effect, simple
SJF no yes optimal avg. waiting; needs burst prediction
SRTF yes yes preemptive SJF
RR yes no good response; depends on quantum
Priority both yes (aging cures)
Multilevel queue usually yes yes fixed assignment
MLFQ yes no (with aging) flexible, complex
Explanation

FCFS serves in order of arrival. It is simple, but the average waiting time is often long and a short job waits behind a long job (convoy effect). In the example (24, 3, 3) the average wait is 17; if the order were 3, 3, 24 it would be 3.

SJF picks the shortest next burst and is optimal for the average waiting time. Since the next burst length cannot be known, it is predicted by exponential averaging \(\tau_{n+1}=\alpha t_n+(1-\alpha)\tau_n\). The preemptive version, SRTF, preempts when a new process arrives with a burst shorter than the remaining time of the running one. In the example, the processes P1 to P4 have waiting times 9, 0, 15, 2 and the average is 6.5. Long jobs may starve.

Round robin gives every process a time quantum and moves it to the back of the queue when the quantum ends. With a very large quantum it behaves like FCFS and with a very small one it spends too much time in context switches. The usual rule is that 80% of CPU bursts should be shorter than the quantum. For the example with q=4, the waits are 6, 4, 7 and the average is 5.67.

Priority scheduling gives the CPU to the highest priority (lowest number, in this book). Low-priority processes may starve, and the cure is aging, which slowly raises the priority of a waiting process. For the example the average is 8.2.

Multilevel queue scheduling splits the ready queue into queues for foreground and background and so on, each with its own algorithm, and a process stays in its queue. Multilevel feedback queue allows a process to move between the queues: a process that uses too much CPU time moves down, and one that waits too long moves up. In the example, Q0 has RR with a quantum of 8, Q1 has RR with 16 and Q2 has FCFS.
