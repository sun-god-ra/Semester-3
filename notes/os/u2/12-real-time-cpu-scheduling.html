Real-Time CPU Scheduling

Operating Systems · Unit II: Process Management and Scheduling

Real-Time CPU Scheduling
Subject
Operating Systems (24CS204)
Unit
Unit II: Process Management and Scheduling
Topic
12 of 14
Terms
Real-time, Interrupt, Kernel, Critical section, POSIX, FCFS

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Soft real-time systems: no guarantee as to when a critical real-time process will be scheduled; guarantee only that the critical process is given preference over noncritical ones. Hard real-time systems: a task must be serviced by its deadline; service after the deadline = no service at all (anti-lock brakes, nuclear plant control, avionics)
  • Minimising latency: event-driven; event latency = time from occurrence of an event to service of the event. Two types: interrupt latency (time from arrival of interrupt at the CPU to the start of the ISR — includes determining the interrupt type, saving the current process's state, and interrupts being disabled in kernel critical sections — must be bounded for hard real-time systems) and dispatch latency (time for the scheduler's dispatcher to stop one process and start another — has conflict phase: preemption of any process running in kernel mode + release by low-priority processes of resources needed by a high-priority process — and dispatch phase: scheduling the high-priority process onto an available CPU). Solution: preemptive kernels
  • Priority-based scheduling: real-time OS must support a priority-based algorithm with preemption; guarantees only soft real-time; for hard real time, additionally need to guarantee deadlines. A periodic process requires the CPU at constant intervals (periods): processing time \(t\), deadline \(d\) (must be serviced by), period \(p\), with \(0\le t\le d\le p\); rate of a periodic task = \(1/p\). The process announces its deadline requirements to the scheduler → admission control: the scheduler either admits the process, guaranteeing it will complete on time, or rejects it
  • Rate-Monotonic Scheduling (RMS): schedules periodic tasks using a static priority policy with preemption; each periodic task is assigned a priority inversely based on its period — shorter period = higher priority; assumes the processing time of a periodic process is the same for each CPU burst. Optimal among static-priority algorithms — if a set of processes cannot be scheduled by RMS, no other static-priority algorithm can
    • Schedulability test (sufficient, not necessary): for \(N\) processes, CPU utilisation \(\sum t_i/p_i \le N(2^{1/N}-1)\) ; as \(N\to\infty\) the bound → ln 2 ≈ 69 %; \(N=1\): 100 %; \(N=2\): 82.8 %; \(N=3\): 78.0 %
    • Example 1 (RMS meets deadlines): P1: \(p_1=50\), \(t_1=20\); P2: \(p_2=100\), \(t_2=35\). Utilisation = 20/50 + 35/100 = 0.4 + 0.35 = 0.75 ≤ 0.828 → schedulable. P1 has higher priority (shorter period): P1 runs 0–20, P2 20–50 (30 done, preempted at 50), P1 50–70, P2 70–75 (finishes 35 total), idle until 100…
    • Example 2 (RMS fails): P1: \(p=50\), \(t=25\); P2: \(p=80\), \(t=35\). Utilisation = 0.5 + 0.4375 = 0.9375 > 0.828 → RMS misses deadline of P2 (P2 would need 35 units by time 80, but P1 uses 25 of every 50: only 5+25... P2 gets 25 units in 25–50, then P1 50–75, P2 75–80 gets 5 → 30 total < 35 at time 80 → deadline missed). But EDF can schedule it as \(U=0.9375\le 1\)
  • Earliest-Deadline-First (EDF) Scheduling: assigns priorities dynamically according to deadlines: earlier deadline = higher priority; when a process becomes runnable, it must announce its deadline; priorities adjusted. Theoretically optimal — can schedule processes so that each meets its deadline and CPU utilisation is 100 % (\(\sum t_i/p_i\le 1\)); not practical because of context-switching cost and the impossibility of reaching 100 %. Does not require periodic processes or constant burst time
  • Proportional share scheduling: allocate \(T\) shares among all applications; an application receiving \(N\) shares is assured \(N/T\) of total processor time; needs admission control (don't admit if not enough shares). POSIX real-time scheduling: SCHED_FIFO (FCFS with no time slicing among equal priority), SCHED_RR (like FIFO but time slicing among equal priority), pthread_attr_setschedpolicy()
Explanation

A soft real-time system gives only preference to critical processes, while in a hard real-time system a missed deadline is a failure. Latency has two parts: interrupt latency, which is the time from the arrival of an interrupt to the start of its service routine, and dispatch latency, which is the time the dispatcher takes to stop one process and start another.

For periodic tasks with processing time \(t\), deadline \(d\) and period \(p\), rate-monotonic scheduling gives a fixed priority by period (shorter period is higher priority) and is optimal among the static-priority methods. A set is guaranteed schedulable if the utilisation \(\sum t_i/p_i\le N(2^{1/N}-1)\), which is 82.8% for two tasks and tends to 69% for many. P1 (period 50, time 20) and P2 (period 100, time 35) use 75%, so RMS works. P1 (50, 25) and P2 (80, 35) use 93.75%: RMS misses P2's deadline, because by time 80 P2 gets only 30 units, while EDF can still meet the deadlines because EDF only needs utilisation ≤ 1. EDF gives the higher priority to the earlier deadline, dynamically, and can reach 100% utilisation in theory. Proportional share scheduling gives each application a number of shares out of T total shares, and needs admission control.
