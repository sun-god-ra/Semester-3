Process Concept

Operating Systems · Unit II: Process Management and Scheduling

Process Concept
Subject
Operating Systems (24CS204)
Unit
Unit II: Process Management and Scheduling
Topic
1 of 14
Terms
Process control block, Page table, Interrupt, Context switch

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Process = a program in execution; the unit of work in a modern time-sharing system. Program = passive entity (executable file on disk); process = active entity with a program counter and set of resources. One program can be several processes (e.g. several users running the same editor)
  • Parts of a process in memory
    • Text section — program code
    • Data section — global variables
    • Heap — memory dynamically allocated at run time (malloc) — grows up
    • Stack — temporary data when calling functions (parameters, return addresses, local variables) — grows down
    • plus the program counter (PC) and processor registers
  • Process states
    • New — being created
    • Ready — waiting to be assigned to a processor
    • Running — instructions are being executed
    • Waiting (blocked) — waiting for some event (I/O completion, signal)
    • Terminated — finished execution
  • Only one process can be running on any processor at a time, but many may be ready or waiting
  • Process Control Block (PCB / task control block) — OS representation of a process; contains: process state, program counter, CPU registers, CPU-scheduling information (priority, pointers to queues), memory-management information (base/limit registers, page tables), accounting information (CPU used, clock time, time limits, process numbers), I/O status information (list of open files, devices allocated). In Linux the PCB is task_struct
  • Threads: a process can have multiple threads of execution — the PCB then includes thread info
Explanation

A program is just a file on disk; a process is a program in execution. It has a text section (the code), a data section (global variables), a heap (memory given at run time, growing upwards) and a stack (function calls, local variables, growing downwards), plus the current value of the program counter and the registers.

A process changes state as it runs. It is new when created, ready when it is waiting for the CPU, running when it has the CPU, waiting when it is waiting for an event such as I/O completion, and terminated at the end. A running process goes back to ready if its time slice expires (an interrupt), and to waiting if it asks for I/O. When the I/O completes, it goes to ready, not directly to running. Only one process can run on a CPU at an instant.

The OS keeps all information about a process in its process control block (PCB): state, program counter, registers, scheduling information, memory-management information, accounting information and I/O status. During a context switch, the OS saves the PCB of the old process and loads the PCB of the new one.
