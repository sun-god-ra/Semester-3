Notebook notes
  • Aim: Get familiar with the Xilinx Spartan-6 FPGA design flow, and implement logic gates and combinational circuits (adder, multiplexer, decoder, comparator) using Verilog (or VHDL) on the board.
  • Components: A Spartan-6 FPGA board (for example Digilent Nexys 3 / Atlys with XC6SLX16 / XC6SLX45), Xilinx ISE Design Suite (ISE 14.7 is the last version that supports Spartan-6; Vivado does not), USB-JTAG cable, PC
  • Theory
    • FPGA (field-programmable gate array) = array of configurable logic blocks (CLBs) connected through a programmable interconnect, surrounded by I/O blocks (IOBs); reconfigurable after manufacture (unlike an ASIC). Spartan-6: each slice has four 6-input LUTs (each can be used as two 5-input LUTs) and eight flip-flops; block RAM (18 Kb), DSP48A1 multiplier-accumulator blocks, clock management (DCM/PLL), SelectIO™ interfaces. A LUT (look-up table) is a small memory that stores the truth table of any function of its inputs
    • Design flow: (1) design entry (HDL — Verilog/VHDL — or schematic) → (2) behavioural simulation (ISim) with a test bench → (3) synthesis (XST: RTL → gate netlist) → (4) implementation: translate (NGDBuild) → map (to LUTs/slices) → place and route → (5) timing analysis → (6) generate programming file (.bit) → (7) configure the device with iMPACT over JTAG. Constraints file (.ucf) assigns the signals to physical pins and sets I/O standards
    • Steps in ISE: File → New Project (select family Spartan6, the device, package and speed grade of the board; preferred language Verilog) → New Source (Verilog module) → write code → add test bench (simulation) → run behavioural simulation → add the .ucf → Synthesize → Implement Design → Generate Programming File → Configure Target Device (iMPACT)
    • HDL vs C: HDL describes concurrent hardware — all the assign statements and gate instances work in parallel; always @(*) describes combinational logic, always @(posedge clk) describes registers
  • Procedure
    • Open ISE, create a new project for the board's device
    • Write the Verilog module (below), create a test bench and simulate; compare with the truth table
    • Create the .ucf file: map the inputs to the slide switches, and the outputs to the LEDs (take the pin locations from the board's reference manual)
    • Synthesize, implement, generate the .bit file and download it with iMPACT; test with the switches
verilog
// Task 12 design: gates, half adder, full adder, 4x1 mux, 2x4 decoder, 2-bit comparator on one FPGA
module fpga_demo(
    input  a, b, c,              // switches SW0, SW1, SW2
    input  [1:0] x, y,           // switches SW3..SW6
    output y_and, y_or, y_xor, y_nand,
    output fa_sum, fa_cout,
    output [3:0] dec,
    output gt, eq, lt
);
    assign y_and  = a & b;
    assign y_or   = a | b;
    assign y_xor  = a ^ b;
    assign y_nand = ~(a & b);
    assign {fa_cout, fa_sum} = a + b + c;                 // full adder
    assign dec = 4'b0001 << x;                            // 2x4 decoder
    assign gt = (x > y), eq = (x == y), lt = (x < y);     // 2-bit comparator
endmodule

A sample .ucf (the LOC pin names below are placeholders; take the real ones from your board's reference manual):

text
NET "a"      LOC = "T10" | IOSTANDARD = LVCMOS33;   # SW0  (example only)
NET "b"      LOC = "T9"  | IOSTANDARD = LVCMOS33;   # SW1  (example only)
NET "y_and"  LOC = "U16" | IOSTANDARD = LVCMOS33;   # LD0  (example only)

Every gate and combinational circuit of experiments 1–6 can be loaded in the same way; reuse the Verilog modules of those experiments.

  • Precautions: switch off the supply before changing wiring; check Vcc/GND; tie unused inputs; confirm LED polarity; no loose wires
  • Result: the observed outputs matched the truth table, so the circuit works as the theory predicts
  • Viva questions
    • What is an FPGA? How is it different from a CPLD and an ASIC?
    • What is a LUT? How many inputs does a Spartan-6 LUT have? (6)
    • Explain the FPGA design flow
    • What is the use of the UCF file?
    • Why can't we use Vivado for Spartan-6? (Vivado supports 7-series and later)
Explanation

An FPGA implements logic with LUTs instead of gates: a 6-input LUT is a 64-bit memory that holds the truth table of any function of up to six variables. The tools convert your Verilog to a netlist (synthesis), map it to LUTs and flip-flops, place them on the chip, route the connections, and create a bit file to load into the FPGA. The UCF file connects the names in your design to the real pins of the chip. In Verilog, assign statements all run at the same time, since they describe hardware, not a program. In the demo module, a + b + c is a full adder, the shift 4'b0001 << x is a 2×4 decoder, and the relational operators make a comparator. The pin names given are only examples, because the actual LOC assignments depend on the board.
