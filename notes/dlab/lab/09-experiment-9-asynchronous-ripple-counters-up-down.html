Experiment 9 — Asynchronous (ripple) counters: up, down and MOD-N

Digital Logic Design Lab · Lab: Tasks 1 to 12

Experiment 9 — Asynchronous (ripple) counters: up, down and MOD-N
Subject
Digital Logic Design Lab (24CS282)
Unit
Lab: Tasks 1 to 12
Topic
9 of 12
Terms
Ripple counter, NAND, Flip-flop, Propagation delay, Verilog
Notebook notes
  • Aim: Design and verify 3-bit asynchronous up and down counters and a MOD-6 counter.
  • Components: IC 7476 / 7473 (JK) or 7474 (D), 7400 (NAND) for the reset; (ready-made: 7490 decade, 7493 4-bit ripple counter); clock pulser, LEDs
  • Theory
    • In an asynchronous (ripple) counter only the first flip-flop gets the external clock; each next flip-flop is clocked by the output of the previous one. Flip-flops are JK with J=K=1 (or T flip-flops, or D with D = Q')
    • Up counter: negative-edge triggered flip-flops, clock of stage \(n\) = \(Q_{n-1}\). Down counter: clock of stage \(n\) = \(\overline{Q}_{n-1}\) (or use positive-edge FFs and connect Q of the previous stage)
    • MOD-N by asynchronous reset: use a NAND gate to detect the count N and connect its output to the active-low Clear inputs of all FFs; the counter jumps to 0 immediately when N appears (it exists only for a very short time — a glitch). MOD-6: the state 6 = 110, so detect \(Q_2Q_1\) (use NAND of \(Q_2\), \(Q_1\)). With 7490: connect \(Q_B\) and \(Q_C\) to the reset inputs R0(1), R0(2)
    • Disadvantage of ripple counters: the propagation delays add, so at high frequency the count is wrong momentarily (decoding glitches); the maximum clock frequency \(f_{max}=1/(n\cdot t_{pd})\). Advantage: simple hardware
  • Procedure
    • Connect the pulse to CLK of the first flip-flop; connect Q of the first to CLK of the second, and so on; J=K=1 (high); Clear all initially
    • Give pulses; record the outputs; for the down counter connect Q' instead of Q
    • For MOD-6 add the NAND gate from Q2, Q1 to the Clear lines; check the 0–5 cycle
verilog
// Task 9: asynchronous (ripple) counters
module tff_async(input clk, clr, output reg q);       // T flip-flop with T=1, async clear
  always @(negedge clk or posedge clr)
    if (clr) q <= 1'b0;
    else q <= ~q;
endmodule

// 3-bit ripple UP counter: clock of each stage = Q of previous stage
module ripple_up(input clk, clr, output [2:0] q);
  tff_async a(clk,  clr, q[0]);
  tff_async b(q[0], clr, q[1]);
  tff_async c(q[1], clr, q[2]);
endmodule

// 3-bit ripple DOWN counter: clock of each stage = Q' of previous stage
module ripple_down(input clk, clr, output [2:0] q);
  tff_async a(clk,   clr, q[0]);
  tff_async b(~q[0], clr, q[1]);
  tff_async c(~q[1], clr, q[2]);
endmodule

// MOD-6 ripple counter: NAND of Q2 and Q1 clears all flip-flops when the count 110 (6) appears
module ripple_mod6(input clk, rst, output [2:0] q);
  wire clr = (q[2] & q[1]) | rst;          // rst = manual clear switch (power-on)
  tff_async a(clk,  clr, q[0]);
  tff_async b(q[0], clr, q[1]);
  tff_async c(q[1], clr, q[2]);
endmodule

  • Precautions: switch off the supply before changing wiring; check Vcc/GND; tie unused inputs; confirm LED polarity; no loose wires
  • Result: the observed outputs matched the truth table, so the circuit works as the theory predicts
  • Viva questions
    • Why are the counters called ripple counters?
    • Compare asynchronous and synchronous counters
    • How many flip-flops are needed for a MOD-10 counter? (4) How is it made using a 7490?
    • What is a decoding glitch?
    • Frequency division: input 8 kHz, 3-bit counter, frequency at the MSB output? (1 kHz)
Explanation

For the ripple counter, each stage divides the frequency of the previous output by 2. Stage 0 toggles at every clock pulse, and stage 1 toggles every time Q0 falls, and so on. This works like a binary counter, but the delay accumulates. For the down counter the next stage is clocked by Q' of the previous stage, so the count goes 000, 111, 110, ... For the MOD-6 counter the NAND gate detects 110 and resets all the flip-flops. In the simulated table, the circuit reaches 110 for a moment (it is shown cleared to 000 at the sixth pulse). In the real circuit this causes a short glitch on the outputs.
