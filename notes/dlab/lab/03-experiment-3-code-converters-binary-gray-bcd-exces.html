Experiment 3 — Code converters: Binary ↔ Gray, BCD ↔ Excess-3

Experiment 3 — Code converters: Binary ↔ Gray, BCD ↔ Excess-3
Subject
Digital Logic Design Lab (24CS282)
Unit
Lab: Tasks 1 to 12
Topic
3 of 12
Terms
XOR, Excess-3, BCD, K-map, Gray code, Encoder, Verilog
Notebook notes
  • Aim: Design and implement a 4-bit binary-to-Gray converter and a Gray-to-binary converter, and BCD-to-Excess-3 and Excess-3-to-BCD converters.
  • Components: IC 7486 (XOR), 7408, 7432, 7404, 7483 (optional for ±3); trainer kit
  • Theory
    • Binary → Gray: \(G_3=B_3\), \(G_2=B_3\oplus B_2\), \(G_1=B_2\oplus B_1\), \(G_0=B_1\oplus B_0\) (3 XOR gates). Gray → binary: \(B_3=G_3\), \(B_2=B_3\oplus G_2\), \(B_1=B_2\oplus G_1\), \(B_0=B_1\oplus G_0\) (3 XOR gates, cascaded)
    • BCD → Excess-3: add 3 (0011) to each BCD digit; inputs 1010–1111 are don't-cares. With K-map simplification: \(X_3=B_3+B_2(B_1+B_0)\), \(X_2=\overline{B_2}(B_1+B_0)+B_2\overline{B_1}\,\overline{B_0}\), \(X_1=\overline{B_1\oplus B_0}\), \(X_0=\overline{B_0}\)
    • Excess-3 → BCD: subtract 3 from the 4-bit input; inputs 0000–0010 and 1101–1111 are invalid (don't-cares). Alternatively add 1101 (−3 in 4 bits) with a 7483 adder
    • Gray code has only one bit change between consecutive numbers (used in encoders and K-maps); Excess-3 is a self-complementing code
  • Procedure
    • Wire the three XOR gates for binary→Gray; verify all 16 inputs
    • Wire the cascaded XORs for Gray→binary and verify it returns the original binary
    • Wire BCD→XS-3 using the equations (or 7483 with the second operand wired as 0011); verify for 0–9
    • Wire XS-3→BCD (7483 with operand 1101 and ignore the carry) and verify
verilog
// Task 3: code converters
module bin2gray(input [3:0] b, output [3:0] g);
  assign g[3] = b[3];
  assign g[2] = b[3] ^ b[2];
  assign g[1] = b[2] ^ b[1];
  assign g[0] = b[1] ^ b[0];
endmodule

module gray2bin(input [3:0] g, output [3:0] b);
  assign b[3] = g[3];
  assign b[2] = b[3] ^ g[2];
  assign b[1] = b[2] ^ g[1];
  assign b[0] = b[1] ^ g[0];
endmodule

// BCD to Excess-3: add 3 (0011)
module bcd2xs3(input [3:0] b, output [3:0] x);
  assign x[3] = b[3] | (b[2] & (b[1] | b[0]));
  assign x[2] = (~b[2] & (b[1] | b[0])) | (b[2] & ~b[1] & ~b[0]);
  assign x[1] = ~(b[1] ^ b[0]);
  assign x[0] = ~b[0];
endmodule

// Excess-3 to BCD: subtract 3
module xs32bcd(input [3:0] x, output [3:0] b);
  assign b = x - 4'd3;
endmodule

  • Viva questions
    • What is the Gray code of 1010? (1111)
    • Why is Gray code useful? (one bit changes at a time, no glitches)
    • Is Excess-3 a weighted code? (no) Why is it self-complementing? (9's complement by inverting bits)
    • How many don't-care states in BCD to XS-3? (6)
    • Gray to binary of 1111? (1010)
Explanation

For binary to Gray, the MSB is copied, and each next Gray bit is the XOR of two adjacent binary bits. In the output, each next Gray code differs from the previous by one bit, for example 7 is 0100 and 8 is 1100, which differ only in the MSB. For Gray to binary, each binary bit is the XOR of the previous binary bit and the current Gray bit, which is why the XORs are cascaded. The third column of the first table shows that the double conversion gives back the input. BCD to Excess-3 adds 3 to the digit, for example 5 (0101) becomes 8 (1000), and 9 (1001) becomes 12 (1100). The second table shows both conversions; the circuit for XS-3 → BCD subtracts 3 and returns the original digit.
