Basis Path Testing (Tom McCabe)

Software Engineering · Unit V: Software Testing

Basis Path Testing (Tom McCabe)
Subject
Software Engineering (24CS203)
Unit
Unit V: Software Testing
Topic
10 of 12
Terms
Cyclomatic complexity, Basis path testing

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • Lets the designer derive a logical complexity measure of a procedural design and use it to define a basis set of execution paths; test cases for the basis set guarantee execution of every statement at least once
  • Flow graph notation: a notation for control flow: node (circle) = one or more procedural statements (a sequence of process boxes and a decision diamond can map into a single node); edge (link) = flow of control; region = area bounded by edges and nodes (outside area counted as a region); predicate node = node that contains a condition (≥ 2 outgoing edges). Compound conditions (a OR b) → separate predicate nodes for each simple condition
  • Independent path: any path through the program that introduces at least one new set of processing statements or a new condition (i.e. traverses at least one new edge not in any other path)
  • Cyclomatic complexity \(V(G)\) — a software metric giving a quantitative measure of the logical complexity; gives the number of independent paths in the basis set → upper bound on the number of tests to ensure each statement executes at least once. Three ways (all equal)

\[V(G)=E-N+2,\qquad V(G)=P+1,\qquad V(G)=\text{number of regions}\]

  • \(E\) = number of edges, \(N\) = number of nodes, \(P\) = number of predicate nodes
  • Interpretation: \(V(G)\): 1–10 simple, low risk; 11–20 moderate; 21–50 complex, high risk; >50 untestable
Example
1  read(n)
2  while (n > 0) {
3     if (n % 2 == 0)
4         even++;
5     else
6         odd++;
7     n--;
   }
8  print(even, odd)
  • Nodes: 1, 2, 3, 4, 5, 6 (=7 merged: 1 read; 2 while; 3 if; 4 even++; 5 odd++; 6 n--; 7 print)
  • \(N=7\), \(E=8\) (1→2, 2→3, 2→7, 3→4, 3→5, 4→6, 5→6, 6→2); predicate nodes \(P=2\) (nodes 2 and 3); regions \(=3\)
  • \(V(G)=8-7+2=3\) \(=2+1=3\) \(=3\) ✓
  • Basis set (3 independent paths):
    • Path 1: 1-2-7 (n ≤ 0)
    • Path 2: 1-2-3-4-6-2-7 (n even)
    • Path 3: 1-2-3-5-6-2-7 (n odd)
  • Deriving test cases: (1) draw the flow graph from the design or code; (2) determine \(V(G)\); (3) determine a basis set of linearly independent paths; (4) prepare test cases that force execution of each path
    • TC1: n = 0 → prints 0 0 (path 1). TC2: n = 2 → loop once, even → 1 0 (path 2). TC3: n = 1 → odd → 0 1 (path 3)
  • Graph matrices: a square matrix with size = number of nodes; entry = link weight (1 if connection exists; or probability, processing time, memory…). Connection matrix: add 1 to each entry where a link exists; sum of each row − 1 = number of decisions; \(V(G)\) = (sum of (row connections − 1) for rows with > 1) + 1. Used for automated tools
Explanation

Basis path testing finds a set of independent paths through the code. A flow graph draws the control flow with nodes for statements and edges for the flow of control. An independent path is a path that includes at least one edge that has not been used in any other path. The cyclomatic complexity of the graph tells how many independent paths there are. It can be calculated in three ways: the number of edges minus the number of nodes plus 2; the number of decision (predicate) nodes plus 1; or the number of regions of the graph. For the example, there are 8 edges and 7 nodes, so \(V(G)=8-7+2=3\). There are two predicate nodes, so \(V(G)=2+1=3\), and the graph has 3 regions. The three independent paths are: skip the loop, go around once through the even branch, and go around once through the odd branch. One test per path guarantees that every statement is executed at least once. The complexity number is also a risk indicator: values above about 10 mean the module is getting too complex to test and maintain easily.
