Internal and External Views of Testing

Software Engineering · Unit V: Software Testing

Internal and External Views of Testing
Subject
Software Engineering (24CS203)
Unit
Unit V: Software Testing
Topic
8 of 12
Terms
Black-box testing, Equivalence partitioning, White-box testing

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • Any engineered product can be tested in two ways
    • External view — black-box testing: knowing the specified function that a product has been designed to perform, tests demonstrate that each function is fully operational while at the same time searching for errors in each function. Tests conducted at the software interface
    • Internal view — white-box (glass-box) testing: knowing the internal workings of a product, tests ensure that internal operations are performed according to specifications and that all internal components have been adequately exercised. Logical paths through the code
Black-box White-box
Knowledge of code not needed required
Based on requirements / specification code structure
Also called behavioral, functional, external structural, glass-box, internal
Tester tester, user (no coding) developer
Finds missing functions, interface errors, performance, initialisation and termination errors, incorrect or missing functions logic errors, wrong assumptions, typographical errors, unreachable code, incorrect paths
Performed later stages (validation, system) earlier stages (unit)
Techniques equivalence partitioning, BVA, graph-based, orthogonal array basis path, condition, data flow, loop testing
  • They are complementary; gray-box testing = a mix
Explanation

Black-box testing treats the software as a box whose inside cannot be seen. It uses the specification to prove that each function works and looks for errors at the interface. White-box testing uses knowledge of the internal structure to ensure that all paths, decisions and loops have been exercised. They are complementary: black-box tests find missing functions and interface errors that white-box tests cannot, because the missing code is not there to test, and white-box tests find logic errors and unreachable code that black-box tests may not reach.
