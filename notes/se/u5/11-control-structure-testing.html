Control Structure Testing

Software Engineering · Unit V: Software Testing

Control Structure Testing
Subject
Software Engineering (24CS203)
Unit
Unit V: Software Testing
Topic
11 of 12

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • Variations that broaden test coverage and improve quality (beyond basis path)
  • Condition testing: a test case design method that exercises the logical conditions in a program module. Simple condition = Boolean variable or relational expression; compound condition = simple conditions joined by &&, ||, !. Detects errors in Boolean operators, Boolean variables, parentheses, relational operators, arithmetic expressions. Branch testing: each true and false branch executed at least once. Domain testing (three or four tests for a relational expression E1 < E2: greater, equal, less)
  • Data flow testing: selects test paths according to the locations of definitions and uses of variables. DEF(S) = set of variables defined in statement S; USE(S) = set used. A definition–use (DU) chain of variable X is [X, S, S'] if X ∈ DEF(S) and X ∈ USE(S') and the definition of X in S is live at S'. Test: every DU chain covered at least once
  • Loop testing: focuses exclusively on the validity of loop constructs. Four classes
    • Simple loops (n = max allowable passes): skip the loop entirely; only one pass; two passes; \(m\) passes where \(m<n\); \(n-1\), \(n\), \(n+1\) passes
    • Nested loops: start at the innermost loop, set all other loops to minimum values; conduct simple-loop tests for the innermost while holding outer loops at minimum iteration; work outward; continue until all loops tested (otherwise number of tests grows geometrically)
    • Concatenated loops: independent → test as simple loops; dependent (the counter of loop 1 is used for loop 2) → treat as nested
    • Unstructured loops: redesign (structured programming constructs), then test
Explanation

Condition testing exercises the logical conditions of the program, including the Boolean operators and relational operators, so that each condition takes both true and false values. Data flow testing follows the variables: it selects paths based on where variables are defined and used, to ensure that every definition-use chain is exercised. Loop testing checks the loops. For a simple loop with at most \(n\) passes, the tests are: skip the loop, one pass, two passes, a typical number \(m\), and \(n-1\), \(n\) and \(n+1\) passes. For nested loops, begin with the innermost loop while the outer ones are at their minimum, and work outwards; this prevents the number of tests from growing geometrically.
