A Strategic Approach to Software Testing

Software Engineering · Unit V: Software Testing

A Strategic Approach to Software Testing
Subject
Software Engineering (24CS203)
Unit
Unit V: Software Testing
Topic
1 of 12
Terms
Debugging

Practice: Part B questions for Unit V and Part A short questions.

Notebook notes
  • Testing = process of executing a program with the intent of finding errors. A good test has a high probability of finding an as-yet-undiscovered error. Debugging = finding and fixing the cause after a test fails
  • A testing strategy provides a template (road map): what steps, when planned and undertaken, how much effort, time, resources
  • Generic characteristics of a testing strategy
    • to perform effective testing, conduct effective technical reviews first (many errors removed before testing)
    • testing begins at the component level and works outward toward integration of the entire system
    • different techniques are appropriate for different approaches and at different times
    • testing is conducted by the developer and (for large projects) an independent test group (ITG)
    • testing and debugging are different, but debugging must be accommodated in any strategy
  • Verification and Validation (V&V)
    • Verification: "Are we building the product right?" — set of tasks that ensure software correctly implements a specific function (conformance to specification; reviews, inspections)
    • Validation: "Are we building the right product?" — ensures that the software traceable to customer requirements (meets user needs; testing)
    • Together = software quality assurance (SQA): reviews, audits, standards, testing

right product built right? right product?
static: reviews, walkthroughs, inspections dynamic: testing the running software
done before validation after verification
checks against specification checks against user needs
errors found early errors found late
Explanation

Testing is the activity of running the program in order to find errors. A good test is one with a high chance of finding an error that has not yet been found, and a successful test is one that uncovers such an error. It follows that testing can show the presence of defects but never their absence. Debugging is a separate activity: it starts after a test has failed and looks for the cause of the failure and corrects it.

A testing strategy is a plan that tells what is to be tested, in what order, by whom, and with what resources. Good strategies begin with technical reviews, because many errors can be removed more cheaply before any test is run, begin testing with the individual components and move outwards to the whole system, and use different techniques at different times.

Verification and validation are often confused. Verification asks whether we are building the product right, which means checking that it correctly implements the specification. This is done mostly by reviews and inspections of work products. Validation asks whether we are building the right product, which means checking that the product meets what the customer actually needs and is done by testing the running software.
