The Software Process

Software Engineering · Unit I: Process Models and Agile Development

The Software Process
Subject
Software Engineering (24CS203)
Unit
Unit I: Process Models and Agile Development
Topic
3 of 13

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Process = framework of activities, actions and tasks needed to build quality software
  • Hierarchy: process framework → framework activities → actions → tasks
  • Generic process framework — five framework activities
    1. Communication — talk with customer/stakeholders; gather requirements
    2. Planning — "map" of the journey: tasks, risks, resources, work products, schedule
    3. Modeling — create models (analysis and design) to understand requirements and design
    4. Construction — code generation and testing
    5. Deployment — deliver to the customer; feedback
  • Umbrella activities (applied throughout the process): software project tracking and control, risk management, software quality assurance, technical reviews, measurement, software configuration management, reusability management, work product preparation and production
  • Process flow (how activities are organised in sequence)
    • Linear — one after another
    • Iterative — repeat one or more before moving on
    • Evolutionary — circular, each circuit gives a more complete version
    • Parallel — some activities execute concurrently
  • Task set defines the work to be done (adapts to project size, complexity, team)
  • Process patterns, process assessment (SCAMPI, CBA IPI, SPICE ISO/IEC 15504, ISO 9001:2000)
  • CMMI (Capability Maturity Model Integration) — levels: 1 Initial, 2 Managed, 3 Defined, 4 Quantitatively Managed, 5 Optimizing
Explanation

A software process is a collection of work activities, actions and tasks performed to create software. The generic framework consists of five activities: communication, planning, modeling, construction and deployment. These apply to any project, large or small, and are adapted to it by choosing the actions and tasks. Alongside them run the umbrella activities, such as project tracking, risk management, quality assurance, reviews, measurement and configuration management, which are needed throughout the project and not at one stage only.

The process flow describes how these activities are arranged in time. In a linear flow they are executed one after another. In an iterative flow, one or more activities are repeated before moving on. In an evolutionary flow they are executed in a circular manner, giving a more complete version of the software with each circuit, and in a parallel flow some activities are carried out at the same time as others. CMMI measures the maturity of an organisation's process on five levels from the chaotic Initial level to the Optimizing level, where the process is continuously improved.
