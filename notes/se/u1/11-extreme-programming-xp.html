Extreme Programming (XP)

Software Engineering · Unit I: Process Models and Agile Development

Extreme Programming (XP)
Subject
Software Engineering (24CS203)
Unit
Unit I: Process Models and Agile Development
Topic
11 of 13
Terms
Agile, Crc card, Refactoring, Continuous integration, Extreme programming

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Most widely used agile method (Kent Beck). Object-oriented approach. Values: communication, simplicity, feedback, courage, respect
  • XP process — four framework activities
  • Planning: listen → create user stories (written by customer, each has a value/priority; developers estimate cost in weeks); stories grouped into releases / increments; project velocity = number of stories implemented in first release → used to estimate later releases
  • Design: KISS principle; CRC cards as the only design work product; spike solution (prototype to reduce risk); refactoring (improve internal structure without changing external behaviour)
  • Coding: develop unit tests first (test-first / TDD); pair programming (two people one workstation: driver & navigator → continuous review); continuous integration (integrate and smoke test daily)
  • Testing: unit tests automated and run often (regression); acceptance (customer) tests from user stories
  • XP practices (12): planning game, small releases, metaphor, simple design, testing, refactoring, pair programming, collective ownership, continuous integration, 40-hour week (sustainable pace), on-site customer, coding standards
  • Industrial XP (IXP), XP problems: requirements volatility, conflicting customer needs, informal requirements, lack of formal design
Explanation

Extreme Programming (XP) is the best-known agile model. Its values are communication, simplicity, feedback, courage and respect. In planning, the customer writes user stories, which are short descriptions of features. The developers estimate the effort for each, and the stories are grouped into releases. The project velocity, the number of stories completed in an iteration, helps in planning the next ones. Design follows the KISS principle. CRC cards are used as the main design tool, and a spike solution, a small prototype, is used to reduce risk. Refactoring, improving the structure of the code without changing its behaviour, is done continuously.

In coding, the unit tests are written before the code, and programmers work in pairs, one writing and the other reviewing, which gives continuous code review. Code is integrated and tested often. Testing is automated, so unit tests can be re-run at any time, and acceptance tests derived from the user stories are specified by the customer. The weaknesses of XP include the volatility of requirements, the lack of formal documentation and design, and the need for an on-site customer.
