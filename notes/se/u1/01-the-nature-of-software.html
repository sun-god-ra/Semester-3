The Nature of Software

Software Engineering · Unit I: Process Models and Agile Development

The Nature of Software
Subject
Software Engineering (24CS203)
Unit
Unit I: Process Models and Agile Development
Topic
1 of 13

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Software = (1) instructions (programs) that give the desired features and performance when executed + (2) data structures that let programs manipulate information + (3) documentation describing operation and use
  • Software is engineered, not manufactured (it does not wear out like hardware)
  • Differences from hardware
    • software is logical, hardware physical; developed, not manufactured; no wear-out, but deteriorates due to change (maintenance introduces defects)
    • Hardware failure curve = "bathtub curve" (infant mortality → useful life → wear-out). Software failure curve = "idealised curve" (initial defects, then low, spikes after each change, never returns to the original level)
    • Most software is custom-built; hardware uses standard components (software reuse is improving: component-based)
  • Software application domains: system software, application software, engineering/scientific software, embedded software, product-line software, web/mobile apps, artificial intelligence software
  • Also legacy software (old systems that remain useful); problems: poor quality, inextensible, poor documentation → needs reengineering
  • Software engineering (IEEE definition): application of a systematic, disciplined, quantifiable approach to development, operation and maintenance of software → engineering applied to software
  • SE is a layered technology
Explanation

Software is different from other engineered products because it is a logical construct, not a physical one. Hardware parts wear out with age, so their failure rate over time follows a bathtub curve: many failures early, a long stable period, and then rising failures as parts wear out. Software does not wear out, but it deteriorates. Each change made during maintenance can introduce new defects, so the failure rate spikes after every change and never goes back to its earlier minimum. This is why maintenance is costly and why design for change matters.

Software engineering applies a systematic approach to the development and maintenance of software. It is described as a layered technology. The base is a quality focus, since every engineering discipline rests on a commitment to quality. Above it is the process, which is the framework that holds technology layers together and enables rational and timely development. The methods layer gives the technical how-to for the activities, and the tools layer gives automated support for the process and methods.

The nature of software has changed over time. Besides traditional applications, we now build web applications and mobile apps, deliver software as a service from the cloud, and develop product lines whose shared parts are reused in several products.
