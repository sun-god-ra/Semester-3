The Unified Process (UP)

Software Engineering · Unit I: Process Models and Agile Development

The Unified Process (UP)
Subject
Software Engineering (24CS203)
Unit
Unit I: Process Models and Agile Development
Topic
7 of 13
Terms
UML, Rational unified process, Use case, Unified process

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Use-case driven, architecture-centric, iterative and incremental; uses UML. Related: Rational Unified Process (RUP)
  • Five phases
Phase Aim
Inception scope, business case, basic use cases, rough architecture, risks, project plan
Elaboration refine use cases, architectural baseline, analysis and design models, plan
Construction develop components, software increments, test; operational beta
Transition beta testing, defect reports, user manuals, delivery to end users
Production ongoing use, support, defect reports and change requests
  • Workflows (disciplines) across phases: requirements, analysis, design, implementation, test (plus management, environment)
  • Each phase has iterations; at the end a milestone. UP work products: vision document, use-case model, analysis model, design model, implementation model, deployment model, test model
Explanation

The Unified Process is a use-case driven, architecture-centric, iterative and incremental framework that uses UML. It has five phases. Inception establishes the scope and business case. Elaboration refines the use cases and creates a baseline architecture. Construction builds the software components. Transition delivers the system to the end users after beta testing, and Production covers ongoing operation and support. Each phase contains iterations, and the five technical workflows (requirements, analysis, design, implementation, test) are carried out in all of them in varying amounts.
