Requirements Modeling for Web and Mobile Apps

Software Engineering · Unit III: Requirements Modeling and Design Concepts

Requirements Modeling for Web and Mobile Apps
Subject
Software Engineering (24CS203)
Unit
Unit III: Requirements Modeling and Design Concepts
Topic
5 of 9
Terms
Use case, Sequence diagram, State diagram, Activity diagram

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • How much analysis is enough? Depends on: size and complexity of the increment, number of stakeholders, size of the team, degree of team collaboration, how well we understand the application domain, and how much the app impacts the business. Small, simple apps need little analysis
  • Input to the requirements model: formulation (statement of goals): informative / functional / user goals; customer & users; user hierarchy
  • Elements for WebApps/mobile apps
Model Content
Content model content objects (text, graphics, images, video, audio) and their relationships; content hierarchy; data tree
Interaction model use cases, sequence diagrams, state diagrams, user interface prototype
Functional model processing performed on content (user-visible functions and hidden functions), activity diagrams
Navigation model how users navigate from one content object / function to another: navigation semantic units (NSU) — ways of navigation; navigation syntax — mechanisms (links, icons, gestures)
Configuration model the environment and infrastructure: server-side (hardware, OS, database), client-side (browser, device, platform), sizes, resource limits
  • Mobile-specific: limited screen size, touch / gestures, context (location, sensors), battery, connectivity (offline), many platforms, notifications, app store rules, security & privacy
  • Use cases for web: primary actors (visitor, registered user, administrator)
  • Navigation modeling: identify the user's tasks, create NSU for each task (a set of information + navigation structures)
Explanation

How much analysis is needed depends on the size and complexity of the app, the number of stakeholders, and how critical the app is to the business. A small app with few stakeholders needs little. For larger ones the model has five parts: the content model (what information objects exist), the interaction model (use cases and screens), the functional model (what processing is done), the navigation model (how users move between content and functions) and the configuration model (the server and client environment). Mobile apps add concerns of small screens, touch interaction, context such as location, battery use, intermittent connectivity and the many platforms.
