WebApp and Mobile App Component-Level Design

Software Engineering · Unit IV: Software Design

WebApp and Mobile App Component-Level Design
Subject
Software Engineering (24CS203)
Unit
Unit IV: Software Design
Topic
9 of 12

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • WebApp component: (1) a well-defined cohesive function that manipulates content or provides computational processing for an end user, or (2) a cohesive package of content and functionality that provides the end user with some required capability
  • Content design at the component level: content objects and the content that goes with them; designing content components (text, graphics, video, a content database, queries → dynamic pages)
  • Functional design: processing functions (search, calculations, database access, form handling, e-commerce)
  • Architecture: MVC, 3-tier (presentation–business–data), REST / web services, client-side scripts (JavaScript) and server-side
  • Mobile apps: component design with separation of UI, business logic, data (MVVM, MVC), consider platform SDK, offline storage, battery and memory constraints, background tasks, push notifications, security (permissions, secure storage), responsiveness (UI thread)
  • Designing traditional components: use structured programming constructs — sequence, condition (if-then-else), repetition (do-while) (single entry/single exit), graphical (flowchart, box diagram), tabular (decision table), program design language (PDL / pseudo-code)
  • Component-based development (CBD): domain engineering (build reusable components in a domain) and component-based engineering: component qualification (interface, performance, reliability), adaptation, composition (architectural ingredients), update; component classification (facets) and retrieval
Explanation

A WebApp component is either a cohesive function that works on content or processes data for the user, or a cohesive package of content and functionality. Common architectures are MVC and the three-tier model of presentation, business logic and data. Mobile app design separates the UI from the logic and data, as in MVVM, and takes account of limited battery and memory, offline use and background tasks.

A traditional component is designed from the three structured constructs: sequence, condition and repetition. These can be shown as flowcharts, tables or pseudo-code. In component-based development, components are qualified (checked for interface, performance and reliability), adapted, composed into the architecture and updated.
