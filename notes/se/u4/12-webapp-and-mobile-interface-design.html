WebApp and Mobile Interface Design

Software Engineering · Unit IV: Software Design

WebApp and Mobile Interface Design
Subject
Software Engineering (24CS203)
Unit
Unit IV: Software Design
Topic
12 of 12

Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Web interface design: goals — navigation (clear, consistent), content first, performance, accessibility, aesthetics. Interface design principles for WebApps: anticipation, communication (status), consistency, controlled autonomy, efficiency, flexibility, focus, Fitts's law (time to reach a target depends on size and distance), human-interface objects, latency reduction, learnability, metaphors, maintain work product integrity, readability, track state, visible navigation
  • Interface design workflow for WebApps: review the info from analysis → develop a rough sketch of screen layout → map user objectives into interface actions → define user task sequences → define interaction pathways → identify content objects → design navigation → design aesthetics (layout, colour, fonts, graphics) → build prototype, test
  • Mobile interface design: small screen — essential content only; touch targets large enough (≈ 44 pt / 48 dp); gestures (tap, swipe, pinch); platform guidelines (Material Design for Android, Human Interface Guidelines for iOS); responsive layout; context (one-hand use, location, orientation); progressive disclosure, navigation patterns (tab bar, drawer, bottom nav); performance and battery; accessibility (screen readers, text scaling); minimise input (defaults, auto-fill)
  • Aesthetic design: layout, graphic design, colour contrast, typography
Explanation

For websites, the main concerns are clear navigation, content first, speed, accessibility and visual design. Fitts's law says the time to reach a target depends on its size and distance, which is the reason that frequently used controls should be big and near. For mobile apps the screen is small and the user touches it, so only essential content is shown, touch targets are large, platform guidelines are followed, and the layout adapts to the device and orientation. Input is kept to a minimum with defaults and auto-fill, and the design considers one-handed use, battery and accessibility.
