Object Oriented Programming Through Java · Unit III: Packages and Interfaces, Exception Handling, and IO Streams

Character Streams
Subject
Object Oriented Programming Through Java (24CS202)
Unit
Unit III: Packages and Interfaces, Exception Handling, and IO Streams
Topic
17 of 17
Terms
Byte stream, Constructor, Checked exception

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Reader: int read() (char as 0–65535 or −1), read(char[]), skip, close. Writer: write(int), write(String), write(char[]), append, flush, close
  • FileReader(path), FileWriter(path [, append]) — text files using default encoding
  • BufferedReader — buffered; readLine() reads a whole line (returns null at end). Wrapped around InputStreamReader(System.in) for keyboard input
  • BufferedWriter — newLine(), write
  • PrintWriter — print, println, printf to file or stream. new PrintWriter(System.out, true) auto-flush
  • InputStreamReader / OutputStreamWriter — bridge from byte stream to char stream with a chosen charset
  • Reading console input: BufferedReader br = new BufferedReader(new InputStreamReader(System.in)); or Scanner (nextInt(), nextLine(), hasNext()), or Console
  • Always close streams (flush buffers) → try-with-resources
java
import java.io.*;

public class CharDemo {
    public static void main(String[] args) throws IOException {
        try (PrintWriter pw = new PrintWriter(new FileWriter("notes.txt"))) {
            pw.println("line one");
            pw.println("line two");
            pw.printf("%d squared is %d%n", 7, 49);
        }
        try (BufferedReader br = new BufferedReader(new FileReader("notes.txt"))) {
            String line;
            int n = 0;
            while ((line = br.readLine()) != null) {
                n++;
                System.out.println(n + ": " + line);
            }
        }
        // keyboard input
        BufferedReader kb = new BufferedReader(new InputStreamReader(System.in));
        String name = kb.readLine();
        System.out.println("Hello " + name);
    }
}
  • With input Ruth: 1: line one, 2: line two, 3: 7 squared is 49, Hello Ruth
  • FileNotFoundException is a subclass of IOException — a checked exception, so throws IOException or try/catch is needed
  • File class: path info — exists(), isFile(), isDirectory(), length(), getName(), getPath(), list(), delete(), mkdir(), createNewFile() (does not read/write content)
Explanation

A stream is a flow of data between your program and something outside it, such as a file or the keyboard. Java has two families. Byte streams, built on InputStream and OutputStream, move raw 8-bit values and are right for binary files such as images. Character streams, built on Reader and Writer, move 16-bit Unicode characters and handle the conversion between bytes and characters for text. If a file is text, use a character stream; otherwise use a byte stream.

Classes are layered like wrappers. A FileInputStream reads bytes from a file; wrapping it in a BufferedInputStream adds a buffer to reduce disk access; wrapping it in a DataInputStream adds methods to read ints and doubles. For text from the keyboard, System.in is a byte stream, so we wrap it in an InputStreamReader to get characters, and then a BufferedReader to read whole lines with readLine().

Because file operations can fail, the constructors and methods throw IOException or its subclass FileNotFoundException, which are checked exceptions, and the code must handle or declare them. Streams must be closed so that buffered data is written out, and try-with-resources ensures that even when an exception occurs. When using DataInputStream, read the values in exactly the order in which they were written, because the file contains only raw bytes with no markers.
