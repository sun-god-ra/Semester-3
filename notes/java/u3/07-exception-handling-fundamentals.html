Exception Handling — Fundamentals

Object Oriented Programming Through Java (24CS202)
Unit

Topic
7 of 17
Terms
JVM

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Exception = abnormal condition / run-time error that disrupts normal flow. Is an object describing the error, created and thrown at the point of error
  • Error vs Exception: Errors are serious JVM-level problems (OutOfMemoryError, StackOverflowError) — not handled; Exceptions — programs can handle
  • Without handling: JVM prints a stack trace and terminates the thread
  • Five keywords: try, catch, finally, throw, throws
  • Flow: statement may fail → JVM creates exception object → throws it → runtime looks for matching catch up the call stack → if none, default handler terminates
java
try {
    // code that may throw
} catch (ExceptionType1 e) {
    // handler
} catch (ExceptionType2 e) {
    // handler
} finally {
    // always runs
}
Explanation

An exception is an object that represents an error, created at the point where the error occurs and passed to the runtime system. If no code handles it, the JVM prints the type, the message, and the stack trace, and ends the thread. Handling lets the program recover and continue.

The class hierarchy begins with Throwable, which has two branches. Error represents serious problems in the JVM, such as running out of memory, which programs should not try to catch. Exception covers problems a program can reasonably handle. Under Exception, the RuntimeException branch and Error are unchecked, which means the compiler does not force you to handle them. They usually indicate bugs, such as dividing by zero or using a null reference. All other exceptions are checked: the compiler insists that the code either catches them or declares them with throws, since they represent conditions outside the programmer's control, such as a missing file.
