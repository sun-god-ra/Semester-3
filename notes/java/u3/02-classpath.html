Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • CLASSPATH = list of directories / JAR files where JVM and javac look for classes and packages
  • Set: environment variable CLASSPATH, or option -cp / -classpath
    • java -cp .:/home/me/classes mypack.Balance (Windows uses ; separator; Linux :)
    • . = current directory
  • Default: current directory (if CLASSPATH not set). If you set it, include . or current directory is not searched
  • Search order: bootstrap classes → extension → CLASSPATH
  • Class loader finds mypack.Balance as <classpath-entry>/mypack/Balance.class
Explanation

A package groups related classes under one name. It has three purposes: it organises large programs, it prevents name collisions (two classes named Date can live in java.util and java.sql), and it controls visibility. The package name is mapped onto a directory structure, so package mypack; means the class file has to be in a folder named mypack. Using the -d . option, the compiler creates that folder for you. You then run the program using its full name from the parent folder, java mypack.Balance.

The class path tells the compiler and JVM where to look for packages and classes. It is a list of folders and JAR files separated by : on Linux or ; on Windows. If you set the CLASSPATH variable yourself and forget to include ., the current directory is no longer searched, and your own classes are not found. This is a common cause of "ClassNotFoundException" or "cannot find symbol" in student programs.
