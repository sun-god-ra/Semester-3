Object Oriented Programming Through Java · Unit III: Packages and Interfaces, Exception Handling, and IO Streams

Interfaces
Subject
Object Oriented Programming Through Java (24CS202)
Unit
Unit III: Packages and Interfaces, Exception Handling, and IO Streams
Topic
5 of 17
Terms
Abstraction, Inheritance, Polymorphism, Functional interface, Constructor, Abstract class

Practice: Part B questions for Unit III and Part A short questions.

Notebook notes
  • Interface = a completely abstract type: specifies what a class must do, not how. Contains method declarations and constants. Achieves full abstraction and multiple inheritance of type
  • Syntax
java
interface Callback {
    void callback(int param);          // implicitly public abstract
    int MAX = 100;                     // implicitly public static final
}
  • Methods in interface are implicitly public abstract; fields are public static final (constants, must be initialised)
  • Implementing: class Client implements Callback { public void callback(int p) {...} }
    • implemented methods must be public (can't reduce visibility)
    • a class can implement many interfaces: implements A, B, C
    • A class that doesn't implement all methods must be abstract
  • Cannot instantiate an interface, but can declare reference variable of interface type → run-time polymorphism
  • Extending interfaces: interface B extends A — class implementing B must implement methods of both. An interface can extend several interfaces
  • Java 8+: default methods (with body, default keyword) and static methods in interfaces; Java 9: private methods
java
interface Greeter {
    void greet(String name);
    default void hello() { System.out.println("Hello from default"); }
    static void util() { System.out.println("static in interface"); }
}
  • Diamond problem: a class gets the same default method from two interfaces → must override it and may call A.super.hello()
  • Marker interface: no methods (Serializable, Cloneable). Functional interface: exactly one abstract method (Runnable, Comparator) → lambdas (Unit IV)
Abstract class Interface
Methods abstract + concrete abstract (+ default, static, private from Java 8/9)
Variables any (instance, static) only constants
Constructors yes no
Inheritance extends one class implements many; interface extends many
Access of members any public
Use partial implementation, is-a capability / contract, can-do
java
interface Shape { double area(); }
interface Printable { void print(); }
class Circle implements Shape, Printable {
    double r;
    Circle(double r) { this.r = r; }
    public double area() { return Math.PI * r * r; }
    public void print() { System.out.printf("Circle area %.2f%n", area()); }
}

public class IfaceDemo {
    public static void main(String[] args) {
        Shape s = new Circle(2);
        System.out.printf("%.2f%n", s.area());
        Printable p = new Circle(1);
        p.print();
        System.out.println(Callback.MAX);
    }
}
interface Callback { int MAX = 100; }
  • Output: 12.57, Circle area 3.14, 100
Explanation

An interface describes what a class can do without any implementation. It is like a contract: any class that implements the interface promises to supply all of its methods. The methods in an interface are automatically public and abstract, and any field is automatically public, static and final. Since a class can implement many interfaces, interfaces give Java the useful part of multiple inheritance, which is the combination of several types, without the ambiguity of inheriting several implementations.

A variable of an interface type can refer to any object whose class implements the interface, and calls on it are resolved at run time, so interfaces support run-time polymorphism in the same way as superclasses do. Since Java 8, an interface can also contain default methods with a body, so that new methods can be added to existing interfaces without breaking the classes that implement them, and static methods. If a class implements two interfaces that provide the same default method, it has to override that method and choose, for example with A.super.hello().

The table of differences between abstract classes and interfaces is a standard exam question. The main points: a class extends only one abstract class but implements many interfaces, an abstract class can hold instance state and constructors, and an interface cannot. Choose an abstract class for a family of closely related classes sharing code, and an interface for a capability that unrelated classes might offer.
