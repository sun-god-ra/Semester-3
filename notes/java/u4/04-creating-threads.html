Creating Threads

Object Oriented Programming Through Java · Unit IV: Multithreading and Lambda Expressions

Creating Threads
Subject
Object Oriented Programming Through Java (24CS202)
Unit
Unit IV: Multithreading and Lambda Expressions
Topic
4 of 14
Terms
Inheritance, Functional interface, Constructor, JVM

Practice: Part B questions for Unit IV and Part A short questions.

On this page
  1. Way 1 — implement Runnable (preferred)
  2. Way 2 — extend Thread
Notebook notes
Way 1 — implement Runnable (preferred)
  • Runnable has one method void run() — the entry point of the thread
  • Create Thread object passing the Runnable, then call start()
java
class NewThread implements Runnable {
    Thread t;
    NewThread() { t = new Thread(this, "Demo Thread"); t.start(); }
    public void run() {
        try {
            for (int i = 3; i > 0; i--) { System.out.println("Child: " + i); Thread.sleep(50); }
        } catch (InterruptedException e) { System.out.println("Child interrupted"); }
        System.out.println("Child exiting");
    }
}
Way 2 — extend Thread
  • Override run(); create object; call start()
java
class MyThread extends Thread {
    MyThread(String name) { super(name); }
    public void run() { System.out.println(getName() + " running"); }
}
  • Which is better? Runnable — class can still extend another class (single inheritance), separates task from the thread mechanism, works with executors. Extend Thread only if you must change thread behaviour
  • Way 3: lambda (Runnable is a functional interface): new Thread(() -> System.out.println("hi")).start();
  • start() vs run(): start() creates a new thread of execution and calls run() in it. Calling run() directly just runs in the current thread like a normal method (no new thread)
  • A thread can be started only once
  • Constructors: Thread(), Thread(Runnable), Thread(Runnable, String name), Thread(String name)
  • Other methods: getName(), setName(), isAlive(), join(), sleep(), yield(), interrupt(), isInterrupted(), getId(), setDaemon()
  • Creating multiple threads — all share CPU, output interleaving is unpredictable
java
class Worker implements Runnable {
    private final String name;
    Worker(String name) { this.name = name; }
    public void run() {
        for (int i = 1; i <= 2; i++) System.out.println(name + " step " + i);
    }
}

public class TwoThreads {
    public static void main(String[] args) throws InterruptedException {
        Thread a = new Thread(new Worker("A"));
        Thread b = new Thread(new Worker("B"));
        a.start();
        a.join();             // wait for A to finish before B starts
        b.start();
        b.join();
        System.out.println("main done");
    }
}
  • Output (deterministic because of join): A step 1, A step 2, B step 1, B step 2, main done
Explanation

There are two basic ways. You can implement the Runnable interface and write the task in run(), then give the object to a Thread and call start(). Or you can extend Thread and override run(). The first approach is usually better, because a class can extend only one other class, but it can implement many interfaces, and because it separates what is to be done from how it is run.

The most important point is the difference between start() and run(). Calling start() asks the JVM to create a new thread of execution, and that new thread calls run(). Calling run() yourself is only an ordinary method call that runs in the current thread, so there is no concurrency at all. Also a thread object can be started only once.

When several threads run together, the order of their output depends on the scheduler and may change between runs. To get a predictable result in the example, the main thread waits for thread A to finish by calling join() before starting B.
