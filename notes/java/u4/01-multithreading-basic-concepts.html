Practice: Part B questions for Unit IV and Part A short questions.

Notebook notes
  • Multitasking: doing more than one thing at a time. Two kinds
    • Process-based: each program (process) runs separately; own memory; heavyweight; inter-process communication costly. Java compiler running while editor open
    • Thread-based: one program has several threads (smallest unit of executable code); share the same address space; lightweight; context-switch cheap
  • Thread = independent path of execution inside a process
  • Multithreaded program = two or more threads running concurrently. Gives better CPU use (while one waits for I/O another runs), responsive UI, parallel work on multi-core CPUs
  • On single core → concurrency by time slicing; multi-core → true parallelism
  • Java has built-in support: Thread class, Runnable interface, synchronized, wait/notify

Explanation

A program normally does one thing at a time, but real programs often need to do several: a browser downloads a file while you scroll, and a game plays sound while drawing the screen. Multitasking means running several activities together. At the level of the operating system, each program is a process with its own memory, which makes processes expensive to create and to communicate between. Inside one process we can run several threads. They are lightweight because they share the same memory, so they can exchange data directly and switching between them is cheap. That sharing is the source of both the power of threads and the difficulty of using them correctly.

In a single-threaded environment, a program that must wait, for example for a disk, simply stops, and the CPU time is wasted. With threads, one thread waits while others continue. A thread moves between states during its life. It is NEW after creation, becomes RUNNABLE when start() is called (it may be running or waiting for the CPU), can be BLOCKED waiting for a lock, WAITING or TIMED_WAITING when it called wait, join or sleep, and finally TERMINATED when run() ends. A terminated thread cannot be started again.

Priorities are numbers from 1 to 10 that tell the scheduler how important a thread is. They are only hints: the actual behaviour depends on the operating system, so correctness must never depend on them.
