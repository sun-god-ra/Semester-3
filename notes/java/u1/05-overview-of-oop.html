Notebook notes
Two paradigms
  • Process-oriented (procedural): "code acting on data". Program = series of linear steps. Code is the focus (C). Hard to manage when program grows
  • Object-oriented: "data controlling access to code". Organises program around data (objects) and a set of well-defined interfaces to that data
Principles of OOP — A PIE (Abstraction, Polymorphism, Inheritance, Encapsulation)
  • Abstraction: manage complexity by hiding detail; show only what is essential (e.g. driving a car without knowing the engine). Hierarchical classification
  • Encapsulation: bind data and the code that uses it into one unit (class) and hide the data from outside (private); access only through methods. Protects from misuse. Class → members (variables = instance variables, methods)
  • Inheritance: one class acquires properties and behaviours of another (subclass extends superclass). Gives reuse and hierarchy. is-a relation
  • Polymorphism: "one interface, multiple methods" — same name, different behaviour. Compile-time (overloading) and run-time (overriding)
  • Other terms: class = blueprint / template; object = instance of a class (state + behaviour + identity); message passing = calling a method
Explanation

Procedural programming organises a program around the steps to perform, with data passed between functions. As programs grow, any function can change any data, which becomes difficult to control. Object-oriented programming reverses the idea: the program is organised around objects, and each object controls access to its own data.

The four principles each deal with a particular problem. Abstraction hides complexity by letting us think about a car as a car, not about its thousands of parts. Encapsulation puts data and the code that works on it together in a class, and keeps the data private so that it can only be changed through methods that can check it. Inheritance lets a new class reuse an existing class and extend it, which models an is-a relationship and avoids repeating code. Polymorphism means one name, many forms: the same method call can behave differently depending on the object, either chosen by the compiler from the argument types (overloading) or by the JVM from the actual object at run time (overriding).
