Features of Java (the "Java buzzwords")

Bytecode, Garbage collection, JVM, JIT

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
Feature Meaning
Simple C/C++ like syntax; no pointers, no operator overloading, no header files, automatic memory
Object-oriented everything (except primitives) is an object; all code in classes
Platform independent / portable "Write Once, Run Anywhere" (WORA) — compiled to bytecode
Robust strong type checking, exception handling, garbage collection, no pointers
Secure no pointers, bytecode verifier, sandbox (security manager), class loader
Architecture neutral bytecode not tied to a CPU; sizes of types fixed (int always 32 bit)
Interpreted and high performance bytecode interpreted by JVM; JIT compiler makes it fast
Multithreaded built-in thread support
Distributed networking (java.net), RMI
Dynamic classes loaded at run time; reflection
Explanation

Java began in 1991 as a language for embedded consumer devices at Sun Microsystems. Those devices used many different processors, so the designers needed a language whose programs did not depend on the CPU. When the web grew in the mid-1990s, the same need appeared on the internet, because a program downloaded from a server could run on any kind of computer. Java became popular by solving exactly that, and its slogan, write once, run anywhere, expresses the idea.

The "buzzwords" are the features designers claimed for the language, and each one is a consequence of a design choice. It is simple and secure because pointers were removed, so a program can neither forge an address nor overwrite arbitrary memory. It is robust because types are checked strictly, exceptions force error handling, and garbage collection removes manual freeing. It is portable and architecture-neutral because programs are compiled to bytecode, and because the size of each type is fixed by the language and not by the machine: an int is 32 bits everywhere.
