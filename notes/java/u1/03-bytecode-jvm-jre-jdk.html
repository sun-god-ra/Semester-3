Bytecode, JVM, JRE, JDK

Object Oriented Programming Through Java · Unit I: Fundamental Java Programming Constructs

Bytecode, JVM, JRE, JDK
Subject
Object Oriented Programming Through Java (24CS202)
Unit
Unit I: Fundamental Java Programming Constructs
Topic
3 of 13
Terms
Bytecode, JVM, Java virtual machine, JIT, Just-in-time

Practice: Part B questions for Unit I and Part A short questions.

Notebook notes
  • Bytecode: highly optimised set of instructions, machine code for the JVM, output of javac (.class files). Not native code
  • JVM (Java Virtual Machine): abstract machine that runs bytecode. Different JVM for each OS/CPU, but the same bytecode runs on all → portability. Parts: class loader, bytecode verifier, interpreter, JIT, garbage collector, runtime data areas (heap, stack, method area)
  • JIT (Just-In-Time) compiler: compiles hot bytecode to native code at run time → speed
  • JRE = JVM + class libraries (needed to run). JDK = JRE + tools (javac, java, javadoc, jar, jdb) (needed to develop). JDK ⊃ JRE ⊃ JVM
  • Why Java is both compiled and interpreted: compiled to bytecode, then interpreted (or JIT-compiled) by the JVM
  • Commands: javac Hello.java → Hello.class; java Hello (no .class)
Explanation

A C compiler translates source code into machine code for one specific processor. The Java compiler javac instead produces bytecode, instructions for an imaginary computer called the Java Virtual Machine. Each platform has its own implementation of the JVM, written in native code, which reads the bytecode and executes it. The programmer compiles once and the same .class file runs on every platform that has a JVM. The extra layer also helps security, because the JVM can check the bytecode before running it and confine the program to a restricted environment.

An interpreter alone would be slow, so modern JVMs include a Just-In-Time compiler. It watches which parts of the program run often, translates those parts into native machine code while the program is running, and uses the native version from then on. This is why Java is described as both compiled and interpreted.

The three similar terms are nested. The JVM runs bytecode. The JRE adds the standard class libraries needed for running programs. The JDK adds the development tools, such as the compiler, so you need the JDK to write programs and only the JRE to run them.
