Object Oriented Programming Through Java · Unit II: Classes, Objects, Inheritance, and String Handling

Abstract Classes
Subject
Object Oriented Programming Through Java (24CS202)
Unit
Unit II: Classes, Objects, Inheritance, and String Handling
Topic
20 of 22
Terms
Abstract class, Constructor, Inheritance

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • Abstract method: declared with abstract, no body: abstract void draw(); — subclasses must implement it
  • Abstract class: declared abstract; may have abstract methods and concrete methods, fields, constructors. Cannot be instantiated (new Shape() illegal); can have reference variables
  • A class with one or more abstract methods must be abstract
  • Subclass must override all abstract methods, else it must also be declared abstract
  • No abstract constructors, no abstract static methods, no abstract private, no abstract final
java
abstract class Figure {
    double d1, d2;
    Figure(double a, double b) { d1 = a; d2 = b; }
    abstract double area();                   // no body
    void info() { System.out.println("Area = " + area()); }
}
class Rectangle extends Figure {
    Rectangle(double a, double b) { super(a, b); }
    double area() { return d1 * d2; }
}
class Triangle extends Figure {
    Triangle(double a, double b) { super(a, b); }
    double area() { return d1 * d2 / 2; }
}

public class AbstractDemo {
    public static void main(String[] args) {
        Figure f = new Rectangle(9, 5);
        f.info();
        f = new Triangle(10, 8);
        f.info();
    }
}
  • Output: Area = 45.0, Area = 40.0
  • Abstract class vs interface (see Unit III): abstract class can have state & constructors, single inheritance; interface = pure contract (before Java 8)
Explanation

An abstract class is an incomplete class: it declares what subclasses must be able to do (the abstract methods) without saying how. Because it is incomplete, you cannot create an object of it, but you can declare variables of its type and fill them with objects of concrete subclasses, which is what makes dynamic dispatch useful. A subclass becomes concrete only when it implements all inherited abstract methods. In the example, info() is written once in Figure and calls area(), whose version is decided at run time by the actual object.
