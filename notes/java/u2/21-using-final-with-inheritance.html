Using `final` with Inheritance

Object Oriented Programming Through Java · Unit II: Classes, Objects, Inheritance, and String Handling

Using `final` with Inheritance
Subject
Object Oriented Programming Through Java (24CS202)
Unit
Unit II: Classes, Objects, Inheritance, and String Handling
Topic
21 of 22
Terms
Inheritance

Practice: Part B questions for Unit II and Part A short questions.

Notebook notes
  • final method — prevents overriding (compile-time binding → slightly faster; "inlining")
  • final class — prevents inheritance. A class can't be both abstract and final
  • Example: final class String, Integer, Math
  • Purpose: security and design integrity
Explanation

A final method cannot be overridden and a final class cannot be extended, which is used to protect behaviour that must not be changed, such as String. A class cannot be both abstract and final, because abstract requires subclasses and final forbids them.

Every class inherits from Object, so every object has methods such as toString() and equals(). The default equals compares references, and the default toString prints the class name and a hash code. To compare contents or give a readable text, override them. When you override equals you should also override hashCode, so that equal objects have the same hash code, otherwise hash-based collections will misbehave.
