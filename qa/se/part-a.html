Part A

Software Engineering: short answer questions

2 marks each · 32 questions

Q1Nov 20252MCO1 K1

Write any two characteristics of good software.

Answer
  1. Operational: it does what it should, correctly, efficiently, safely and usably (correctness, reliability, usability, security, performance).
  2. Maintainable / modifiable: it can be corrected, adapted and extended easily as the needs of the customer change.
  3. Transitional: portable, interoperable and reusable. (Pressman's three groups of quality: operation, revision, transition.)
Q2Nov 20252MCO1 K1

What are software myths?

Answer

Software myths are wrong beliefs about software and the process of building it that mislead managers, customers and practitioners. Examples: management myth: "we already have a book of standards, so the team will follow it"; customer myth: "a general statement of objectives is enough to start, details can come later"; practitioner myth: "once the program runs, our job is over". Reality: change is costly late, and most effort comes after delivery (maintenance).

Q3Nov 20252MCO2 K1

What is a use case?

Answer

A use case is a written scenario that describes how an actor (user or external system) interacts with the system to reach a goal, as a sequence of steps. It captures the functional behaviour from the user's point of view, e.g. "Withdraw cash" by the actor Customer from an ATM.

Q4Nov 20252MCO2 K1

What is requirements management?

Answer

Requirements management is the set of activities that identify, control and track requirements and their changes during the project. It includes unique identification, a traceability table (requirement ↔ design ↔ code ↔ test), version control and change control, so that every change is analysed and agreed before it is made.

Q5Nov 20252MCO3 K2

Define design patterns.

Answer

A design pattern is a proven, reusable solution to a commonly occurring design problem in a given context. It is described by a name, the problem, the solution and the consequences. Example: Singleton, Observer, Factory.

Q6Nov 20252MCO3 K1

List the analysis packages in requirements modelling.

Answer

An analysis package is a container that groups related analysis classes (and their use cases) into a coherent unit, e.g. Customer, Order, Payment, Inventory packages. Packages are shown in UML with the folder icon and show dependencies between groups of classes. They give a high-level view and help to divide the work.

Q7Nov 20252MCO4 K2

What is software architecture?

Answer

Software architecture is the overall structure of the software: the components, the externally visible properties of those components and the relationships among them. It is the first design representation and decides how the system meets its quality needs (performance, security, modifiability).

Q8Nov 20252MCO4 K1

State the purpose of interface design.

Answer

Interface design makes the interaction between the user and the system easy, efficient and error-free. It decides what the user sees, how they give input and how the system responds (screens, menus, messages). It also covers interfaces between modules and to external systems.

Q9Nov 20252MCO5 K1

What is regression testing?

Answer

Regression testing means re-running earlier tests after a change (bug fix, new feature) to make sure the change has not broken the existing working behaviour. It uses a saved test suite and is often automated.

Q10Nov 20252MCO5 K2

What is basis path testing?

Answer

A white-box technique (Tom McCabe) that uses the cyclomatic complexity of the control-flow graph to find the number of linearly independent paths and designs a test case for each. Every statement gets executed at least once. \(V(G) = E - N + 2 = P + 1\) (P = decision nodes).

Q11Apr 20262MCO1 K1

What is the Unified Process?

Answer

The Unified Process (UP/RUP) is a use-case driven, architecture-centric, iterative and incremental software process framework built on UML. It has four phases: Inception, Elaboration, Construction, Transition (plus Production).

Q12Apr 20262MCO1 K1

What is agility?

Answer

Agility is the ability to respond quickly and effectively to change and deliver working software frequently. Agile methods favour individuals and interactions, working software, customer collaboration and responding to change (Agile Manifesto).

Q13Apr 20262MCO2 K2

Differentiate between functional and non-functional requirements.

Answer
Functional Non-functional
What the system must do (features, functions) How well it does it (quality, constraints)
"The user can reset the password by email" "The page loads in under 2 s", security, usability, reliability
Tested by functional testing Tested by performance, security, usability tests
Q14Apr 20262MCO2 K2

List any two challenges in requirements gathering.

Answer
  1. Scope problem: the boundary is badly defined or customers add unnecessary details.
  2. Understanding problem: customers are not sure what they need, don't know the technical limits, or communicate poorly with the developers.
  3. Volatility problem: requirements change over time.
Q15Apr 20262MCO3 K1

What is scenario-based modelling?

Answer

It models the system from the user's point of view using use cases, activity diagrams and swimlane diagrams. It is the first element of requirements modelling and the others (class-based, behavioural) are built on it.

Q16Apr 20262MCO3 K1

What is the purpose of a use case diagram?

Answer

A use case diagram shows the actors, the use cases and the relationships between them (association, include, extend, generalisation). It gives a quick overview of the functionality the system offers and who uses it.

Q17Apr 20262MCO4 K2

List any two advantages of architectural design.

Answer
  1. Communication: gives all stakeholders a common high-level picture.
  2. Early analysis: quality attributes (performance, security) can be checked before implementation.
  3. Reuse: components and styles can be reused and the cost of change is lower.
Q18Apr 20262MCO4 K2

What are the qualities of a good design?

Answer

(Pressman) The design must implement all explicit and implicit requirements, be a readable guide for coders and testers, and give a complete picture of data, function and behaviour. It should be modular, have distinct representations of data, architecture, interfaces and components, use recognisable patterns, and show low coupling and high cohesion.

Q19Apr 20262MCO5 K1

State the objectives of software testing.

Answer

(Myers) (1) Testing is executing a program to find errors; (2) a good test case is one with a high probability of finding an undiscovered error; (3) a successful test is one that uncovers an error. Testing shows presence of errors, not their absence.

Q20Apr 20262MCO5 K2

What is control structure testing?

Answer

A group of white-box techniques that test the logic of control structures: condition testing (each condition true/false), data-flow testing (definition–use of variables) and loop testing (simple, nested, concatenated, unstructured loops).

Q21Expected2MCO1 K1

List the generic framework activities of a software process.

Answer

Communication, Planning, Modeling, Construction, Deployment. Umbrella activities: project tracking, risk management, quality assurance, reviews, configuration management, reusability, measurement.

Q22Expected2MCO1 K2

Differentiate between the Waterfall model and the Incremental model.

Answer

Waterfall: linear, one delivery at the end, requirements must be fixed early. Incremental: first delivers a core product and adds increments, with early working software and easier change.

Q23Expected2MCO1 K1

List the values of Extreme Programming (XP).

Answer

Communication, Simplicity, Feedback, Courage, Respect.

Q24Expected2MCO2 K1

What is a CRC card? What does CRC stand for?

Answer

Class–Responsibility–Collaborator card: an index card with the class name, its responsibilities (what it knows and does) and the collaborators (other classes it works with). Used in class-based modelling.

Q25Expected2MCO2 K2

List the tasks of requirements engineering.

Answer

Inception, Elicitation, Elaboration, Negotiation, Specification, Validation, Requirements management.

Q26Expected2MCO3 K1

What is coupling and cohesion?

Answer

Cohesion: how strongly the elements inside a module belong together (high is good). Coupling: how much a module depends on other modules (low is good).

Q27Expected2MCO3 K2

What is abstraction? Give types.

Answer

Abstraction suppresses detail and shows only the essentials at a level. Procedural abstraction (named sequence of instructions, e.g. open) and data abstraction (named collection of data, e.g. door with type, weight, dimensions).

Q28Expected2MCO4 K1

List the architectural styles.

Answer

Data-centred, data-flow (pipe and filter), call-and-return (main program/subprogram, remote procedure call, layered), object-oriented, and layered architectures.

Q29Expected2MCO4 K2

State any two golden rules of user interface design.

Answer

(Theo Mandel) (1) Place the user in control; (2) reduce the user's memory load; (3) make the interface consistent.

Q30Expected2MCO5 K2

Differentiate between verification and validation.

Answer

Verification: "Are we building the product right?" (checks against the specification; reviews, inspections). Validation: "Are we building the right product?" (checks it meets the customer's needs; testing, acceptance).

Q31Expected2MCO5 K1

Differentiate between alpha and beta testing.

Answer

Alpha: done at the developer's site by the customer in a controlled setting. Beta: done at the customer's site by end users in a real environment, with no developer present.

Q32Expected2MCO5 K2

What is cyclomatic complexity? Write its formulas.

Answer

A metric giving the number of independent paths in a program. \(V(G) = E - N + 2\), \(V(G) = P + 1\), or \(V(G)\) = number of regions of the flow graph.
