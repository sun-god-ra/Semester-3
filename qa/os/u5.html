Part B · Unit V

Storage Management and File System

Operating Systems · 6 questions · Notes for this unit

Q1Nov 20258MCO5 K3

Explain the SCAN and C-SCAN disk scheduling algorithms with an example.

Answer

Request queue (cylinders 0–199): 98, 183, 37, 122, 14, 124, 65, 67. Head at 53, moving toward higher numbers.

  • SCAN (elevator): the arm moves in one direction serving requests on the way to the end of the disk, then reverses and serves the rest. Order: 53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 → 37 → 14. Total head movement = (199−53) + (199−14) = 146 + 185 = 331 cylinders.
  • C-SCAN (circular SCAN): moves in one direction serving requests; at the end it jumps straight back to cylinder 0 (without serving) and continues in the same direction. Order: 53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 → 0 → 14 → 37. Total = (199−53) + 199 + 37 = 382 when the return jump is counted (183 if it is not counted; state which you use).

For comparison on the same queue: FCFS = 640, SSTF = 236, LOOK = 299. SCAN/C-SCAN avoid the starvation that SSTF may cause; C-SCAN gives a more uniform waiting time, since the cylinders at the far end are not served twice per sweep.

Q2Nov 20258MCO5 K2

Explain the file operations.

Answer

A file is a named collection of related information on secondary storage. Operations (supported by system calls):

  1. Creating: find space, make a directory entry.
  2. Writing: system call with the file name and data; the system keeps a write pointer.
  3. Reading: keeps a read pointer (current-file-position pointer).
  4. Repositioning (seek): change the pointer, no I/O.
  5. Deleting: release the space and remove the directory entry.
  6. Truncating: erase contents but keep the attributes. Others: append, rename, open() and close(). The OS keeps an open-file table (system-wide and per process) with the file pointer, the open count, the disk location and access rights, so a file is searched in the directory only once at open(). Attributes: name, identifier, type, location, size, protection, time, date, user.

Answer
Structure Idea Advantage Disadvantage
Single-level one directory for all files simple name clashes between users, no grouping
Two-level a master directory with one user directory per user solves name clashes between users, efficient search no grouping inside, difficult sharing
Tree-structured directories contain files and subdirectories; absolute and relative paths grouping, current directory, natural sharing is limited
Acyclic-graph tree plus shared files/directories via links sharing without copies deletion issues (dangling pointers), must avoid cycles
General graph cycles allowed flexible need garbage collection / cycle detection to avoid infinite loops
Q4Nov 20258MCO5 K2

(OR) Explain the free-space management methods.

Answer

The system keeps a free-space list of the unused blocks.

  1. Bit vector (bitmap): one bit per block (1 = free). Simple and fast to find the first free block or n contiguous blocks; the bitmap must be kept in memory, big for large disks.
  2. Linked list: link all free blocks; no waste of space but traversing is slow and contiguous space is hard to find.
  3. Grouping: first free block stores the addresses of n free blocks; the last of these points to another such block. Many free blocks can be found quickly.
  4. Counting: store the address of the first free block plus the count of contiguous free blocks that follow; suits contiguous allocation.
  5. Space maps (ZFS): divide the disk into metaslabs, each with a log-structured record of the allocate and free actions.
Q5Expected8MCO5 K2

Explain the file allocation methods.

Answer
  • Contiguous: each file occupies a set of contiguous blocks; directory has start and length. Pro: fast sequential and direct access. Con: external fragmentation, files cannot easily grow.
  • Linked: each block holds a pointer to the next; directory points to the first (and last). Pro: no external fragmentation, grows easily. Con: no efficient direct access, pointer overhead, a damaged pointer loses the rest; FAT improves this by keeping the links in a table.
  • Indexed: an index block holds all block addresses of the file. Pro: direct access, no external fragmentation. Con: index block overhead; for large files use linked, multilevel or combined (UNIX inode: direct, single, double, triple indirect) index blocks.
Q6Expected8MCO5 K2

Explain protection: domains of protection and the access matrix.

Answer

Goal: ensure each program component uses a resource only in ways consistent with policy. Principle of least privilege.

  • Domain of protection: a set of (object, access-rights) pairs. A process executes in a domain; may be a user, a process or a procedure.
  • Access matrix: rows = domains, columns = objects, entry = rights.
F1 F2 Printer
D1 read
D2 read print
D3 read, execute
D4 read, write read, write
  • Implementations: access-control list (per object, the column) and capability list (per domain, the row).
  • Rights such as switch, copy, owner and control allow changes to the matrix.
