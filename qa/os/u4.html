Q1Nov 20258MCO4 K3

Explain First-fit, Best-fit and Worst-fit allocation. Place processes of 212 KB, 417 KB, 112 KB and 426 KB (in order) in the partitions 100 KB, 500 KB, 200 KB, 300 KB and 600 KB.

Answer
  • First-fit: allocate the first hole that is big enough. Fast.
  • Best-fit: allocate the smallest hole that is big enough; leaves the smallest leftover, searches the whole list.
  • Worst-fit: allocate the largest hole; the leftover is big enough to be useful, searches the whole list.

Partitions: 100, 500, 200, 300, 600.

Process First-fit Best-fit Worst-fit
212 KB 500 (left 288) 300 (left 88) 600 (left 388)
417 KB 600 (left 183) 500 (left 83) 500 (left 83)
112 KB 288 (in the 500 partition's remainder, left 176) 200 (left 88) 388 (in the 600 remainder, left 276)
426 KB must wait (no hole of 426 KB; the largest is 300) 600 (left 174) must wait (no hole of 426 KB; the largest is 300)

Check of the first-fit step for 112 KB: the first hole that fits in the list order (100, 288, 200, 300, 183) is the 288 KB remainder, giving 176 left. Result: Best-fit is the only one that places all four processes. First-fit and worst-fit leave the 426 KB process waiting. (Best-fit isn't always the best in general: it tends to produce many tiny useless holes.)

Q2Nov 20258MCO4 K2

Explain internal and external fragmentation.

Answer
  • Internal fragmentation: memory inside an allocated partition or page that the process does not use. Example: a process of 18,462 bytes in 4 KB pages needs 5 pages = 20,480 bytes; 2,018 bytes in the last page are wasted. Average waste is half a page per process. Reduced by smaller pages / variable partitions.
  • External fragmentation: total free memory is enough for a request, but it is split into non-contiguous small holes. Occurs in variable (dynamic) partitioning, segmentation and contiguous allocation; the first-fit/best-fit statistics suggest about one-third of memory may be unusable (50 percent rule: for N allocated blocks about 0.5N are lost).
  • Solutions: compaction (shuffle memory to make one big hole; needs run-time binding), paging (removes external fragmentation, leaves internal), segmentation with paging.

Total free = 60K but a 40K request fails: external fragmentation.

Q3Nov 20258MCO4 K3

(OR) Explain LRU and optimal page replacement with an example.

Answer

Reference string: 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1, with 3 frames. (The paper's own string was not captured by me, so use the same method on the string given in the question. This standard string is for practice.)

  • Optimal (OPT): replace the page that will not be used for the longest time in the future. Lowest possible fault rate, but needs future knowledge, so it is only a benchmark.
  • LRU: replace the page not used for the longest time in the past (approximation of OPT using the past). Implemented with counters or a stack.
Algorithm Page faults (3 frames)
FIFO 15
LRU 12
Optimal 9

How OPT proceeds: 7, 0, 1 fill the frames (3 faults). Page 2 replaces 7 (4th fault; 7 is needed farthest in the future). 0 is a hit. Page 3 replaces 1 (5th). 0 hit. Page 4 replaces 0 (6th; among 2, 3, 0 the page 0 is next used farthest away). 2 and 3 hit. Page 0 replaces 4 (7th; 4 is never used again). Page 1 replaces 3 (8th). 2, 0, 1 hit. Page 7 replaces 2 (9th; 2 is never used again). 0 and 1 hit. Total 9 faults. Neither suffers from Belady's anomaly (more frames can give more faults in FIFO). They are stack algorithms.

Q4Nov 20258MCO4 K2

(OR) Explain the performance of copy-on-write.

Answer

Copy-on-write (COW) lets parent and child processes initially share the same pages, marked read-only/copy-on-write. Only when either process writes to a shared page is a copy of that page made for the writer.

Performance:

  • fork() becomes very fast and cheap: no copying of the whole address space.
  • Saves memory: only modified pages are duplicated; pages never modified (code, read-only data) stay shared.
  • Especially good when the child calls exec() immediately (no copy at all).
  • Cost: each first write causes a page fault and a page copy; the pages that are copied come from a pool of zero-filled free frames.
  • Used in Linux, Windows and macOS (vfork() is a variant without COW).
Q5Expected8MCO4 K2

Explain paging with a neat diagram, and the translation look-aside buffer.

Answer

Paging divides the logical address space into fixed-size pages and the physical memory into frames of the same size. The CPU address is split into page number \(p\) and offset \(d\); the page table maps \(p\) to frame number \(f\); the physical address is \(f\times\text{page size}+d\).

Example: page size 1 KB, logical address 3500 → \(p=3\), \(d=428\); if page 3 is in frame 7 → physical address = \(7\times1024+428=7596\). TLB: associative cache of (page, frame) pairs. Effective access time \(EAT=\alpha(t_{TLB}+m)+(1-\alpha)(t_{TLB}+2m)\). With hit ratio 80 percent, TLB 20 ns, memory 100 ns: \(0.8\times120+0.2\times220=140\) ns.
