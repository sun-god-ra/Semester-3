Part B · Unit I

Introduction and Operating System Structures

Operating Systems · 5 questions · Notes for this unit

Q1Nov 20258MCO1 K2

Explain the importance of operating systems.

Answer

An operating system (OS) is the software that manages the hardware and acts as the intermediary between the user and the computer. Why it matters:

  1. Resource manager: allocates CPU, memory, storage and I/O devices fairly and efficiently among programs.
  2. Convenience: hides the hardware detail (the user and programmer see files, windows, processes, not disk sectors).
  3. Control program: prevents errors and improper use (protection, dual mode).
  4. Multiprogramming and time-sharing: keeps the CPU busy, gives many users the illusion of their own machine.
  5. Abstraction and portability: the same program runs on different hardware through system calls and drivers.
  6. Security and accounting: authentication, access control, logging.
  7. Platform for applications: provides the services (file system, networking, GUI) all programs depend on. Without an OS every application would need to manage hardware directly.
Q2Nov 20258MCO1 K2

Explain the computer system organisation with a neat diagram.

Answer

A modern computer has one or more CPUs and device controllers connected through a common bus to the shared memory.

  • Bootstrap program (in ROM/firmware) starts the system, initialises registers and device controllers, and loads the kernel.
  • Interrupts: a device controller signals the CPU by an interrupt; the CPU saves its state, uses the interrupt vector to find the interrupt service routine, runs it and resumes. Software raises a trap (system call or error).
  • I/O structure: each controller has a local buffer; the driver moves data between the buffer and the memory. For bulk transfers DMA moves a whole block without CPU involvement, and gives one interrupt per block.
  • Storage hierarchy: registers → cache → main memory → SSD/disk → tape; faster = smaller and costlier.
  • Dual-mode operation (user / kernel) and a timer protect the OS.
Q3Nov 20258MCO1 K2

(OR) Explain the services provided by an operating system.

Answer

Services for the user:

  1. User interface: command line, GUI, batch.
  2. Program execution: load, run and terminate programs, normally or by error.
  3. I/O operations: programs cannot do I/O directly, the OS does it.
  4. File-system manipulation: create, delete, read, write, search, permissions.
  5. Communications: between processes on the same or different computers (shared memory, message passing).
  6. Error detection: in CPU, memory, devices and user programs; takes appropriate action.

Services for efficient operation of the system:

  1. Resource allocation: among multiple users and jobs.
  2. Accounting (logging): who used how much of what.
  3. Protection and security: control of access; authentication and defence against external attacks.
Q4Nov 20258MCO1 K2

(OR) Explain the advantages and limitations of distributed operating systems.

Answer

A distributed OS manages a collection of independent computers connected by a network and makes them appear to the user as one single coherent system.

Advantages

  • Resource sharing (files, printers, CPU time) across nodes.
  • Computation speed-up by load sharing and parallel execution.
  • Reliability / fault tolerance: failure of one node does not stop the system.
  • Scalability: add nodes to grow.
  • Communication among users and remote access to data.
  • Better price/performance than a single large machine.

Limitations

  • Network dependence: network failure or latency affects everything.
  • Complex software: synchronisation, naming, consistency, distributed deadlock are hard.
  • Security problems: more points of attack, data travels over the network.
  • Higher cost of management, troubleshooting is difficult.
  • Overhead of messages and clock synchronisation.
Q5Expected8MCO1 K2

Explain the operating system structures.

Answer
  1. Simple (monolithic) structure: all functionality in one kernel (MS-DOS, original UNIX). Fast but hard to maintain and one bug can crash everything.
  2. Layered approach: the OS is divided into layers; layer N uses only layers below it. Easy debugging; many layers cost performance.
  3. Microkernel: only the essentials (IPC, basic scheduling, memory) in the kernel; other services run in user space. Secure and extensible but slower due to message passing (Mach, QNX).
  4. Modular (loadable kernel modules): core kernel plus dynamically loaded modules (Linux, Solaris).
  5. Hybrid: mix of the above (Windows NT, macOS).
  6. Virtual machines: a layer that presents the hardware as many separate virtual machines.
